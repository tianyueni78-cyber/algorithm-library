# Local Search：局部搜索

# 1. 一句话说明它是什么

> 局部搜索是一种从现有方案出发，不断做小修改，只要变得更好就继续，主要用于快速改进调度、路径和排序方案。

核心思路：

```text
当前方案
→ 小改一下
→ 更好就保留
→ 重复
```

缺点是可能卡在“附近最好、整体不一定最好”的方案，即局部最优。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义方案怎么表示
  ├── 定义怎样小幅修改方案
  ├── 定义方案好坏
  └── 定义约束和停止条件
  ↓
局部搜索需要完成的工作
  ├── 生成邻近方案
  ├── 评价邻近方案
  ├── 选择更好的方案
  └── 重复直到无法改进
  ↓
最终结果
  └── 一个局部最优方案
```

人提供：

- 初始解；
- 邻域操作；
- 评价函数；
- 可行性规则；
- 停止条件。

算法返回：

- 改进后的方案；
- 目标值；
- 搜索次数。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 一个完整方案

怎样小幅修改方案？
→ 邻域操作

什么情况绝对不允许？
→ 可行性检查

什么结果算更好？
→ 评价函数

哪些信息已经知道？
→ 任务、机器、时间、距离等数据

什么会变化？
→ 当前方案和目标值
```

常见邻域：

| 问题 | 解的表示 | 小幅修改 |
|---|---|---|
| 任务排序 | 任务序列 | 交换两个任务 |
| 机器分配 | 工序—机器 | 更换一台机器 |
| 车辆路径 | 客户顺序 | 交换、插入、反转 |
| 员工排班 | 班次表 | 调换两个班次 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始输入 | 问题数据 | 任务、机器、加工时间 |
| 算法输入 | 初始解、邻域、评价函数 | `A-B-C-D`、交换操作 |
| 内部数据 | 当前解、邻居解、目标值 | 当前成本100 |
| 输出 | 改进后的方案 | `A-C-B-D`，成本82 |

# 7. 完整运行流程

```text
生成或接收初始解
  ↓
生成邻近方案
  ↓
评价邻近方案
  ↓
找到更好的方案？
  ├── 是：替换当前方案并继续
  └── 否：停止
  ↓
输出当前方案
```

# 9. 每个模块的输入、输出和构成

## 9.1 初始解 Initial Solution

### 作用

提供搜索起点。

### 输入

- 问题数据；
- 约束规则。

### 内部构成

```text
InitialSolution
├── RandomBuilder
└── GreedyBuilder
```

### 处理过程

随机生成或用贪心算法构造方案。

### 输出

- 初始可行解。

### 是否需要用户自己实现

通常需要自己实现。

## 9.2 邻域 Neighborhood

### 作用

定义怎样小幅修改当前方案。

### 输入

- 当前解；
- 邻域类型。

### 内部构成

```text
Neighborhood
├── Swap
├── Insert
└── Reverse
```

### 处理过程

对当前解执行交换、插入或反转。

### 输出

- 一组邻近方案。

### 是否需要用户自己实现

通常需要自己实现，是局部搜索的核心。

## 9.3 评价 Evaluation

### 作用

判断方案好坏。

### 输入

- 候选方案；
- 问题数据。

### 内部构成

```text
Evaluation
├── Objective
└── ConstraintPenalty
```

### 处理过程

计算时间、成本、距离或延误。

### 输出

- 目标值；
- 是否可行。

### 是否需要用户自己实现

通常需要自己实现。

## 9.4 移动选择 Move Selection

### 作用

决定采用哪个邻近方案。

### 输入

- 当前解；
- 邻居及其目标值。

### 内部构成

```text
MoveSelection
├── FirstImprovement
└── BestImprovement
```

### 处理过程

两种常见方式：

```text
First Improvement
→ 找到第一个更好邻居就采用

Best Improvement
→ 检查全部邻居，选择最好的
```

### 输出

- 下一轮当前解。

### 是否需要用户自己实现

通常需要自己实现。

## 9.5 主循环 Main Loop

### 作用

重复生成、评价和选择邻居。

### 输入

- 初始解；
- 各功能模块；
- 停止条件。

### 内部构成

```text
MainLoop
├── Generate
├── Evaluate
├── Select
└── Stop
```

### 处理过程

持续改进，直到没有更好邻居或达到次数限制。

### 输出

- 局部最优解；
- 最终目标值。

### 是否需要用户自己实现

通常需要自己实现，但循环很短。

# 11. 用户需要实现什么

## 通常需要自己实现

- 解的表示；
- 初始解；
- 邻域操作；
- 评价函数；
- 可行性检查；
- 移动选择；
- 停止条件。

## 通常由标准库提供

- 随机数；
- 列表操作；
- 排序；
- 最小值和最大值查找。

局部搜索通常不需要专门求解器。

# 12. 它真正帮我解决什么

| 问题 | 回答 |
|---|---|
| 帮助理解问题？ | 不会，需要人先定义方案 |
| 帮助建立模型？ | 不直接建模 |
| 帮助搜索答案？ | 是，搜索当前方案附近 |
| 帮助预测结果？ | 不是 |
| 帮助连续决策？ | 通常不是 |
| 帮助验证可行？ | 可以调用人定义的检查规则 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 调度、路径、排序 | 容易设计邻域 |
| 已经有初始方案 | 可以直接改进 |
| 精确算法太慢 | 搜索速度通常较快 |
| 只需要较好方案 | 不必证明最优 |

| 不太适合 | 原因 |
|---|---|
| 必须证明全局最优 | 局部搜索不能保证 |
| 很难设计邻域 | 无法有效移动 |
| 局部最优很多 | 容易卡住 |
| 每次评价成本很高 | 搜索会很慢 |

# 14. 与相近算法比较

| 对比项 | 局部搜索 | Greedy | ILS |
|---|---|---|---|
| 起点 | 一个完整方案 | 通常从空方案开始 | 一个完整方案 |
| 搜索方式 | 小幅修改 | 每次直接选当前最好 | 局部搜索后再扰动 |
| 是否回头修改 | 会 | 通常不会 | 会 |
| 跳出局部最优 | 基础版本不能 | 不涉及 | 可以通过扰动 |
| 主要用途 | 改进方案 | 构造方案 | 多次改进不同区域 |

# 15. 可以与其他算法融合的位置

## 15.1 Greedy＋Local Search

```text
Greedy
  ↓ 快速生成初始解
Local Search
  ↓ 继续改进
最终方案
```

## 15.2 GA/NSGA-II＋Local Search

```text
GA或NSGA-II
  ↓ 生成个体
Local Search
  ↓ 改进优秀个体
下一代种群
```

这种组合常称为模因算法。

## 15.3 MILP/CP＋Local Search

```text
MILP或CP
  ↓ 生成可行解
Local Search
  ↓ 快速改进
更好的方案
```

局部搜索也可以先生成候选解，再交给精确求解器继续处理。

## 15.4 RL＋Local Search

```text
当前搜索状态
  ↓
RL选择邻域操作
  ↓
Local Search执行修改
```

RL 可以学习什么时候使用交换、插入或反转。

# 16. 最小示例

## 16.1 原始问题

安排四个任务的执行顺序，使总延误最小。

## 16.2 输入

```text
当前顺序：A-B-C-D
目标值：100
```

## 16.3 邻域操作

```text
交换任意两个任务
```

## 16.4 搜索过程

```text
交换B和C：
A-C-B-D
目标值：82
→ 更好，接受

继续检查附近方案：
没有低于82的邻居
→ 停止
```

## 16.5 输出

```text
最终顺序：A-C-B-D
目标值：82
```

这个结果是局部最优，但不一定是所有排列中的全局最优。

# 17. 一句话总结

> 人负责定义解、邻域、评价和约束；局部搜索负责不断用更好的邻近方案替换当前方案；最终输出一个局部最优解，但通常不能保证全局最优。
