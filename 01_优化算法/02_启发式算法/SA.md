# SA：模拟退火

SA 指 Simulated Annealing（模拟退火），不是敏感性分析。

# 1. 一句话说明它是什么

> 模拟退火是一种在搜索前期偶尔接受较差方案、后期逐渐只接受更好方案的方法，主要用于跳出局部最优。

直观理解：

```text
高温：敢于乱走，探索更多区域
低温：逐渐保守，专注改进当前区域
```

SA 通常不能证明全局最优，但比基础局部搜索更不容易卡住。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义方案怎么表示
  ├── 定义怎样修改方案
  ├── 定义方案好坏
  ├── 设置初始温度和降温规则
  └── 定义停止条件
  ↓
SA需要完成的工作
  ├── 生成邻近方案
  ├── 评价新方案
  ├── 接受更好方案
  ├── 按概率接受较差方案
  ├── 逐渐降低温度
  └── 保存历史最好方案
  ↓
最终结果
  └── 搜索过程中找到的最好方案
```

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 一个完整方案

怎样小幅修改方案？
→ 邻域操作

什么情况不能发生？
→ 可行性检查

什么结果算更好？
→ 评价函数

怎样跳出局部最优？
→ 接受部分较差方案

探索程度怎样逐渐降低？
→ 温度和降温规则
```

常见对应关系：

| 问题 | 解的表示 | 邻域操作 |
|---|---|---|
| 任务排序 | 任务序列 | 交换两个任务 |
| 车辆路径 | 客户顺序 | 交换、插入、反转 |
| 机器分配 | 工序—机器 | 更换机器 |
| 员工排班 | 班次表 | 调换班次 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始输入 | 问题数据 | 任务、机器、时间 |
| 算法输入 | 初始解、邻域、温度参数 | 任务顺序、交换操作 |
| 内部数据 | 当前解、最好解、温度 | 当前成本100、温度50 |
| 输出 | 搜索到的最好方案 | 最好成本82 |

# 7. 完整运行流程

```text
生成初始解
  ↓
设置初始温度
  ↓
生成邻近方案
  ↓
新方案更好？
  ├── 是：接受
  └── 否：按概率决定是否接受
  ↓
更新历史最好解
  ↓
降低温度
  ↓
达到停止条件？
  ├── 否：继续搜索
  └── 是：输出最好解
```

# 9. 每个模块的输入、输出和构成

## 9.1 初始解 Initial Solution

### 作用

提供搜索起点。

### 输入

- 问题数据；
- 约束条件。

### 内部构成

```text
InitialSolution
├── RandomBuilder
└── GreedyBuilder
```

### 处理过程

随机生成或使用贪心方法构造方案。

### 输出

- 初始可行解。

### 是否需要用户自己实现

通常需要自己实现。

## 9.2 邻域 Neighborhood

### 作用

小幅修改当前方案。

### 输入

- 当前解；
- 邻域类型。

### 内部构成

```text
Neighborhood
├── Swap
├── Insert
└── Reverse
```

### 处理过程

随机执行一次交换、插入或反转。

### 输出

- 一个邻近方案。

### 是否需要用户自己实现

通常需要自己实现。

## 9.3 评价 Evaluation

### 作用

判断方案好坏。

### 输入

- 候选方案；
- 问题数据。

### 内部构成

```text
Evaluation
├── Objective
└── ConstraintPenalty
```

### 处理过程

计算成本、距离、延误或完工时间。

### 输出

- 目标值；
- 是否可行。

### 是否需要用户自己实现

通常需要自己实现。

## 9.4 接受规则 Acceptance

### 作用

决定是否采用新方案。

### 输入

- 当前目标值；
- 新目标值；
- 当前温度；
- 随机数。

### 内部构成

```text
Acceptance
├── BetterAcceptance
└── WorseProbability
```

### 处理过程

```text
新方案更好
→ 一定接受

新方案更差
→ 高温时较可能接受
→ 低温时较少接受
```

### 输出

- 接受或拒绝；
- 下一轮当前解。

### 是否需要用户自己实现

通常需要自己实现，是 SA 的核心。

## 9.5 降温 Cooling

### 作用

让算法从大胆探索逐渐转为稳定改进。

### 输入

- 当前温度；
- 降温速度。

### 内部构成

```text
Cooling
├── TemperatureUpdate
└── MinimumTemperature
```

### 处理过程

常见方式：

```text
新温度 = 当前温度 × 降温系数
```

例如：

```text
100 → 95 → 90.25 → ...
```

### 输出

- 新温度。

### 是否需要用户自己实现

通常只需设置初始温度、降温系数和最低温度。

## 9.6 主循环 Main Loop

### 作用

组织邻域、接受和降温过程。

### 输入

- 初始解；
- 各功能模块；
- 停止条件。

### 内部构成

```text
MainLoop
├── Generate
├── Evaluate
├── Accept
├── UpdateBest
├── Cool
└── Stop
```

### 处理过程

重复生成候选、决定接受、更新最好解并降温。

### 输出

- 历史最好解；
- 最好目标值。

### 是否需要用户自己实现

通常需要自己实现，但主循环较短。

# 11. 用户需要实现什么

## 通常需要自己实现

- 解的表示；
- 初始解；
- 邻域操作；
- 评价函数；
- 可行性检查；
- 初始温度；
- 降温规则；
- 接受规则；
- 停止条件。

## 通常由标准库提供

- 随机数；
- 指数计算；
- 列表操作；
- 时间记录。

SA 通常不需要专门求解器。

# 12. 它真正帮我解决什么

| 问题 | 回答 |
|---|---|
| 帮助理解问题？ | 不会，需要人定义方案和规则 |
| 帮助建立模型？ | 不直接建模 |
| 帮助搜索答案？ | 是，通过随机邻域搜索 |
| 帮助预测结果？ | 不是 |
| 帮助连续决策？ | 通常不是 |
| 帮助验证可行？ | 可以调用人定义的检查规则 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 局部最优很多 | 可以接受较差解跳出去 |
| 调度、路径、排序 | 容易设计邻域 |
| 只需要较好方案 | 不必证明最优 |
| 精确算法太慢 | SA通常更灵活 |

| 不太适合 | 原因 |
|---|---|
| 必须证明全局最优 | SA通常不能证明 |
| 参数难设置 | 温度不合适会影响结果 |
| 邻域难设计 | 无法有效搜索 |
| 评价一次非常慢 | 大量迭代成本高 |

# 14. 与相近算法比较

| 对比项 | SA | 局部搜索 | ILS |
|---|---|---|---|
| 是否接受较差解 | 按概率接受 | 通常不接受 | 扰动后可能接受 |
| 跳出局部最优 | 温度概率 | 基础版本不能 | 扰动 |
| 核心参数 | 温度、降温速度 | 邻域 | 扰动强度 |
| 搜索方式 | 连续随机移动 | 持续改进 | 局部优化后重启 |
| 最优保证 | 通常没有 | 通常没有 | 通常没有 |

# 15. 可以与其他算法融合的位置

## 15.1 Greedy＋SA

```text
Greedy
  ↓ 生成较好初始解
SA
  ↓ 跳出局部最优并继续改进
最终方案
```

## 15.2 GA/NSGA-II＋SA

```text
GA或NSGA-II
  ↓ 生成优秀个体
SA
  ↓ 局部改进个体
下一代种群
```

## 15.3 MILP/CP＋SA

```text
SA
  ↓ 生成候选方案
MILP或CP
  ↓ 修复约束并精确优化
可行方案
```

也可以先由精确求解器生成初始解，再交给 SA 改进。

## 15.4 RL＋SA

```text
当前搜索状态
  ↓
RL选择温度、邻域或降温速度
  ↓
SA执行搜索
```

RL 可以帮助 SA 自适应控制参数。

# 16. 最小示例

## 16.1 原始问题

安排任务顺序，使总延误最小。

## 16.2 输入

```text
当前顺序：A-B-C-D
当前目标值：100
初始温度：高
```

## 16.3 搜索过程

```text
产生新方案：
A-C-B-D
目标值：90
→ 更好，接受

产生新方案：
C-A-B-D
目标值：96
→ 更差，但高温时可能接受

从96继续搜索：
C-A-D-B
目标值：80
→ 更好，接受并更新最好解
```

如果一直拒绝96，就可能到不了80。

温度降低后，算法会越来越少接受较差方案。

## 16.4 输出

```text
最好顺序：C-A-D-B
最好目标值：80
```

# 17. 一句话总结

> 人负责定义解、邻域、评价、温度和降温规则；SA 负责在高温时大胆探索、低温时稳定改进；最终输出搜索过程中找到的最好方案，但通常不能证明全局最优。

# 18. 理解检查

SA 遇到一个稍差的新方案时，当前温度越高，它被接受的可能性会更高还是更低？
