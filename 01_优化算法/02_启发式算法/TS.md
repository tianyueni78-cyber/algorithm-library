# TS：禁忌搜索

TS 指 Tabu Search（禁忌搜索）。

# 1. 一句话说明它是什么

> 禁忌搜索是一种“允许暂时变差，但禁止马上走回头路”的搜索方法，主要用于跳出局部最优。

核心思路：

```text
选择当前最好操作
→ 记录这个操作
→ 暂时禁止撤销
→ 继续探索新区域
```

TS 通常不能证明全局最优，但比基础局部搜索更不容易反复绕圈。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义方案怎么表示
  ├── 定义邻域操作
  ├── 定义方案好坏
  ├── 定义什么被记录为禁忌
  └── 设置禁忌期限和停止条件
  ↓
TS需要完成的工作
  ├── 生成邻近方案
  ├── 排除禁忌操作
  ├── 选择最好允许方案
  ├── 更新禁忌表
  └── 保存历史最好方案
  ↓
最终结果
  └── 搜索过程中找到的最好方案
```

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 一个完整方案

怎样小幅修改方案？
→ 邻域操作

什么情况绝对不允许？
→ 可行性约束

什么结果算更好？
→ 评价函数

怎样避免回到刚才的方案？
→ 禁忌表

禁忌操作什么时候可以破例？
→ 特赦规则
```

常见对应关系：

| 问题 | 解的表示 | 邻域操作 |
|---|---|---|
| 任务排序 | 任务序列 | 交换两个任务 |
| 车辆路径 | 客户顺序 | 交换、插入、反转 |
| 机器分配 | 工序—机器 | 更换机器 |
| 员工排班 | 班次表 | 调换班次 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始输入 | 问题数据 | 任务、机器、时间 |
| 算法输入 | 初始解、邻域、禁忌期限 | 任务序列、交换操作 |
| 内部数据 | 当前解、最好解、禁忌表 | 禁止交换B和C三轮 |
| 输出 | 搜索到的最好方案 | 最好成本80 |

# 7. 完整运行流程

```text
生成初始解
  ↓
生成邻近方案
  ↓
过滤禁忌操作
  ↓
检查特赦条件
  ↓
选择最好允许方案
  ↓
更新当前解
  ↓
更新历史最好解
  ↓
更新禁忌表
  ↓
达到停止条件？
  ├── 否：继续搜索
  └── 是：输出最好解
```

# 9. 每个模块的输入、输出和构成

## 9.1 初始解 Initial Solution

### 作用

提供搜索起点。

### 输入

- 问题数据；
- 约束规则。

### 内部构成

```text
InitialSolution
├── RandomBuilder
└── GreedyBuilder
```

### 处理过程

随机生成或使用贪心规则构造方案。

### 输出

- 初始可行解。

### 是否需要用户自己实现

通常需要自己实现。

## 9.2 邻域 Neighborhood

### 作用

生成当前方案附近的新方案。

### 输入

- 当前解；
- 邻域类型。

### 内部构成

```text
Neighborhood
├── Swap
├── Insert
└── Reverse
```

### 处理过程

对当前方案执行交换、插入或反转。

### 输出

- 一组邻近方案；
- 每个方案对应的操作。

### 是否需要用户自己实现

通常需要自己实现。

## 9.3 评价 Evaluation

### 作用

判断方案好坏。

### 输入

- 候选方案；
- 问题数据。

### 内部构成

```text
Evaluation
├── Objective
└── ConstraintPenalty
```

### 处理过程

计算成本、距离、延误或完工时间。

### 输出

- 目标值；
- 是否可行。

### 是否需要用户自己实现

通常需要自己实现。

## 9.4 禁忌记忆 Tabu Memory

### 作用

记录近期操作，防止立即撤销或重复。

### 输入

- 本轮采用的操作；
- 禁忌期限；
- 当前禁忌表。

### 内部构成

```text
TabuMemory
├── TabuList
├── RemainingTenure
└── ExpirationUpdate
```

### 处理过程

例如本轮交换了 B 和 C：

```text
记录：交换B和C
期限：3轮
```

接下来3轮暂时禁止执行相反操作。

### 输出

- 更新后的禁忌表。

### 是否需要用户自己实现

通常需要自己实现，是 TS 的核心。

## 9.5 特赦规则 Aspiration

### 作用

允许特别优秀的禁忌操作破例执行。

### 输入

- 禁忌候选解；
- 候选目标值；
- 历史最好目标值。

### 内部构成

```text
Aspiration
└── GlobalBestCheck
```

### 处理过程

```text
操作虽然被禁忌
但产生了历史最好方案
→ 允许执行
```

### 输出

- 是否解除本次禁忌。

### 是否需要用户自己实现

通常需要自己实现，规则一般很简单。

## 9.6 主循环 Main Loop

### 作用

组织邻域、禁忌判断和方案更新。

### 输入

- 初始解；
- 各模块；
- 停止条件。

### 内部构成

```text
MainLoop
├── Generate
├── FilterTabu
├── Select
├── UpdateBest
├── UpdateMemory
└── Stop
```

### 处理过程

即使所有允许方案都更差，也通常选择其中最好的一个继续前进。

### 输出

- 历史最好解；
- 最好目标值。

### 是否需要用户自己实现

通常需要自己实现。

# 11. 用户需要实现什么

## 通常需要自己实现

- 解的表示；
- 初始解；
- 邻域操作；
- 评价函数；
- 可行性检查；
- 禁忌内容；
- 禁忌期限；
- 特赦规则；
- 停止条件。

## 通常由标准库提供

- 列表或队列；
- 字典和集合；
- 随机数；
- 排序。

TS 通常不需要专门求解器。

# 12. 它真正帮我解决什么

| 问题 | 回答 |
|---|---|
| 帮助理解问题？ | 不会，需要人定义方案和规则 |
| 帮助建立模型？ | 不直接建模 |
| 帮助搜索答案？ | 是，通过带记忆的邻域搜索 |
| 帮助预测结果？ | 不是 |
| 帮助连续决策？ | 通常不是 |
| 帮助验证可行？ | 可以调用人定义的检查规则 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 局部最优很多 | 可以接受暂时变差 |
| 搜索容易来回循环 | 禁忌表可阻止回头 |
| 调度、路径和排序 | 容易定义邻域操作 |
| 只需要较好方案 | 不必证明最优 |

| 不太适合 | 原因 |
|---|---|
| 必须证明全局最优 | TS通常不能证明 |
| 很难设计禁忌内容 | 记忆机制会失效 |
| 邻域非常大 | 每轮评价成本高 |
| 每次评价很慢 | 总搜索时间会很长 |

# 14. 与相近算法比较

| 对比项 | TS | 局部搜索 | SA |
|---|---|---|---|
| 是否接受较差解 | 可以 | 通常不接受 | 按概率接受 |
| 跳出局部最优 | 禁忌记忆 | 基础版本不能 | 温度概率 |
| 防止走回头路 | 禁忌表 | 没有 | 没有明确记忆 |
| 核心参数 | 禁忌期限 | 邻域 | 温度和降温速度 |
| 最优保证 | 通常没有 | 通常没有 | 通常没有 |

# 15. 可以与其他算法融合的位置

## 15.1 Greedy＋TS

```text
Greedy
  ↓ 生成较好的初始解
TS
  ↓ 继续搜索并避免循环
最终方案
```

## 15.2 GA/NSGA-II＋TS

```text
GA或NSGA-II
  ↓ 生成优秀个体
TS
  ↓ 局部改进个体
下一代种群
```

## 15.3 MILP/CP＋TS

```text
TS
  ↓ 生成候选方案
MILP或CP
  ↓ 修复并精确优化
可行方案
```

也可以先由精确求解器生成初始解，再交给 TS 改进。

## 15.4 RL＋TS

```text
当前搜索状态
  ↓
RL选择邻域或禁忌期限
  ↓
TS执行搜索
```

RL 可以动态调整：

- 使用哪种邻域；
- 禁忌多长时间；
- 是否扩大搜索范围。

# 16. 最小示例

## 16.1 原始问题

安排任务顺序，使总延误最小。

## 16.2 输入

```text
当前顺序：A-B-C-D
当前目标值：100
禁忌期限：3轮
```

## 16.3 搜索过程

```text
交换B和C：
A-C-B-D
目标值：90
→ 接受

将“交换B和C”加入禁忌表
→ 3轮内不能马上换回去
```

下一轮允许方案都比90差：

```text
C-A-B-D
目标值：95
```

TS 仍可接受95，以离开当前区域。

随后找到：

```text
C-A-D-B
目标值：80
```

更新历史最好解。

如果某个禁忌操作能直接得到75，即使它在禁忌表中，也可以通过特赦规则执行。

## 16.4 输出

```text
最好顺序：产生目标值75的方案
最好目标值：75
```

# 17. 一句话总结

> 人负责定义解、邻域、评价、禁忌内容和期限；TS 负责利用禁忌记忆避免回头，并允许暂时变差以探索新区域；最终输出历史最好方案，但通常不能证明全局最优。
