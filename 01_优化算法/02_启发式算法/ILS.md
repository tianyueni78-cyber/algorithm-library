# ILS：迭代局部搜索

ILS 指 Iterated Local Search（迭代局部搜索），不是模仿学习。

# 1. 一句话说明它是什么

> ILS 是一种“先把当前方案改好，卡住后打乱一下，再继续改”的搜索方法，主要用于寻找较好的调度、路径或排序方案。

核心流程：

```text
局部优化
→ 卡住
→ 扰动
→ 再次局部优化
```

ILS 通常不能保证找到全局最优解，但比单次局部搜索更容易跳出局部最优。

# 3. 人和算法分别负责什么
```text
现实问题
  ↓
人需要完成的工作
  ├── 定义解怎么表示
  ├── 定义怎样修改一个解
  ├── 定义方案好坏
  ├── 定义扰动方式
  └── 定义接受规则
  ↓
ILS需要完成的工作
  ├── 生成初始解
  ├── 执行局部搜索
  ├── 扰动当前解
  ├── 再次局部搜索
  ├── 判断是否接受新解
  └── 保存历史最好解
  ↓
最终结果
  └── 搜索过程中找到的最好方案
```

人向 ILS 提供：

- 问题数据；
- 解的表示；
- 评价函数；
- 邻域操作；
- 扰动操作；
- 接受规则；
- 停止条件。

ILS 返回：

- 最好方案；
- 最好目标值；
- 搜索记录。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 一个完整方案

怎样小幅修改方案？
→ 邻域操作

什么情况不允许？
→ 可行性检查或修复规则

什么结果算更好？
→ 评价函数

局部搜索卡住后怎样跳出去？
→ 扰动操作

什么新方案可以保留？
→ 接受规则
```

常见对应关系：

| 现实问题 | 解的表示 | 邻域操作 |
|---|---|---|
| 任务排序 | 任务序列 | 交换两个任务 |
| 机器分配 | 工序—机器组合 | 更换一台机器 |
| 车辆路径 | 客户访问顺序 | 交换、插入、反转 |
| 员工排班 | 员工班次表 | 调换两个班次 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始输入 | 任务、机器、时间、距离 | 10项任务、3台机器 |
| 算法输入 | 解、评价函数、邻域和扰动 | 任务序列、交换操作 |
| 内部数据 | 当前解、新解、最好解 | 当前成本100 |
| 输出 | 搜索到的最好方案 | 最好成本82 |

# 7. 完整运行流程

```text
现实问题
  ↓
生成初始解
  ↓
局部搜索
  ↓
得到局部最优解
  ↓
扰动当前解
  ↓
再次局部搜索
  ↓
接受或拒绝新解
  ↓
更新历史最好解
  ↓
是否停止？
  ├── 否：继续扰动
  └── 是：输出最好解
```

# 9. 每个模块的输入、输出和构成

## 9.1 初始解 Initial Solution

### 作用

生成搜索起点。

### 输入

- 问题数据；
- 可行性规则。

### 内部构成

```text
InitialSolution
├── RandomBuilder
└── GreedyBuilder
```

### 处理过程

随机生成或使用贪心规则构造一个完整方案。

### 输出

- 初始可行解。

### 是否需要用户自己实现

通常需要自己实现。

## 9.2 评价 Evaluation

### 作用

判断哪个方案更好。

### 输入

- 一个完整方案；
- 问题数据。

### 内部构成

```text
Evaluation
├── Objective
├── ConstraintPenalty
└── FeasibilityCheck
```

### 处理过程

计算成本、时间、距离或其他目标。

### 输出

- 目标值；
- 是否可行。

### 是否需要用户自己实现

通常需要自己实现。

## 9.3 局部搜索 Local Search

### 作用

不断小幅修改当前方案，直到附近找不到更好的方案。

### 输入

- 当前解；
- 邻域操作；
- 评价函数。

### 内部构成

```text
LocalSearch
├── NeighborGenerator
├── NeighborEvaluation
└── MoveSelection
```

### 处理过程

```text
生成邻居
→ 评价邻居
→ 接受更好邻居
→ 重复
```

### 输出

- 局部最优解。

### 是否需要用户自己实现

通常需要自己实现，也可以复用已有局部搜索代码。

## 9.4 扰动 Perturbation

### 作用

较大幅度修改当前解，帮助跳出局部最优。

### 输入

- 当前局部最优解；
- 扰动强度。

### 内部构成

```text
Perturbation
├── Swap
├── Insert
└── MultiMove
```

### 处理过程

随机执行一次或多次修改。

### 输出

- 被扰动的新起点。

### 是否需要用户自己实现

通常需要自己实现。

扰动太小可能跳不出去，太大则接近重新随机搜索。

## 9.5 接受规则 Acceptance

### 作用

决定是否用新解替换当前解。

### 输入

- 当前解；
- 新局部最优解；
- 两者目标值。

### 内部构成

```text
Acceptance
├── BetterOnly
└── ProbabilisticAcceptance
```

### 处理过程

常见规则：

```text
新解更好 → 接受
新解更差 → 拒绝
```

也可以偶尔接受较差解，提高跳出局部最优的能力。

### 输出

- 下一轮使用的当前解。

### 是否需要用户自己实现

通常需要自己实现。

## 9.6 主循环 Main Loop

### 作用

组织局部搜索、扰动和接受过程。

### 输入

- 初始解；
- 各模块；
- 停止条件。

### 内部构成

```text
MainLoop
├── LocalSearch
├── Perturb
├── Accept
├── UpdateBest
└── Stop
```

### 处理过程

重复调用各模块，并保存历史最好方案。

### 输出

- 历史最好解；
- 最好目标值。

### 是否需要用户自己实现

通常需要自己实现，但主循环很短。

# 11. 用户需要实现什么

## 通常需要自己实现

- 解的表示；
- 初始解生成；
- 评价函数；
- 邻域操作；
- 可行性检查；
- 局部搜索；
- 扰动操作；
- 接受规则；
- 停止条件。

## 通常由标准库提供

- 随机数；
- 排序；
- 列表操作；
- 时间记录。

ILS 通常不需要专门求解器。

# 12. 它真正帮我解决什么

| 问题 | 回答 |
|---|---|
| 帮助理解问题？ | 不会，需要人先定义方案和规则 |
| 帮助建立模型？ | 不直接建模，需要人定义解和评价 |
| 帮助搜索答案？ | 是，通过反复局部搜索寻找更好方案 |
| 帮助预测结果？ | 不是 |
| 帮助连续决策？ | 通常不是，主要优化一个完整方案 |
| 帮助验证可行？ | 可以调用人定义的检查或修复规则 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 调度、路径和排序 | 容易设计交换、插入等邻域 |
| 单次局部搜索容易卡住 | 扰动可以更换搜索区域 |
| 精确算法太慢 | ILS通常更快 |
| 已有局部搜索代码 | 很容易扩展成ILS |

| 不太适合 | 原因 |
|---|---|
| 必须证明全局最优 | ILS通常不能证明 |
| 很难设计邻域 | 无法有效改进方案 |
| 评价一次非常昂贵 | 搜索成本会很高 |
| 扰动后很难恢复可行 | 大量时间花在修复上 |

# 14. 与相近算法比较

| 对比项 | ILS | 局部搜索 | 模拟退火 |
|---|---|---|---|
| 核心方式 | 局部优化后扰动再搜索 | 一直改进当前附近 | 按概率接受较差解 |
| 跳出局部最优 | 靠扰动 | 基础版本不能 | 靠温度和概率 |
| 主要参数 | 扰动强度、接受规则 | 邻域和选择规则 | 初始温度、降温速度 |
| 最优保证 | 通常没有 | 通常没有 | 通常没有 |
| 适用场景 | 调度、路径、组合优化 | 局部改进 | 搜索区域复杂的问题 |

# 15. 可以与其他算法融合的位置

## 15.1 Greedy＋ILS

```text
Greedy
  ↓ 生成较好的初始解
ILS
  ↓ 反复改进
最终方案
```

贪心负责快速初始化，ILS 负责继续优化。

## 15.2 ILS＋MILP/CP

```text
ILS
  ↓ 生成候选解或部分决定
MILP/CP
  ↓ 修复并精确优化
可行方案
```

也可以由 MILP/CP 生成初始解，再交给 ILS 快速改进。

## 15.3 ILS＋RL

```text
当前搜索状态
  ↓
RL选择邻域或扰动强度
  ↓
ILS执行搜索
```

RL 可以动态控制：

- 使用哪种邻域；
- 扰动多少；
- 是否接受新解。

# 16. 最小示例

## 16.1 原始问题

需要安排一组任务顺序，使总延误尽量小。

## 16.2 输入

```text
任务：A、B、C、D
初始顺序：A-B-C-D
```

## 16.3 搜索过程

```text
初始方案：
A-B-C-D
目标值：120

局部搜索后：
A-C-B-D
目标值：100
附近没有更好方案，搜索卡住

扰动：
D-C-B-A
目标值：135

再次局部搜索：
C-D-A-B
目标值：92

92优于100，因此接受
```

## 16.4 输出

```text
最好顺序：C-D-A-B
最好目标值：92
```

关键点：

> 扰动后的方案可以暂时更差，因为它的作用是把搜索带到新的区域。

# 17. 一句话总结

> 人负责定义解、评价函数、邻域、扰动和接受规则；ILS 负责反复进行“局部优化—扰动—再优化”；最终输出搜索过程中找到的最好方案，但通常不能证明它是全局最优。
