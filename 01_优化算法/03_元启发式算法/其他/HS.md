# HS（和声搜索算法）

# 1. 一句话说明它是什么

> HS 是一种从历史优秀方案中取值、进行小幅调整或随机尝试的优化算法，主要用于寻找较优的参数或组合方案。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义需要决定的内容
  ├── 设置取值范围和约束
  └── 定义评价方法
  ↓
HS需要完成的工作
  ├── 保存一组较好方案
  ├── 从历史方案中选择参数值
  ├── 对部分参数小幅调整
  ├── 随机尝试新参数
  └── 用新方案替换较差方案
  ↓
最终结果
  └── 找到的最好方案及其评价值
```

HS不会自动发现变量、目标和约束，这些必须由人定义。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 需要调整的参数或选择

什么情况绝对不允许？
→ 参数边界和业务约束

什么结果算更好？
→ 目标函数

哪些信息已经知道？
→ 业务数据和固定参数

哪些信息会发生变化？
→ 环境、需求和设备状态
```

| 关键词 | 对应内容 |
|---|---|
| 调整、设置、选择、分配 | 决策变量 |
| 必须、不能、最多、至少 | 约束 |
| 最小、最大、更快、更省 | 目标 |
| 已知、给定、测量 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 设备或任务数据 | 速度、温度、成本 |
| 建模后的输入 | 变量范围、目标、约束 | 速度1～10 |
| 算法内部数据 | 和声记忆库、新和声、评分 | 多组候选方案 |
| 最终业务输出 | 最好方案和目标值 | 最佳速度7.2 |

“和声记忆库”就是保存当前较好方案的集合。

# 7. 完整运行流程

```text
随机生成和声记忆库
  ↓
生成一个新方案
  ├── 从记忆库取值
  ├── 小幅调整
  └── 随机取值
  ↓
检查约束
  ↓
评价新方案
  ↓
比最差方案更好？
  ├── 是 → 替换
  └── 否 → 丢弃
  ↓
达到停止条件？
  ├── 否 → 继续
  └── 是 → 输出最好方案
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存变量、范围、目标和约束。

### 输入

- 业务数据
- 变量范围
- 评价规则

### 内部构成

```text
Problem_Data
├── data
├── bounds
├── objective
└── constraints
```

### 处理过程

把现实问题整理成可评价的优化问题。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Harmony_Memory

### 作用

保存当前较好的候选方案。

### 输入

- 变量范围
- 记忆库大小

### 内部构成

```text
Harmony_Memory
├── initialize_memory()
├── sort_harmonies()
└── find_best_and_worst()
```

### 处理过程

随机生成多个方案，评价后保存。

### 输出

- 和声记忆库
- 最好和最差方案

### 是否需要用户自己实现

算法库通常可以提供。

## 03_Improvisation

### 作用

生成新的候选方案。

### 输入

- 和声记忆库
- 记忆选择概率
- 音调调整概率
- 调整幅度

### 内部构成

```text
Improvisation
├── select_from_memory()
├── pitch_adjust()
├── random_select()
└── create_new_harmony()
```

### 处理过程

每个变量从记忆库取值或随机生成，再决定是否微调。

### 输出

- 新和声方案

### 是否需要用户自己实现

通常由算法库提供。

## 04_Evaluation

### 作用

评价并检查新方案。

### 输入

- 新方案
- Problem

### 内部构成

```text
Evaluation
├── check_constraints()
├── repair()
└── calculate_objective()
```

### 处理过程

处理非法变量并计算目标值。

### 输出

- 目标值
- 可行性结果

### 是否需要用户自己实现

目标和约束通常需要自己实现。

## 05_Memory_Update

### 作用

决定是否将新方案放入记忆库。

### 输入

- 新方案
- 当前记忆库

### 内部构成

```text
Memory_Update
├── compare_with_worst()
├── replace_worst()
└── update_best()
```

### 处理过程

新方案更好时替换当前最差方案。

### 输出

- 更新后的和声记忆库
- 当前最好方案

### 是否需要用户自己实现

通常由算法库提供。

## 06_Main_Solver

### 作用

控制HS完整运行。

### 输入

- Problem
- HS配置

### 内部构成

```text
Main_Solver
├── initialize()
├── improvise()
├── evaluate()
├── update_memory()
└── stop()
```

### 处理过程

重复生成新方案、评价和更新记忆库。

### 输出

- 最好方案
- 最好目标值
- 运行记录

### 是否需要用户自己实现

主框架通常由算法库提供。

# 12. 它真正帮我解决什么

| 问题 | HS的作用 |
|---|---|
| 理解问题？ | 不能，人负责分析。 |
| 建立模型？ | 不能自动建立。 |
| 搜索答案？ | 是，这是主要作用。 |
| 预测结果？ | 不能，可与预测模型结合。 |
| 连续决策？ | 通常不是，环境变化后需重新运行。 |
| 验证可行性？ | 可以执行人定义的约束检查。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 连续参数优化 | 可以直接微调参数 |
| 离散组合问题 | 可以从记忆库选择离散值 |
| 无法计算导数 | 只需要评价方案 |

| 不太适合 | 原因 |
|---|---|
| 必须证明最优 | HS通常不能证明 |
| 评价成本很高 | 需要反复评价新方案 |
| 约束非常复杂 | 需要额外修复方法 |

# 14. 与相近算法比较

| 对比项 | HS | GA | SA |
|---|---|---|---|
| 历史方案 | 和声记忆库 | 种群 | 当前方案 |
| 新方案产生 | 记忆取值、微调、随机取值 | 交叉和变异 | 邻域移动 |
| 同时保留方案 | 多个 | 多个 | 一个 |
| 保证最优 | 不保证 | 不保证 | 不保证 |

# 15. 可以与其他算法融合的位置

```text
贪心算法
  ↓ 生成较好的初始记忆库
HS
  ↓ 找到较好方案
局部搜索
  ↓ 精细调整
最终方案
```

| 融合方式 | 位置 | 数据传递 | 作用 |
|---|---|---|---|
| HS + 局部搜索 | 最终精调 | HS输出最好方案 | 提高精度 |
| HS + DE | 新方案生成 | DE提供差分候选值 | 增强搜索能力 |
| HS + RL | 参数控制 | RL调整选择和微调概率 | 动态控制搜索 |
| HS + CP/MILP | 修复或补全 | HS输出候选方案 | 处理复杂约束 |

# 16. 最小示例

## 原始问题

调整机器速度，使产品误差最小。

## 输入数据

```text
速度范围：1～10
```

## 变量

```text
机器速度
```

## 规则

```text
速度不能超出1～10
```

## 目标

```text
产品误差最小
```

## 执行过程

```text
记忆库：速度3、6、9
  ↓
从记忆库选择6
  ↓
小幅调整为6.5
  ↓
评价6.5
  ↓
若优于最差方案3，则替换3
```

## 输出结果

```text
最好速度：约7.2
产品误差：当前最小值
```

# 17. 一句话总结

> 人负责定义变量、范围、约束和评价方法；HS负责从优秀方案中取值、微调或随机尝试；最终输出找到的较优方案。
