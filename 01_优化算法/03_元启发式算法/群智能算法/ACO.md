# ACO（蚁群优化算法）

# 1. 一句话说明它是什么

> ACO 是一种让多个候选方案逐步完成选择、再用优秀方案影响后续搜索的算法，主要用于路径、顺序和组合优化。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义可选择的节点或任务
  ├── 定义哪些选择允许连接
  ├── 定义方案评价方法
  └── 设置约束
  ↓
ACO需要完成的工作
  ├── 让多只蚂蚁分别构造方案
  ├── 评价完整方案
  ├── 增强优秀选择的信息素
  └── 重复搜索
  ↓
最终结果
  └── 找到的较优路径、顺序或组合
```

ACO不会自动理解现实问题，也不会自动发现节点、约束和目标。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 下一步选择哪个节点、任务或资源

什么情况绝对不允许？
→ 约束和可行选择集合

什么结果算更好？
→ 距离、时间、成本等目标

哪些信息已经知道？
→ 节点、距离、任务和资源数据

哪些信息会发生变化？
→ 路况、任务、故障和需求
```

| 自然语言关键词 | 对应内容 |
|---|---|
| 路径、顺序、先后、选择 | 决策 |
| 必须、不能、只能 | 约束 |
| 最短、最快、最便宜 | 目标 |
| 距离、成本、加工时间 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 节点、距离和任务数据 | 城市距离表 |
| 建模后的输入 | 可选连接、目标和约束 | 每个城市访问一次 |
| 算法内部数据 | 信息素、启发信息、蚂蚁方案 | 各条边的吸引力 |
| 最终业务输出 | 最好路径或顺序 | A→C→B→A |

- 信息素：历史优秀方案留下的偏好。
- 启发信息：当前看来更值得选择的局部信息，例如距离较短。

# 7. 完整运行流程

```text
建立节点和可选连接
  ↓
初始化信息素
  ↓
每只蚂蚁逐步构造方案
  ↓
检查约束
  ↓
评价完整方案
  ↓
信息素蒸发
  ↓
优秀方案增加信息素
  ↓
达到停止条件？
  ├── 否 → 继续
  └── 是 → 输出最好方案
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存节点、连接、成本和约束。

### 输入

- 业务数据
- 可选连接
- 评价规则

### 内部构成

```text
Problem_Data
├── nodes
├── connections
├── costs
└── constraints
```

### 处理过程

把现实问题转换成可逐步选择的结构。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Pheromone

### 作用

保存各个选择的历史偏好。

### 输入

- 可选连接
- 初始信息素

### 内部构成

```text
Pheromone
├── initialize_pheromone()
└── pheromone_matrix
```

### 处理过程

给每个允许选择设置初始信息素。

### 输出

- 信息素矩阵

### 是否需要用户自己实现

算法库通常可以提供。

## 03_Solution_Construction

### 作用

让每只蚂蚁逐步构造完整方案。

### 输入

- 当前部分方案
- 可行选择
- 信息素
- 启发信息

### 内部构成

```text
Solution_Construction
├── get_feasible_choices()
├── calculate_probability()
├── select_next()
└── build_solution()
```

### 处理过程

计算各选择的概率，选择下一步，直到形成完整方案。

### 输出

- 蚂蚁构造的完整方案

### 是否需要用户自己实现

问题相关的可行选择通常需要自己实现。

## 04_Evaluation

### 作用

评价方案并检查约束。

### 输入

- 完整方案
- Problem

### 内部构成

```text
Evaluation
├── check_feasibility()
├── calculate_objective()
└── rank_solutions()
```

### 处理过程

检查方案是否合法，计算成本并进行排序。

### 输出

- 目标值
- 可行性结果
- 方案排名

### 是否需要用户自己实现

目标和约束通常需要自己实现。

## 05_Pheromone_Update

### 作用

降低旧信息素，并强化优秀方案。

### 输入

- 当前信息素
- 蚂蚁方案
- 方案目标值

### 内部构成

```text
Pheromone_Update
├── evaporate()
├── deposit()
└── limit_pheromone()
```

### 处理过程

先让信息素蒸发，再让优秀方案增加信息素。

### 输出

- 更新后的信息素

### 是否需要用户自己实现

算法库通常提供。

## 06_Main_Solver

### 作用

控制ACO完整运行。

### 输入

- Problem
- ACO配置

### 内部构成

```text
Main_Solver
├── initialize()
├── construct_solutions()
├── evaluate()
├── update_pheromone()
├── update_best()
└── stop()
```

### 处理过程

重复构造方案、评价方案和更新信息素。

### 输出

- 最好方案
- 最好目标值
- 信息素状态

### 是否需要用户自己实现

主框架可由算法库提供。

# 12. 它真正帮我解决什么

| 问题 | ACO的作用 |
|---|---|
| 理解问题？ | 不能，人负责分析。 |
| 建立模型？ | 不能自动建立。 |
| 搜索答案？ | 是，主要搜索路径、顺序和组合。 |
| 预测结果？ | 不能，可与预测模型结合。 |
| 连续决策？ | 能逐步构造一次方案，但不等同于强化学习的动态决策。 |
| 验证可行性？ | 可以执行人定义的约束检查。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 路径规划 | 方案由一段段路径组成 |
| 任务排序 | 可以逐步选择下一个任务 |
| 调度和分配 | 可以逐步构造完整方案 |

| 不太适合 | 原因 |
|---|---|
| 纯连续参数优化 | DE、PSO或CMA-ES通常更直接 |
| 必须证明最优 | ACO通常不能证明 |
| 方案难以逐步构造 | 不容易定义蚂蚁的下一步选择 |

# 14. 与相近算法比较

| 对比项 | ACO | GA | PSO |
|---|---|---|---|
| 方案生成 | 逐步构造 | 交叉和变异 | 参数位置移动 |
| 历史经验 | 信息素 | 优秀个体遗传 | 个体和群体最好位置 |
| 主要变量 | 路径、顺序、组合 | 通用编码 | 连续参数 |
| 保证最优 | 不保证 | 不保证 | 不保证 |

# 15. 可以与其他算法融合的位置

```text
贪心算法
  ↓ 提供启发信息
ACO
  ↓ 输出较好路径或顺序
局部搜索
  ↓ 精细调整
最终方案
```

| 融合方式 | 位置 | 数据传递 | 作用 |
|---|---|---|---|
| ACO + 贪心 | 选择概率 | 贪心提供局部评分 | 加快搜索 |
| ACO + 局部搜索 | 方案改进 | ACO输出完整方案 | 提高方案质量 |
| ACO + RL | 参数控制 | RL输出选择或更新策略 | 适应动态环境 |
| ACO + CP/MILP | 修复或精确优化 | ACO输出候选方案 | 处理复杂约束 |

# 16. 最小示例

## 原始问题

从A出发，访问B和C后返回A，希望总距离最短。

## 输入数据

| 路段 | 距离 |
|---|---:|
| A—B | 2 |
| A—C | 4 |
| B—C | 1 |

## 决策

```text
访问顺序
```

## 规则

```text
每个城市访问一次
最后返回A
```

## 目标

```text
总距离最短
```

## 执行过程

```text
蚂蚁1：A→B→C→A
蚂蚁2：A→C→B→A
  ↓
计算总距离
  ↓
较好路径增加信息素
  ↓
下一轮更可能选择这些连接
```

## 输出结果

```text
路径：A→B→C→A
总距离：7
```

# 17. 一句话总结

> 人负责定义节点、可选连接、约束和评价方法；ACO负责逐步构造方案并用信息素积累搜索经验；最终输出找到的较优路径、顺序或组合。
