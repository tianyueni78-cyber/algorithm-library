# FA（萤火虫算法）

本次的 FA 指 **Firefly Algorithm，萤火虫算法**。

# 1. 一句话说明它是什么

> FA 是一种让较差方案向较好方案靠近、同时保留随机搜索的优化算法，主要用于寻找较优参数组合。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义需要调整的参数
  ├── 设置参数范围和约束
  └── 定义怎样评价方案
  ↓
FA需要完成的工作
  ├── 生成多组候选参数
  ├── 比较方案好坏
  ├── 让较差方案向较好方案移动
  └── 加入随机移动继续探索
  ↓
最终结果
  └── 找到的最好参数及其评价值
```

FA不会自动发现现实问题中的参数、约束和目标。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 需要调整的参数

什么情况绝对不允许？
→ 参数边界和约束

什么结果算更好？
→ 目标函数

哪些信息已经知道？
→ 业务数据和固定参数

哪些信息会发生变化？
→ 环境、需求和设备状态
```

| 关键词 | 对应内容 |
|---|---|
| 调整、设置、比例、系数 | 决策变量 |
| 不能、必须、上限、下限 | 约束 |
| 最小、最大、更快、更省 | 目标 |
| 已知、给定、测量 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 设备或实验数据 | 速度、温度、误差 |
| 建模后的输入 | 参数范围、目标、约束 | 速度1～10 |
| 算法内部数据 | 萤火虫位置、亮度、距离 | 多组候选参数及评分 |
| 最终业务输出 | 最好参数和目标值 | 最佳速度7.2 |

- 萤火虫位置：一组候选参数。
- 亮度：方案质量。
- 吸引力：一个方案对另一个方案的影响程度。

# 7. 完整运行流程

```text
随机生成候选方案
  ↓
评价每个方案
  ↓
比较方案亮度
  ↓
较差方案向较好方案移动
  ↓
加入随机移动
  ↓
处理边界和约束
  ↓
更新最好方案
  ↓
达到停止条件？
  ├── 否 → 继续
  └── 是 → 输出结果
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存参数、范围、目标和约束。

### 输入

- 业务数据
- 参数边界
- 评价方法

### 内部构成

```text
Problem_Data
├── data
├── bounds
├── objective
└── constraints
```

### 处理过程

把现实问题整理成参数优化问题。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Initialization

### 作用

生成初始候选方案。

### 输入

- 参数范围
- 萤火虫数量

### 内部构成

```text
Initialization
├── create_fireflies()
└── initialize_parameters()
```

### 处理过程

在参数范围内随机生成多组方案。

### 输出

- 初始萤火虫种群

### 是否需要用户自己实现

算法库通常可以提供。

## 03_Evaluation

### 作用

评价每只萤火虫代表的方案。

### 输入

- 候选参数
- Problem

### 内部构成

```text
Evaluation
├── calculate_objective()
├── check_constraints()
└── calculate_brightness()
```

### 处理过程

计算目标值，检查约束并转换成亮度。

### 输出

- 目标值
- 亮度
- 可行性结果

### 是否需要用户自己实现

目标和约束通常需要自己实现。

## 04_Attraction_And_Movement

### 作用

让较差方案向较好方案移动。

### 输入

- 两个候选方案
- 两者距离
- 吸引力参数
- 随机搜索参数

### 内部构成

```text
Attraction_And_Movement
├── calculate_distance()
├── calculate_attractiveness()
├── move_toward_brighter()
└── add_random_movement()
```

### 处理过程

计算距离和吸引力，向较好方案靠近，再加入随机变化。

### 输出

- 新候选方案

### 是否需要用户自己实现

通常由算法库提供。

## 05_Constraint_Handling

### 作用

处理越界或违反规则的方案。

### 输入

- 新方案
- 参数边界
- 约束

### 内部构成

```text
Constraint_Handling
├── check_bounds()
├── repair()
└── penalty()
```

### 处理过程

对非法参数进行截断、修复或扣分。

### 输出

- 合法方案
- 或带惩罚的评分

### 是否需要用户自己实现

边界可由库处理；复杂约束通常需要自己实现。

## 06_Main_Solver

### 作用

控制FA完整运行。

### 输入

- Problem
- FA配置

### 内部构成

```text
Main_Solver
├── initialize()
├── evaluate()
├── compare()
├── move()
├── update_best()
└── stop()
```

### 处理过程

重复评价、比较、移动和更新最好方案。

### 输出

- 最好参数
- 最好目标值
- 运行记录

### 是否需要用户自己实现

主框架通常由算法库提供。

# 12. 它真正帮我解决什么

| 问题 | FA的作用 |
|---|---|
| 理解问题？ | 不能，人负责分析。 |
| 建立模型？ | 不能自动建立。 |
| 搜索答案？ | 是，这是主要作用。 |
| 预测结果？ | 不能，可与预测模型结合。 |
| 连续决策？ | 通常不是，环境变化后需重新运行。 |
| 验证可行性？ | 可以执行人定义的约束检查。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 连续参数优化 | 可以直接移动参数 |
| 不需要或没有导数 | 只需评价方案 |
| 存在多个较好区域 | 不同萤火虫可以分别搜索 |

| 不太适合 | 原因 |
|---|---|
| 必须证明最优 | FA通常不能证明 |
| 复杂离散问题 | 需要重新设计移动方式 |
| 评价成本很高 | 需要大量方案比较 |

# 14. 与相近算法比较

| 对比项 | FA | PSO | ABC |
|---|---|---|---|
| 移动依据 | 向更亮方案移动 | 跟随自身和群体最好位置 | 在食物源附近搜索 |
| 个体互动 | 多个较好个体都可吸引 | 主要参考最好位置 | 按方案质量分配搜索 |
| 适合变量 | 连续变量为主 | 连续变量 | 连续变量为主 |
| 保证最优 | 不保证 | 不保证 | 不保证 |

# 15. 可以与其他算法融合的位置

```text
预测模型
  ↓ 评价参数效果
FA
  ↓ 找到较好参数
局部搜索
  ↓ 精细调整
最终方案
```

| 融合方式 | 位置 | 数据传递 | 作用 |
|---|---|---|---|
| FA + 局部搜索 | 最终精调 | FA输出较好参数 | 提高精度 |
| FA + DE | 方案移动 | DE提供差分方案 | 增强搜索能力 |
| FA + RL | 参数调整 | RL输出吸引力或随机参数 | 动态控制搜索 |
| FA + CP/MILP | 约束修复 | FA输出候选方案 | 处理复杂约束 |

# 16. 最小示例

## 原始问题

调整机器速度，使产品误差最小。

## 输入数据

```text
速度范围：1～10
```

## 变量

```text
机器速度
```

## 规则

```text
速度不能超出1～10
```

## 目标

```text
产品误差最小
```

## 执行过程

```text
候选速度：3、6、9
  ↓
速度6的误差最小，亮度最高
  ↓
速度3和9向速度6附近移动
  ↓
加入小幅随机变化
  ↓
继续评价
```

## 输出结果

```text
最好速度：约6.5
产品误差：当前最小值
```

# 17. 一句话总结

> 人负责定义参数、范围、约束和评价方法；FA负责让较差方案向较好方案移动并继续随机探索；最终输出找到的较优参数。
