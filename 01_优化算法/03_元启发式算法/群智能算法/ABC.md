# ABC（人工蜂群算法）

# 1. 一句话说明它是什么

> ABC 是一种让多组候选方案分工搜索、重点开发好方案并放弃长期无效方案的优化算法，主要用于寻找较优参数组合。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义需要决定的参数
  ├── 设置参数范围和约束
  └── 定义怎样评价方案
  ↓
ABC需要完成的工作
  ├── 生成多组方案
  ├── 在现有方案附近搜索
  ├── 重点搜索较好的区域
  └── 放弃长期没有改善的方案
  ↓
最终结果
  └── 找到的最好方案及其评价值
```

ABC不会自动发现变量、约束和目标；这些必须由人定义。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 待优化参数

什么情况绝对不允许？
→ 约束和参数边界

什么结果算更好？
→ 目标函数

哪些信息已经知道？
→ 输入数据和固定参数

哪些信息会发生变化？
→ 环境、需求和设备状态
```

| 关键词 | 对应内容 |
|---|---|
| 调整、设置、分配 | 决策变量 |
| 必须、不能、最多 | 约束 |
| 最小、最大、更快 | 目标 |
| 已知、给定 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 现实数据 | 机器速度、能耗 |
| 建模后的输入 | 参数范围、目标、约束 | 速度1～10 |
| 算法内部数据 | 食物源、评分、失败次数 | 多组候选参数 |
| 最终业务输出 | 最好方案和评分 | 最佳速度7.3 |

“食物源”就是一个候选方案。

# 7. 完整运行流程

```text
生成初始方案
  ↓
雇佣蜂：在每个方案附近搜索
  ↓
观察蜂：重点搜索较好的方案
  ↓
侦察蜂：替换长期没有改善的方案
  ↓
记录最好方案
  ↓
达到停止条件？
  ├── 否 → 继续
  └── 是 → 输出结果
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存问题、参数范围和约束。

### 输入

- 业务数据
- 参数边界
- 评价规则

### 内部构成

```text
Problem_Data
├── data
├── bounds
├── objective
└── constraints
```

### 处理过程

把现实问题整理成可评价的参数优化问题。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Initialization

### 作用

生成第一批候选方案。

### 输入

- 参数范围
- 食物源数量

### 内部构成

```text
Initialization
├── create_food_sources()
└── evaluate_sources()
```

### 处理过程

随机生成并评价多组方案。

### 输出

- 初始食物源集合

### 是否需要用户自己实现

算法库通常可以提供。

## 03_Employed_Bee

### 作用

在每个现有方案附近寻找更好的方案。

### 输入

- 当前食物源
- 其他食物源
- 参数范围

### 内部构成

```text
Employed_Bee
├── create_neighbor()
├── evaluate_neighbor()
└── greedy_select()
```

### 处理过程

生成邻近方案；更好就替换，否则保留原方案。

### 输出

- 更新后的食物源

### 是否需要用户自己实现

通常由算法库提供。

## 04_Onlooker_Bee

### 作用

把更多搜索机会分配给较好的方案。

### 输入

- 食物源
- 各方案评分

### 内部构成

```text
Onlooker_Bee
├── calculate_probability()
├── select_source()
├── create_neighbor()
└── greedy_select()
```

### 处理过程

按质量选择方案，再在附近搜索。

### 输出

- 更新后的食物源

### 是否需要用户自己实现

通常由算法库提供。

## 05_Scout_Bee

### 作用

替换长期没有改善的方案。

### 输入

- 食物源
- 失败次数
- 放弃阈值

### 内部构成

```text
Scout_Bee
├── detect_abandoned()
└── random_restart()
```

### 处理过程

发现停滞方案后，随机生成新方案替换。

### 输出

- 新食物源
- 清零后的失败次数

### 是否需要用户自己实现

通常由算法库提供。

## 06_Evaluation

### 作用

评价并检查候选方案。

### 输入

- 候选方案
- Problem

### 内部构成

```text
Evaluation
├── calculate_objective()
├── check_constraints()
└── calculate_fitness()
```

### 处理过程

计算目标值，检查约束并转换成评分。

### 输出

- 目标值
- 适应度
- 可行性结果

### 是否需要用户自己实现

目标和约束通常需要自己实现。

## 07_Main_Solver

### 作用

控制ABC完整运行。

### 输入

- Problem
- ABC配置

### 内部构成

```text
Main_Solver
├── initialize()
├── employed_phase()
├── onlooker_phase()
├── scout_phase()
├── update_best()
└── stop()
```

### 处理过程

重复执行雇佣蜂、观察蜂和侦察蜂阶段。

### 输出

- 最好方案
- 最好目标值
- 运行记录

### 是否需要用户自己实现

主框架通常由算法库提供。

# 12. 它真正帮我解决什么

| 问题 | ABC的作用 |
|---|---|
| 理解问题？ | 不能，人负责分析。 |
| 建立模型？ | 不能自动建立。 |
| 搜索答案？ | 是，这是主要作用。 |
| 预测结果？ | 不能，可与预测模型结合。 |
| 连续决策？ | 通常不是，环境变化后需重新运行。 |
| 验证可行性？ | 可执行人定义的约束检查。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 连续参数优化 | 可直接调整数值 |
| 黑箱问题 | 不需要导数 |
| 容易陷入局部区域 | 侦察蜂可以重新搜索 |

| 不太适合 | 原因 |
|---|---|
| 必须证明最优 | ABC通常不能证明 |
| 复杂离散问题 | 需要重新设计方案表示 |
| 评价成本很高 | 需要反复评价大量方案 |

# 14. 与相近算法比较

| 对比项 | ABC | PSO | DE |
|---|---|---|---|
| 新方案来源 | 邻近搜索和随机重启 | 跟随最好位置移动 | 利用方案差值 |
| 防止停滞 | 侦察蜂重启 | 依靠速度和随机性 | 依靠差分变异 |
| 适合变量 | 连续变量为主 | 连续变量 | 连续变量 |
| 保证最优 | 不保证 | 不保证 | 不保证 |

# 15. 可以与其他算法融合的位置

```text
贪心或启发式算法
  ↓ 生成初始方案
ABC
  ↓ 搜索较好方案
局部搜索
  ↓ 精细调整
最终方案
```

| 融合方式 | 位置 | 数据传递 | 作用 |
|---|---|---|---|
| ABC + 局部搜索 | 最终精调 | ABC输出较好方案 | 提高精度 |
| ABC + DE | 邻域生成 | DE输出差分方案 | 增强搜索能力 |
| ABC + RL | 参数控制 | RL输出搜索策略 | 动态调整搜索 |
| ABC + CP/MILP | 方案修复 | ABC输出候选方案 | 处理复杂约束 |

# 16. 最小示例

## 原始问题

调整机器速度，使产品误差最小。

## 输入数据

```text
速度范围：1～10
```

## 变量

```text
机器速度
```

## 规则

```text
速度不能超出1～10
```

## 目标

```text
产品误差最小
```

## 执行过程

```text
初始速度：3、6、9
  ↓
雇佣蜂在附近尝试
  ↓
观察蜂重点搜索评分较好的速度
  ↓
侦察蜂替换长期无改善的速度
```

## 输出结果

```text
最好速度：7.2
产品误差：当前最小值
```

# 17. 一句话总结

> 人负责定义参数、范围、约束和评价方法；ABC负责分工搜索并替换停滞方案；最终输出找到的较好方案。
