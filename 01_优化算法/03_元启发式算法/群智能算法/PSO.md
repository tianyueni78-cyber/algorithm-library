# PSO（粒子群优化算法）

# 1. 一句话说明它是什么

> PSO 是一种让多组候选参数同时参考“自己历史最好”和“群体最好”位置移动的优化算法，主要用于寻找较优的连续参数组合。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义需要调整的参数
  ├── 设置参数范围和约束
  └── 定义评价方法
  ↓
PSO需要完成的工作
  ├── 生成多组候选参数
  ├── 记录每个方案的历史最好位置
  ├── 记录全体最好位置
  └── 更新各方案的速度和位置
  ↓
最终结果
  └── 找到的最好参数及其评价值
```

PSO不会自动理解现实问题，也不会自动发现参数、目标和约束。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 需要调整的参数

什么情况绝对不允许？
→ 参数边界和约束

什么结果算更好？
→ 目标函数

哪些信息已经知道？
→ 业务数据和固定参数

哪些信息会发生变化？
→ 环境、需求和设备状态
```

| 关键词 | 对应内容 |
|---|---|
| 调整、设置、比例、系数 | 决策变量 |
| 不能、必须、上限、下限 | 约束 |
| 最小、最大、更快、更省 | 目标 |
| 已知、给定、测量 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 设备或实验数据 | 速度、温度、误差 |
| 建模后的输入 | 参数范围、目标、约束 | 速度1～10 |
| 算法内部数据 | 位置、速度、个体最好、群体最好 | 多组候选参数 |
| 最终业务输出 | 最好参数和目标值 | 最佳速度7.2 |

- 粒子位置：一组候选参数。
- 粒子速度：下一次参数调整的方向和幅度。
- 个体最好：该粒子自己找到过的最好参数。
- 群体最好：所有粒子找到过的最好参数。

# 7. 完整运行流程

```text
随机生成粒子位置和速度
  ↓
评价所有粒子
  ↓
更新每个粒子的个体最好
  ↓
更新群体最好
  ↓
更新粒子速度
  ↓
更新粒子位置
  ↓
处理边界和约束
  ↓
达到停止条件？
  ├── 否 → 继续
  └── 是 → 输出群体最好
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存参数、范围、目标和约束。

### 输入

- 业务数据
- 参数边界
- 评价规则

### 内部构成

```text
Problem_Data
├── data
├── bounds
├── objective
└── constraints
```

### 处理过程

把现实问题整理成参数优化问题。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Initialization

### 作用

生成初始粒子群。

### 输入

- 参数范围
- 粒子数量

### 内部构成

```text
Initialization
├── create_positions()
├── create_velocities()
└── create_particles()
```

### 处理过程

随机生成初始位置和速度。

### 输出

- 初始粒子群

### 是否需要用户自己实现

算法库通常可以提供。

## 03_Evaluation

### 作用

评价每个粒子的当前位置。

### 输入

- 粒子位置
- Problem

### 内部构成

```text
Evaluation
├── calculate_objective()
├── check_constraints()
└── calculate_fitness()
```

### 处理过程

计算目标值并检查约束。

### 输出

- 目标值
- 适应度
- 可行性结果

### 是否需要用户自己实现

目标和约束通常需要自己实现。

## 04_Best_Update

### 作用

更新个体最好和群体最好。

### 输入

- 当前粒子
- 历史最好记录

### 内部构成

```text
Best_Update
├── update_personal_best()
└── update_global_best()
```

### 处理过程

当前方案更好时，替换对应的历史记录。

### 输出

- 新个体最好
- 新群体最好

### 是否需要用户自己实现

通常由算法库提供。

## 05_Velocity_Position_Update

### 作用

计算粒子下一步如何移动。

### 输入

- 当前位置和速度
- 个体最好位置
- 群体最好位置
- PSO参数

### 内部构成

```text
Velocity_Position_Update
├── update_velocity()
├── limit_velocity()
└── update_position()
```

### 处理过程

综合原速度、个体经验和群体经验，得到新位置。

### 输出

- 新速度
- 新位置

### 是否需要用户自己实现

通常由算法库提供。

## 06_Constraint_Handling

### 作用

处理越界或违反规则的粒子。

### 输入

- 新位置
- 参数边界
- 业务约束

### 内部构成

```text
Constraint_Handling
├── check_bounds()
├── repair()
└── penalty()
```

### 处理过程

对非法参数进行截断、修复或扣分。

### 输出

- 合法位置
- 或带惩罚的评分

### 是否需要用户自己实现

边界可由库处理；复杂约束通常需要自己实现。

## 07_Main_Solver

### 作用

控制PSO完整运行。

### 输入

- Problem
- PSO配置

### 内部构成

```text
Main_Solver
├── initialize()
├── evaluate()
├── update_best()
├── update_velocity()
├── update_position()
└── stop()
```

### 处理过程

重复评价、更新最好记录、更新速度和位置。

### 输出

- 群体最好参数
- 最好目标值
- 运行记录

### 是否需要用户自己实现

主框架通常由算法库提供。

# 12. 它真正帮我解决什么

| 问题 | PSO的作用 |
|---|---|
| 理解问题？ | 不能，人负责分析。 |
| 建立模型？ | 不能自动建立。 |
| 搜索答案？ | 是，这是主要作用。 |
| 预测结果？ | 不能，可与预测模型结合。 |
| 连续决策？ | 通常不是，环境变化后需重新运行。 |
| 验证可行性？ | 可以执行人定义的约束检查。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 连续参数优化 | 可以直接移动参数 |
| 无法计算导数 | 只需评价方案 |
| 希望结构简单 | 核心只有速度和位置更新 |

| 不太适合 | 原因 |
|---|---|
| 必须证明最优 | PSO通常不能证明 |
| 路径和排序问题 | 需要重新设计粒子表示 |
| 评价成本很高 | 需要多轮评价粒子群 |

# 14. 与相近算法比较

| 对比项 | PSO | GWO | DE |
|---|---|---|---|
| 移动依据 | 自己最好＋群体最好 | 当前前三名 | 方案之间的差值 |
| 是否保存速度 | 是 | 否 | 否 |
| 适合变量 | 连续变量 | 连续变量为主 | 连续变量 |
| 保证最优 | 不保证 | 不保证 | 不保证 |

# 15. 可以与其他算法融合的位置

```text
预测模型
  ↓ 评价候选参数
PSO
  ↓ 找到较好参数
局部搜索
  ↓ 精细调整
最终方案
```

| 融合方式 | 位置 | 数据传递 | 作用 |
|---|---|---|---|
| PSO + 局部搜索 | 最终精调 | PSO输出群体最好 | 提高精度 |
| PSO + DE | 位置更新 | DE提供差分候选方案 | 增强多样性 |
| PSO + RL | 参数控制 | RL输出惯性或学习参数 | 动态调节搜索 |
| PSO + CP/MILP | 约束修复 | PSO输出候选参数 | 处理复杂约束 |

# 16. 最小示例

## 原始问题

调整机器速度，使产品误差最小。

## 输入数据

```text
速度范围：1～10
```

## 变量

```text
机器速度
```

## 规则

```text
速度不能超出1～10
```

## 目标

```text
产品误差最小
```

## 执行过程

```text
粒子位置：3、6、9
  ↓
粒子3自己历史最好：3
群体最好：6
  ↓
粒子3同时参考3和6更新速度
  ↓
向更好的区域移动
```

## 输出结果

```text
群体最好速度：约7.2
产品误差：当前最小值
```

# 17. 一句话总结

> 人负责定义参数、范围、约束和评价方法；PSO负责让粒子参考自己的历史最好和群体最好位置移动；最终输出找到的较优参数。

# 18. 理解检查
