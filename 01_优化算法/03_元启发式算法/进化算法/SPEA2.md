# SPEA2（强度帕累托进化算法2）

# 1. 一句话说明它是什么

> SPEA2 是一种同时优化多个互相冲突目标的进化算法，主要用于找出一组各有取舍的优秀方案。

例如：同时追求“成本低”和“速度快”，最终不会只返回一个答案，而会返回多个折中方案。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 定义需要决定什么
  ├── 定义多个评价目标
  ├── 定义约束和方案编码
  └── 设置种群大小、档案大小等参数
  ↓
SPEA2需要完成的工作
  ├── 生成并评价多个方案
  ├── 比较方案之间的支配关系
  ├── 保存优秀且分布均匀的方案
  └── 通过选择、交叉和变异继续搜索
  ↓
最终结果
  └── 一组互不明显优于对方的折中方案
```

人提供问题、目标、约束和编码；SPEA2负责搜索；最终由人从结果集中选择最符合实际需要的方案。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 决策变量或染色体

什么情况绝对不允许？
→ 约束和可行性规则

哪些结果都希望变好？
→ 多个目标函数

哪些信息已经知道？
→ 输入数据和固定参数

哪些信息会发生变化？
→ 动态任务、故障、价格或需求
```

| 自然语言关键词 | 对应内容 |
|---|---|
| 选择、顺序、分配、数量 | 决策变量 |
| 必须、不能、至少、最多 | 约束 |
| 更快、更省、更稳、更均衡 | 多个目标 |
| 已知、给定、现有 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 任务、资源、成本等数据 | 订单、车辆、距离 |
| 建模后的输入 | 编码、约束、多个目标 | 成本最小、时间最短 |
| 算法内部数据 | 种群、外部档案、适应度 | 当前方案和历史优秀方案 |
| 最终业务输出 | 一组折中方案 | 低成本方案、快速方案、平衡方案 |

# 7. 完整运行流程

```text
现实问题
  ↓
定义编码、约束和多个目标
  ↓
生成初始种群
  ↓
计算每个方案的多个目标值
  ↓
合并当前种群与外部档案
  ↓
计算支配强度、原始适应度和密度
  ↓
更新外部档案
  ↓
选择父代
  ↓
交叉和变异
  ↓
生成下一代
  ↓
达到停止条件？
  ├── 否 → 继续循环
  └── 是 → 输出外部档案
```

“外部档案”就是专门保存当前优秀折中方案的集合。

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存问题数据、多个目标和约束。

### 输入

- 原始业务数据
- 目标定义
- 业务规则

### 内部构成

```text
Problem_Data
├── input_data
├── objectives
└── constraints
```

### 处理过程

读取并整理现实数据。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Encoding

### 作用

在现实方案和染色体之间转换。

### 输入

- Problem
- 现实方案或染色体

### 内部构成

```text
Encoding
├── encode()
├── decode()
└── repair()
```

### 处理过程

编码、解码，并修复不合法方案。

### 输出

- 染色体
- 现实方案
- 修复后的方案

### 是否需要用户自己实现

通常需要自己实现。

## 03_Initialization

### 作用

生成第一批候选方案。

### 输入

- Problem
- 种群规模

### 内部构成

```text
Initialization
├── random_initialize()
└── heuristic_initialize()
```

### 处理过程

随机生成或利用业务规则生成初始方案。

### 输出

- 初始种群

### 是否需要用户自己实现

两者都可以。

## 04_Objective_Evaluation

### 作用

计算每个方案在多个目标上的表现。

### 输入

- 候选方案
- Problem

### 内部构成

```text
Objective_Evaluation
├── decode()
├── calculate_objectives()
└── check_constraints()
```

### 处理过程

还原方案，计算多个目标值并检查约束。

### 输出

- 目标值列表
- 可行性结果

### 是否需要用户自己实现

通常需要自己实现。

## 05_Fitness_Assignment

### 作用

根据方案之间的优劣关系和拥挤程度计算适应度。

### 输入

- 当前种群
- 外部档案
- 所有方案的目标值

### 内部构成

```text
Fitness_Assignment
├── calculate_strength()
├── calculate_raw_fitness()
├── calculate_density()
└── calculate_fitness()
```

### 处理过程

```text
计算每个方案支配多少其他方案
  ↓
计算它被哪些强方案支配
  ↓
检查它周围是否过于拥挤
  ↓
得到最终适应度
```

### 输出

- 每个方案的适应度
- 支配关系
- 密度值

### 是否需要用户自己实现

SPEA2算法库通常提供。

## 06_Archive_Update

### 作用

保存优秀方案，并控制方案数量和分布。

### 输入

- 合并后的种群
- 适应度
- 档案容量

### 内部构成

```text
Archive_Update
├── select_nondominated()
├── fill_archive()
└── truncate_archive()
```

### 处理过程

优先保留非支配方案；数量不足时补充较好方案；数量过多时删除过于拥挤的方案。

### 输出

- 更新后的外部档案

### 是否需要用户自己实现

SPEA2算法库通常提供。

## 07_Genetic_Operators

### 作用

根据档案中的优秀方案产生新方案。

### 输入

- 外部档案
- 交叉率
- 变异率

### 内部构成

```text
Genetic_Operators
├── tournament_selection()
├── crossover()
├── mutation()
└── repair()
```

### 处理过程

选择父代，进行交叉和变异，然后修复非法方案。

### 输出

- 下一代种群

### 是否需要用户自己实现

通用算子可由算法库提供；特殊编码需要自己实现。

## 08_Main_Solver

### 作用

控制SPEA2的完整运行。

### 输入

- Problem
- SPEA2配置

### 内部构成

```text
Main_Solver
├── initialize()
├── evaluate()
├── assign_fitness()
├── update_archive()
├── reproduce()
└── stop()
```

### 处理过程

反复执行评价、适应度计算、档案更新和新一代生成。

### 输出

- 最终外部档案
- 帕累托方案集
- 每个方案的目标值

### 是否需要用户自己实现

主框架可由算法库提供，问题相关部分需要用户实现。

# 12. 它真正帮我解决什么

| 问题 | SPEA2的作用 |
|---|---|
| 帮助理解问题？ | 不能，问题仍由人分析。 |
| 帮助建立模型？ | 不能自动建模，人必须定义变量、目标和约束。 |
| 帮助搜索答案？ | 是，主要作用是搜索多个折中方案。 |
| 帮助预测结果？ | 不能，但可以调用预测模型评价方案。 |
| 帮助连续决策？ | 原始SPEA2主要解决一次性优化，环境变化后通常需要重新运行。 |
| 帮助验证可行性？ | 可以执行人定义的检查规则，但不会自动发现规则。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 同时存在多个冲突目标 | 能保留多种折中方案 |
| 调度、路径和资源分配 | 方案组合数量大 |
| 不知道各目标权重 | 不必先把多个目标合成一个 |
| 希望方案分布均匀 | 密度机制可以减少方案扎堆 |

| 不太适合 | 原因 |
|---|---|
| 只有一个目标 | 普通GA更简单 |
| 必须证明全局最优 | SPEA2通常无法证明 |
| 目标评价特别耗时 | 每代需要评价大量方案 |
| 决策者只接受一个答案 | 最后仍需从结果集中选择 |

# 14. 与相近算法比较

| 对比项 | SPEA2 | NSGA-II | NSGA-III |
|---|---|---|---|
| 主要用途 | 多目标优化 | 多目标优化 | 目标数量较多的优化 |
| 优秀解保存 | 独立外部档案 | 父代与子代联合筛选 | 参考点引导筛选 |
| 分布控制 | 邻近距离密度 | 拥挤距离 | 参考点 |
| 最终输出 | 一组折中方案 | 一组折中方案 | 一组折中方案 |
| 保证可行 | 取决于约束处理 | 取决于约束处理 | 取决于约束处理 |
| 保证最优 | 不保证 | 不保证 | 不保证 |
| 更适合 | 两三个目标 | 两三个目标 | 三个以上目标 |

# 15. 可以与其他算法融合的位置

```text
贪心算法
  ↓ 生成较好的初始方案
SPEA2
  ↓ 输出多组折中方案
局部搜索
  ↓ 精细改进每个方案
最终方案集
```

| 融合方式 | 融合位置 | 数据传递 | 解决的问题 |
|---|---|---|---|
| SPEA2 + 贪心 | 初始化 | 贪心输出初始方案 | 提高初始种群质量 |
| SPEA2 + 局部搜索 | 子代优化 | SPEA2输出子代，局部搜索返回改进方案 | 提升方案精度 |
| SPEA2 + CP/MILP | 修复或优化 | SPEA2输出部分决策，求解器补全 | 处理复杂约束 |
| SPEA2 + RL | 参数或算子选择 | 状态输入RL，RL输出操作策略 | 动态调节搜索 |
| SPEA2 + 预测模型 | 目标评价 | 方案输入模型，模型输出预测值 | 减少真实计算成本 |

# 16. 最小示例

## 原始问题

选择一个运输方案，同时希望运输时间短、成本低。

## 输入数据

| 方案 | 时间 | 成本 |
|---|---:|---:|
| A | 2小时 | 100元 |
| B | 3小时 | 70元 |
| C | 4小时 | 90元 |
| D | 5小时 | 60元 |

## 变量

```text
选择哪个运输方案
```

## 规则

```text
只能选择一个方案
```

## 目标

```text
目标1：时间最短
目标2：成本最低
```

## SPEA2处理结果

- C比B更慢且更贵，因此被B淘汰。
- A最快，但成本较高。
- B在时间和成本之间较平衡。
- D最便宜，但速度最慢。

## 输出结果

```text
帕累托方案集
├── A：2小时，100元
├── B：3小时，70元
└── D：5小时，60元
```

SPEA2负责找出这三个折中方案，但不会替用户决定“时间”和“成本”哪个更重要。

# 17. 一句话总结

> 人负责定义方案、约束和多个评价目标；SPEA2负责搜索并保存分布较均匀的折中方案；最终输出一组帕累托方案供人选择。

# 18. 理解检查

如果方案A速度更快但价格更高，而方案B速度更慢但价格更低，SPEA2应该直接淘汰其中一个，还是可能同时保留它们？
