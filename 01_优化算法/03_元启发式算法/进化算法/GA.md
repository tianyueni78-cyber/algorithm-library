# GA（遗传算法）

# 1. 一句话说明它是什么

> GA 是一种同时尝试多组方案、不断保留和组合较好方案的搜索方法，主要用于寻找复杂问题中的较优解。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 决定方案如何表示
  ├── 定义必须遵守的规则
  └── 定义怎样评价方案好坏
  ↓
GA需要完成的工作
  ├── 生成一批方案
  ├── 选择较好的方案
  ├── 组合并修改方案
  └── 重复搜索
  ↓
最终结果
  └── 找到的最好方案及其评价值
```

GA不会自动理解现实问题。人提供问题数据、方案表示、评价方法和约束；GA负责搜索；最后返回较好的方案，但通常不保证是全局最优解。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 染色体：一个完整方案的代码表示

什么情况绝对不允许？
→ 约束：判断方案是否合法

什么结果算更好？
→ 适应度：方案的评分

哪些信息已经知道？
→ 任务、资源、成本、时间等输入数据

哪些信息会变化？
→ 新任务、故障、需求和资源状态
```

| 自然语言关键词 | 对应内容 |
|---|---|
| 选择、顺序、分配、数量 | 需要编码的决定 |
| 必须、不能、最多、至少 | 约束 |
| 最少、最快、最大、最均衡 | 适应度 |
| 已知、给定、拥有 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 现实中的已知数据 | 任务时间、机器数量 |
| 建模后的输入 | 编码、约束、评分规则 | `[2,1,3]` 表示任务顺序 |
| 算法内部数据 | 种群、适应度、代数 | 100个候选方案 |
| 最终业务输出 | 最好方案及评价值 | 最优任务顺序、完成时间 |

# 7. 完整运行流程

```text
现实问题
  ↓
设计方案编码
  ↓
生成初始种群
  ↓
计算每个方案的适应度
  ↓
选择较好的方案
  ↓
交叉组合
  ↓
随机变异
  ↓
修复非法方案
  ↓
形成下一代
  ↓
达到停止条件？
  ├── 否 → 继续进化
  └── 是 → 输出最好方案
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存现实问题的数据和规则。

### 输入

- 任务、资源、成本等数据
- 业务规则

### 内部构成

```text
Problem_Data
├── raw_data
├── constraints
└── parameters
```

### 处理过程

读取并检查数据，整理成算法可使用的形式。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Encoding

### 作用

把现实方案转换成GA可以修改的染色体。

### 输入

- Problem
- 现实方案

### 内部构成

```text
Encoding
├── encode()
└── decode()
```

### 处理过程

`encode()`把方案转成染色体；`decode()`把染色体还原成现实方案。

### 输出

- 染色体
- 现实方案

### 是否需要用户自己实现

通常需要自己实现。

## 03_Initialization

### 作用

生成第一批候选方案。

### 输入

- Problem
- 种群规模

### 内部构成

```text
Initialization
├── random_initialize()
└── heuristic_initialize()
```

### 处理过程

随机生成或使用规则生成多个方案。

### 输出

- 初始种群

### 是否需要用户自己实现

两者都可以。

## 04_Fitness

### 作用

评价每个方案好不好。

### 输入

- 染色体
- Problem

### 内部构成

```text
Fitness
├── decode()
├── calculate_objective()
└── calculate_penalty()
```

### 处理过程

还原方案，计算目标值，对违反规则的方案扣分。

### 输出

- 适应度
- 目标值

### 是否需要用户自己实现

通常需要自己实现。

## 05_Selection

### 作用

选择用于产生下一代的方案。

### 输入

- 种群
- 适应度

### 内部构成

```text
Selection
├── tournament_selection()
└── roulette_selection()
```

### 处理过程

让评分较好的方案获得更高的入选概率。

### 输出

- 父代方案

### 是否需要用户自己实现

算法库通常提供，也可以自己实现。

## 06_Crossover

### 作用

把两个父代方案组合成新方案。

### 输入

- 两个父代
- 交叉概率

### 内部构成

```text
Crossover
├── select_positions()
└── combine_parents()
```

### 处理过程

选择交叉位置，交换或重组部分内容。

### 输出

- 子代方案

### 是否需要用户自己实现

通用编码可使用算法库；特殊编码通常需要自己实现。

## 07_Mutation

### 作用

随机修改方案，增加搜索范围。

### 输入

- 子代方案
- 变异概率

### 内部构成

```text
Mutation
├── select_gene()
└── modify_gene()
```

### 处理过程

随机选择部分内容并进行替换、交换或调整。

### 输出

- 变异后的方案

### 是否需要用户自己实现

取决于编码方式。

## 08_Constraint_Handling

### 作用

处理违反现实规则的方案。

### 输入

- 候选方案
- 约束

### 内部构成

```text
Constraint_Handling
├── check_feasibility()
├── repair()
└── penalty()
```

### 处理过程

检查方案；可以修复，也可以通过扣分降低其入选机会。

### 输出

- 合法方案
- 或带惩罚的适应度

### 是否需要用户自己实现

通常需要自己实现。

## 09_Main_Solver

### 作用

控制GA的完整运行过程。

### 输入

- Problem
- GA配置

### 内部构成

```text
Main_Solver
├── initialize()
├── evaluate()
├── select()
├── crossover()
├── mutate()
├── repair()
├── replace()
└── stop()
```

### 处理过程

按代重复评价、选择、交叉、变异和更新种群。

### 输出

- 最好方案
- 最好目标值
- 运行记录

### 是否需要用户自己实现

框架可由算法库提供，问题相关部分需要用户实现。

# 11. 用户需要实现什么

## 通常需要自己实现

- 问题数据读取
- 染色体编码和解码
- 适应度计算
- 约束检查与修复
- 结果转换

## 通常由算法库提供

- 种群管理
- 常见选择算子
- 常见交叉算子
- 常见变异算子
- 迭代控制

特殊编码下，交叉和变异也需要自己设计。

# 12. 它真正帮我解决什么

| 问题 | GA的作用 |
|---|---|
| 帮助理解问题？ | 不能。现实问题仍要由人分析。 |
| 帮助建立模型？ | 不能自动建立，但要求人明确方案、规则和评分。 |
| 帮助搜索答案？ | 是，这是它的主要作用。 |
| 帮助预测结果？ | 不能，除非与预测模型结合。 |
| 帮助连续决策？ | 原始GA通常解决一次性搜索，动态决策需反复运行或与RL融合。 |
| 帮助验证可行性？ | 可以调用人定义的检查规则，但不会自动发现这些规则。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 调度、路径、分配 | 方案组合很多 |
| 目标难以直接求解 | 只要能够计算方案评分即可 |
| 多目标问题 | 可以同时维护多种不同方案 |
| 允许近似解 | 能在有限时间找到较好方案 |

| 不太适合 | 原因 |
|---|---|
| 必须证明最优 | GA通常不能证明全局最优 |
| 评价一次非常耗时 | GA需要反复评价大量方案 |
| 小型简单问题 | 精确算法可能更快 |
| 无法评价方案好坏 | GA无法决定选择方向 |

# 14. 与相近算法比较

| 对比项 | GA | SA | 局部搜索 |
|---|---|---|---|
| 同时保留方案数 | 多个 | 一个 | 一个 |
| 搜索方式 | 选择、交叉、变异 | 按概率接受新方案 | 不断接受附近的较好方案 |
| 跳出局部最优 | 依靠种群和变异 | 依靠接受较差方案 | 较弱 |
| 是否保证可行 | 取决于编码和修复 | 取决于邻域设计 | 取决于邻域设计 |
| 是否保证最优 | 通常不保证 | 通常不保证 | 通常不保证 |
| 适合问题 | 大范围组合搜索 | 单方案随机搜索 | 快速改进已有方案 |

# 15. 可以与其他算法融合的位置

```text
贪心算法
  ↓ 生成质量较高的初始种群
GA
  ↓ 输出较好的候选方案
局部搜索
  ↓ 进一步精细调整
最终方案
```

| 融合方式 | 融合位置 | 数据传递 | 解决的问题 |
|---|---|---|---|
| GA + 贪心 | 初始化 | 贪心输出初始方案 | 提高起点质量 |
| GA + 局部搜索 | 子代优化 | GA输出子代，局部搜索返回改进方案 | 提高局部搜索精度 |
| GA + CP/MILP | 修复或精确优化 | GA输出部分决策，求解器补全 | 保证复杂约束 |
| GA + RL | 算子选择 | 状态输入RL，RL输出算子或参数 | 动态调整搜索策略 |
| GA + 预测模型 | 适应度评价 | GA输出方案，模型预测方案效果 | 降低真实评价成本 |

# 16. 最小示例

## 原始问题

从三个任务中选择任务，总时间不能超过5小时，希望收益最大。

## 输入数据

| 任务 | 时间 | 收益 |
|---|---:|---:|
| A | 2 | 6 |
| B | 3 | 8 |
| C | 4 | 9 |

## 变量

染色体使用三个0或1：

```text
[是否选A, 是否选B, 是否选C]
```

## 规则

```text
总时间 ≤ 5
```

## 目标

```text
总收益尽量大
```

## 执行过程

```text
初始种群
├── [1,0,0] → 收益6
├── [0,1,0] → 收益8
├── [0,0,1] → 收益9
└── [1,1,0] → 收益14

选择较好方案
  ↓
交叉和变异
  ↓
继续评价
```

## 输出结果

```text
染色体：[1,1,0]
选择任务：A、B
总时间：5小时
总收益：14
是否可行：是
```

# 17. 一句话总结

> 人负责定义方案如何表示、哪些规则必须满足以及怎样评价好坏；GA负责不断生成、组合和筛选方案；最终输出搜索到的较好方案及其评价值。
