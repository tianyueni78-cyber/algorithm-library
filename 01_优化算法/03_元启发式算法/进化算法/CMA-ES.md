# CMA-ES（协方差矩阵自适应进化策略）

# 1. 一句话说明它是什么

> CMA-ES 是一种会自动学习“下一轮往哪里搜索、搜索范围多大”的优化方法，主要用于寻找复杂连续参数的较优组合。

它常用于调整一组可以取小数的参数，例如控制器参数、模型参数和工程设计参数。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 确定需要调整哪些参数
  ├── 设置参数初始值和允许范围
  ├── 定义怎样评价方案好坏
  └── 定义必须满足的约束
  ↓
CMA-ES需要完成的工作
  ├── 在当前搜索区域生成一批参数
  ├── 评价并排列这些参数
  ├── 根据优秀方案调整搜索中心
  ├── 学习参数之间的联动方向
  └── 自动扩大或缩小搜索范围
  ↓
最终结果
  └── 找到的较优参数及其评价值
```

人提供问题和评价规则；CMA-ES负责搜索，但不会自动理解现实业务，也通常不能证明结果是全局最优。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 需要调整的连续参数

什么情况绝对不允许？
→ 参数边界和约束

什么结果算更好？
→ 目标函数或评价指标

哪些信息已经知道？
→ 数据、初始参数、参数范围

哪些信息会发生变化？
→ 环境、需求和设备状态
```

| 自然语言关键词 | 对应内容 |
|---|---|
| 调整、设置、比例、系数 | 决策参数 |
| 上限、下限、不能、必须 | 边界或约束 |
| 最小、最大、更快、更稳 | 目标 |
| 初始、给定、已知 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 设备、实验或仿真数据 | 控制误差、能耗 |
| 建模后的输入 | 参数、初始值、目标和约束 | 两个控制器参数 |
| 算法内部数据 | 搜索中心、步长、协方差矩阵 | 当前搜索位置和方向 |
| 最终业务输出 | 最好参数及其效果 | 参数A=2.4、参数B=0.7 |

“协方差矩阵”可以直观理解为：记录哪些参数应该一起变化，以及更值得往哪个方向搜索。

# 7. 完整运行流程

```text
现实问题
  ↓
定义参数、初始值和评价方法
  ↓
设置初始搜索中心和搜索范围
  ↓
随机生成一批候选参数
  ↓
评价并排序
  ↓
用优秀方案更新搜索中心
  ↓
学习参数之间的联动方向
  ↓
调整搜索范围
  ↓
达到停止条件？
  ├── 否 → 继续生成新方案
  └── 是 → 输出最好参数
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存参数、范围、目标和约束。

### 输入

- 原始业务数据
- 参数初始值
- 参数边界
- 评价规则

### 内部构成

```text
Problem_Data
├── initial_parameters
├── bounds
├── objective
└── constraints
```

### 处理过程

把现实问题整理成连续参数优化问题。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Strategy_State

### 作用

保存CMA-ES当前学到的搜索状态。

### 输入

- 初始参数
- 初始搜索范围
- 参数数量

### 内部构成

```text
Strategy_State
├── mean
├── step_size
├── covariance_matrix
└── evolution_paths
```

- `mean`：当前搜索中心。
- `step_size`：整体搜索范围。
- `covariance_matrix`：参数的联动关系和重点搜索方向。
- `evolution_paths`：记录最近几轮搜索移动趋势。

### 处理过程

建立算法初始搜索状态。

### 输出

- StrategyState

### 是否需要用户自己实现

通常由CMA-ES算法库提供。

## 03_Candidate_Sampling

### 作用

根据当前搜索状态生成候选参数。

### 输入

- 搜索中心
- 搜索范围
- 协方差矩阵
- 种群规模

### 内部构成

```text
Candidate_Sampling
├── sample_random_vectors()
├── transform_directions()
└── create_candidates()
```

### 处理过程

围绕当前中心，按照学到的重点方向生成一批方案。

### 输出

- 候选参数集合

### 是否需要用户自己实现

通常由算法库提供。

## 04_Objective_Evaluation

### 作用

评价每组参数的效果。

### 输入

- 候选参数
- Problem

### 内部构成

```text
Objective_Evaluation
├── run_model()
├── calculate_objective()
├── check_constraints()
└── rank_candidates()
```

### 处理过程

运行实验、模型或仿真，计算目标值并排列候选方案。

### 输出

- 每个方案的目标值
- 排序结果
- 可行性结果

### 是否需要用户自己实现

评价规则通常需要自己实现；排序由算法库提供。

## 05_Strategy_Update

### 作用

根据优秀方案更新下一轮搜索方式。

### 输入

- 优秀候选方案
- 当前搜索状态

### 内部构成

```text
Strategy_Update
├── update_mean()
├── update_evolution_paths()
├── update_covariance()
└── update_step_size()
```

### 处理过程

```text
优秀方案
  ↓
移动搜索中心
  ↓
学习参数联动方向
  ↓
调整搜索范围
```

### 输出

- 新搜索中心
- 新搜索范围
- 新协方差矩阵

### 是否需要用户自己实现

通常由算法库提供。

## 06_Constraint_Handling

### 作用

处理超出范围或违反规则的参数。

### 输入

- 候选参数
- 参数边界
- 业务约束

### 内部构成

```text
Constraint_Handling
├── check_bounds()
├── repair_or_resample()
└── calculate_penalty()
```

### 处理过程

对非法参数进行截断、重新生成、修复或扣分。

### 输出

- 合法候选方案
- 或带惩罚的目标值

### 是否需要用户自己实现

边界处理可由库提供；复杂业务约束通常需要自己实现。

## 07_Main_Solver

### 作用

控制CMA-ES完整运行。

### 输入

- Problem
- CMA-ES配置

### 内部构成

```text
Main_Solver
├── initialize_state()
├── sample_candidates()
├── evaluate()
├── rank()
├── update_strategy()
└── stop()
```

### 处理过程

重复生成、评价、排序和更新搜索状态。

### 输出

- 最好参数
- 最好目标值
- 最终搜索状态

### 是否需要用户自己实现

主循环通常由算法库提供。

# 12. 它真正帮我解决什么

| 问题 | CMA-ES的作用 |
|---|---|
| 帮助理解问题？ | 不能，现实问题仍由人分析。 |
| 帮助建立模型？ | 不能自动建模，人必须定义参数、目标和约束。 |
| 帮助搜索答案？ | 是，主要负责搜索连续参数。 |
| 帮助预测结果？ | 不能，但可以调用预测模型评价参数。 |
| 帮助连续决策？ | 通常解决一次参数优化，环境变化后需要重新运行。 |
| 帮助验证可行性？ | 可以执行人定义的检查规则，但不会自动发现规则。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 连续参数优化 | 直接搜索实数参数 |
| 参数之间互相影响 | 能学习参数联动方向 |
| 目标函数不规则 | 不需要导数 |
| 仿真和黑箱优化 | 只需要能够评价方案 |

“黑箱优化”就是不知道内部公式，但输入参数后能够得到评分。

| 不太适合 | 原因 |
|---|---|
| 排序、路径等离散问题 | 原始CMA-ES主要处理连续变量 |
| 参数特别多 | 协方差矩阵计算和存储成本较高 |
| 单次评价非常昂贵 | 每轮需要评价多个方案 |
| 必须证明最优 | 通常无法证明全局最优 |

# 14. 与相近算法比较

| 对比项 | CMA-ES | DE | PSO |
|---|---|---|---|
| 主要变量 | 连续参数 | 连续参数 | 连续参数 |
| 新方案来源 | 学习搜索分布 | 利用方案差值 | 根据最好位置移动 |
| 参数联动学习 | 强 | 间接利用 | 较弱 |
| 是否需要导数 | 不需要 | 不需要 | 不需要 |
| 是否保证最优 | 不保证 | 不保证 | 不保证 |
| 更适合 | 参数相关性强的问题 | 通用连续优化 | 较直观的连续优化 |

# 15. 可以与其他算法融合的位置

```text
预测模型
  ↓ 快速评价参数效果
CMA-ES
  ↓ 输出较优连续参数
精确算法或局部搜索
  ↓ 完成离散决策或精细调整
最终方案
```

| 融合方式 | 融合位置 | 数据传递 | 解决的问题 |
|---|---|---|---|
| CMA-ES + 预测模型 | 目标评价 | 参数输入模型，模型输出预测效果 | 降低评价成本 |
| CMA-ES + 局部搜索 | 最终精调 | CMA-ES输出参数 | 提高局部精度 |
| CMA-ES + RL | 策略参数优化 | CMA-ES输出策略参数 | 自动调整RL超参数 |
| CMA-ES + CP/MILP | 混合决策 | CMA-ES处理连续参数，求解器处理离散变量 | 处理混合问题 |
| CMA-ES + 多目标算法 | 目标筛选 | CMA-ES优化局部连续参数 | 兼顾多个目标 |

# 16. 最小示例

## 原始问题

调整机器的速度和温度，希望产品误差最小。

## 输入数据

```text
速度范围：1～10
温度范围：20～100℃
初始参数：速度5、温度60℃
```

## 决策变量

```text
方案 = [速度, 温度]
```

## 规则

```text
速度和温度不能超过允许范围
```

## 目标

```text
产品误差越小越好
```

## 算法执行过程

```text
第一轮围绕 [5, 60] 生成多个方案
  ↓
发现优秀方案大多在“速度提高、温度降低”的方向
  ↓
移动搜索中心
  ↓
把搜索方向调整为“速度和温度联动变化”
  ↓
逐渐缩小搜索范围
```

## 输出结果

```text
最好速度：7.2
最好温度：51.5℃
产品误差：当前搜索中的最小值
```

# 17. 一句话总结

> 人负责定义参数、初始位置、约束和评价方法；CMA-ES负责学习搜索方向和搜索范围；最终输出找到的较优连续参数及其评价值。
