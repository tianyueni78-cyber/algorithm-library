# DE（差分进化算法）

# 1. 一句话说明它是什么

> DE 是一种利用候选方案之间的差异来产生新方案的搜索算法，主要用于寻找连续参数的较优组合。

例如调整：

```text
温度 = ？
速度 = ？
压力 = ？
```

DE特别适合这种“参数可以取小数”的优化问题。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 确定需要调整哪些参数
  ├── 设置每个参数的范围
  ├── 定义方案评价方法
  └── 定义必须遵守的约束
  ↓
DE需要完成的工作
  ├── 随机生成多组参数
  ├── 利用方案之间的差值产生新方案
  ├── 比较新旧方案
  └── 不断保留更好的方案
  ↓
最终结果
  └── 找到的一组较优参数及其评价值
```

人提供参数、范围、目标和约束；DE负责搜索；最终返回找到的较好参数，但通常不保证全局最优。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 决策变量，也就是需要调整的参数

什么情况绝对不允许？
→ 约束和参数边界

什么结果算更好？
→ 目标函数或评价指标

哪些信息已经知道？
→ 输入数据和固定参数

哪些信息会发生变化？
→ 环境、需求、设备状态
```

| 自然语言关键词 | 对应内容 |
|---|---|
| 调整、设置、控制、比例 | 决策变量 |
| 范围、上限、下限、不能 | 边界或约束 |
| 最小、最大、更快、更省 | 目标 |
| 已知、给定、测量得到 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 设备和生产数据 | 温度、产量、能耗 |
| 建模后的输入 | 参数范围、目标、约束 | 温度20～100℃ |
| 算法内部数据 | 种群、变异向量、试验方案 | 多组参数组合 |
| 最终业务输出 | 最好参数和目标值 | 温度65℃、速度8.2 |

# 7. 完整运行流程

```text
现实问题
  ↓
确定参数、范围和评价方法
  ↓
随机生成初始种群
  ↓
评价每个方案
  ↓
选择三个不同方案
  ↓
利用方案差值进行变异
  ↓
与原方案交叉
  ↓
处理越界或非法参数
  ↓
比较新方案和原方案
  ↓
保留更好的方案
  ↓
达到停止条件？
  ├── 否 → 继续循环
  └── 是 → 输出最好方案
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存参数范围、目标和约束。

### 输入

- 原始业务数据
- 参数上下限
- 评价规则

### 内部构成

```text
Problem_Data
├── input_data
├── lower_bounds
├── upper_bounds
├── objective
└── constraints
```

### 处理过程

把现实数据整理成DE可以使用的形式。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Initialization

### 作用

生成第一批参数组合。

### 输入

- 参数上下限
- 种群大小

### 内部构成

```text
Initialization
├── random_initialize()
└── evaluate_population()
```

### 处理过程

在每个参数的允许范围内随机生成多个方案。

### 输出

- 初始种群
- 初始目标值

### 是否需要用户自己实现

算法库通常可以提供。

## 03_Objective_Evaluation

### 作用

评价每组参数的效果。

### 输入

- 候选方案
- Problem

### 内部构成

```text
Objective_Evaluation
├── calculate_objective()
├── check_constraints()
└── calculate_penalty()
```

### 处理过程

计算方案目标值，并处理违反约束的方案。

### 输出

- 目标值
- 可行性结果

### 是否需要用户自己实现

通常需要自己实现。

## 04_Mutation

### 作用

利用方案之间的差值产生新参数。

### 输入

- 当前种群
- 缩放因子 `F`

### 内部构成

```text
Mutation
├── select_vectors()
├── calculate_difference()
└── create_mutant()
```

### 处理过程

```text
选择基础方案
  ↓
选择另外两个方案
  ↓
计算两者差值
  ↓
把差值的一部分加到基础方案
```

### 输出

- 变异方案

### 是否需要用户自己实现

算法库通常提供。

## 05_Crossover

### 作用

把原方案和变异方案进行组合。

### 输入

- 原方案
- 变异方案
- 交叉概率 `CR`

### 内部构成

```text
Crossover
├── choose_dimensions()
└── create_trial_vector()
```

### 处理过程

从原方案和变异方案中分别选择部分参数，组成试验方案。

### 输出

- 试验方案

### 是否需要用户自己实现

算法库通常提供。

## 06_Boundary_Handling

### 作用

处理超过范围或违反规则的参数。

### 输入

- 试验方案
- 参数上下限
- 约束

### 内部构成

```text
Boundary_Handling
├── check_bounds()
├── clip_or_resample()
└── repair_constraints()
```

### 处理过程

检查参数，进行截断、重新生成或修复。

### 输出

- 合法试验方案

### 是否需要用户自己实现

边界处理可由库提供；业务约束修复通常需要自己实现。

## 07_Selection

### 作用

比较新方案和原方案。

### 输入

- 原方案及其目标值
- 试验方案及其目标值

### 内部构成

```text
Selection
├── compare()
└── keep_better()
```

### 处理过程

新方案更好就替换原方案，否则保留原方案。

### 输出

- 下一代方案

### 是否需要用户自己实现

算法库通常提供。

## 08_Main_Solver

### 作用

控制DE完整运行。

### 输入

- Problem
- DE配置

### 内部构成

```text
Main_Solver
├── initialize()
├── evaluate()
├── mutate()
├── crossover()
├── repair()
├── select()
└── stop()
```

### 处理过程

按代重复变异、交叉、评价和选择。

### 输出

- 最好参数
- 最好目标值
- 运行记录

### 是否需要用户自己实现

主框架可由算法库提供，问题评价部分需要用户实现。

# 12. 它真正帮我解决什么

| 问题 | DE的作用 |
|---|---|
| 帮助理解问题？ | 不能，问题仍由人分析。 |
| 帮助建立模型？ | 不能自动建模，人必须定义参数和评价方法。 |
| 帮助搜索答案？ | 是，主要负责搜索较优参数组合。 |
| 帮助预测结果？ | 不能，但可以使用预测模型评价参数。 |
| 帮助连续决策？ | 原始DE通常解决一次优化；环境变化后需要重新运行。 |
| 帮助验证可行性？ | 可以执行人定义的检查规则。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 连续参数优化 | DE直接调整实数参数 |
| 目标函数复杂 | 不需要计算导数 |
| 参数之间关系不清楚 | 可以通过反复试验搜索 |
| 仿真参数校准 | 只需能够评价参数效果 |

| 不太适合 | 原因 |
|---|---|
| 排序和组合问题 | 原始DE主要处理连续变量 |
| 每次评价非常耗时 | 需要评价大量方案 |
| 必须证明最优 | DE通常不能证明 |
| 参数范围无法确定 | 难以生成合理方案 |

# 14. 与相近算法比较

| 对比项 | DE | GA | PSO |
|---|---|---|---|
| 主要变量 | 连续数值 | 连续或离散编码 | 连续数值 |
| 产生新方案 | 利用方案差值 | 交叉和变异 | 根据自身与群体最好位置移动 |
| 是否需要导数 | 不需要 | 不需要 | 不需要 |
| 是否保证可行 | 取决于边界与约束处理 | 取决于编码和修复 | 取决于边界处理 |
| 是否保证最优 | 不保证 | 不保证 | 不保证 |
| 更适合 | 连续参数优化 | 组合和编码问题 | 连续参数快速搜索 |

# 15. 可以与其他算法融合的位置

```text
预测模型
  ↓ 快速预测参数效果
DE
  ↓ 输出较优参数
局部搜索
  ↓ 进行精细调整
最终参数
```

| 融合方式 | 融合位置 | 数据传递 | 解决的问题 |
|---|---|---|---|
| DE + 局部搜索 | 最终精调 | DE输出参数，局部搜索继续改进 | 提高精度 |
| DE + 预测模型 | 目标评价 | 参数输入模型，模型输出预测效果 | 降低评价成本 |
| DE + RL | 参数控制 | RL输出 `F` 或 `CR` | 动态调整搜索范围 |
| DE + CP/MILP | 约束处理 | DE输出连续参数，求解器补全离散决策 | 处理混合变量 |
| DE + GA | 搜索操作 | 两种算法交换候选方案 | 同时处理不同变量 |

# 16. 最小示例

## 原始问题

调整机器速度，希望产量接近100，同时速度不能超过10。

## 输入数据

```text
速度范围：0～10
目标产量：100
产量 = 速度 × 12
```

## 决策变量

```text
机器速度
```

## 约束

```text
0 ≤ 速度 ≤ 10
```

## 目标

```text
实际产量与100的差距最小
```

## 算法执行过程

```text
当前三个方案
├── A：速度4
├── B：速度9
└── C：速度6

利用B与C的差值
  ↓
产生新的速度方案
  ↓
与原方案组合
  ↓
评价新方案
  ↓
保留更接近目标产量的方案
```

## 输出结果

```text
最好速度：约8.33
预计产量：约100
目标差距：接近0
```

# 17. 一句话总结

> 人负责定义参数、范围、约束和评价方法；DE负责利用候选方案之间的差值搜索更好的参数；最终输出找到的较优参数及其目标值。
