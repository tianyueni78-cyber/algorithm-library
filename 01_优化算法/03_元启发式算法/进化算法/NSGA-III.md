# NSGA-III（第三代非支配排序遗传算法）

# 1. 一句话说明它是什么

> NSGA-III 是一种同时优化多个冲突目标的进化算法，主要用于寻找分布较均匀的多种折中方案。

它特别适合目标较多的问题，例如同时优化：

```text
时间
成本
能耗
质量
风险
```

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 确定需要做哪些决定
  ├── 定义多个优化目标
  ├── 定义约束和方案编码
  └── 设置或生成参考方向
  ↓
NSGA-III需要完成的工作
  ├── 生成和评价大量候选方案
  ├── 按方案优劣关系进行分层
  ├── 将方案分配到不同参考方向
  ├── 保留不同方向上的代表方案
  └── 通过交叉和变异继续搜索
  ↓
最终结果
  └── 一组分布较均匀的折中方案
```

参考方向可以理解为：预先在目标空间中安排多个“位置”，引导算法在不同取舍方向上寻找方案。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 决策变量或染色体

什么情况绝对不允许？
→ 约束和可行性规则

哪些结果都希望变好？
→ 多个目标函数

哪些信息已经知道？
→ 输入数据和固定参数

哪些信息会发生变化？
→ 新任务、故障、价格和需求
```

| 自然语言关键词 | 对应内容 |
|---|---|
| 选择、安排、分配、数量 | 决策变量 |
| 必须、不能、最多、至少 | 约束 |
| 更快、更省、更稳、更环保 | 多个目标 |
| 已知、给定、现有 | 输入数据 |

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 任务、资源和成本数据 | 订单、机器、能耗 |
| 建模后的输入 | 编码、约束、多个目标 | 时间、成本、能耗最小 |
| 算法内部数据 | 种群、等级、参考方向 | 不同取舍方向上的方案 |
| 最终业务输出 | 一组折中方案 | 快速、便宜、节能、平衡方案 |

# 7. 完整运行流程

```text
现实问题
  ↓
定义编码、约束和多个目标
  ↓
生成参考方向
  ↓
生成初始种群
  ↓
计算每个方案的多个目标值
  ↓
父代与子代合并
  ↓
非支配排序
  ↓
完整保留前面的优秀层
  ↓
标准化最后一层的目标值
  ↓
把方案关联到参考方向
  ↓
从不同参考方向选择代表方案
  ↓
生成下一代
  ↓
达到停止条件？
  ├── 否 → 继续循环
  └── 是 → 输出折中方案集
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

保存问题数据、多个目标和约束。

### 输入

- 原始业务数据
- 优化目标
- 业务规则

### 内部构成

```text
Problem_Data
├── input_data
├── objectives
└── constraints
```

### 处理过程

整理现实数据并检查完整性。

### 输出

- Problem对象

### 是否需要用户自己实现

通常需要自己实现。

## 02_Encoding

### 作用

在现实方案与染色体之间转换。

### 输入

- Problem
- 现实方案或染色体

### 内部构成

```text
Encoding
├── encode()
├── decode()
└── repair()
```

### 处理过程

编码、解码并修复非法方案。

### 输出

- 染色体
- 现实方案

### 是否需要用户自己实现

通常需要自己实现。

## 03_Initialization

### 作用

生成第一批候选方案。

### 输入

- Problem
- 种群规模

### 内部构成

```text
Initialization
├── random_initialize()
└── heuristic_initialize()
```

### 处理过程

随机生成或利用业务规则生成方案。

### 输出

- 初始种群

### 是否需要用户自己实现

两者都可以。

## 04_Objective_Evaluation

### 作用

计算每个方案的多个目标值。

### 输入

- 候选方案
- Problem

### 内部构成

```text
Objective_Evaluation
├── decode()
├── calculate_objectives()
└── check_constraints()
```

### 处理过程

还原方案，计算各项目标并检查约束。

### 输出

- 多个目标值
- 可行性结果

### 是否需要用户自己实现

通常需要自己实现。

## 05_Nondominated_Sorting

### 作用

根据方案之间的整体优劣关系进行分层。

### 输入

- 种群
- 多个目标值

### 内部构成

```text
Nondominated_Sorting
├── compare_dominance()
├── find_fronts()
└── assign_rank()
```

### 处理过程

未被其他方案全面超过的进入第一层，其余方案依次进入后续层。

### 输出

- 非支配层
- 每个方案的等级

### 是否需要用户自己实现

算法库通常提供。

## 06_Reference_Directions

### 作用

建立不同目标取舍的搜索方向。

### 输入

- 目标数量
- 参考方向划分数量

### 内部构成

```text
Reference_Directions
├── generate_directions()
├── normalize_objectives()
└── associate_solutions()
```

### 处理过程

生成参考方向，统一目标尺度，然后把每个方案分配给最接近的方向。

### 输出

- 参考方向集合
- 方案与参考方向的对应关系

### 是否需要用户自己实现

通常由NSGA-III算法库提供。

## 07_Environmental_Selection

### 作用

从不同参考方向选择下一代方案。

### 输入

- 非支配层
- 参考方向
- 种群大小

### 内部构成

```text
Environmental_Selection
├── fill_complete_fronts()
├── count_direction_members()
├── select_from_last_front()
└── build_next_population()
```

### 处理过程

先保留完整优秀层；最后空间不足时，优先从方案较少的参考方向补充代表方案。

### 输出

- 下一代种群

### 是否需要用户自己实现

通常由算法库提供。

## 08_Genetic_Operators

### 作用

产生新的候选方案。

### 输入

- 当前种群
- 交叉率
- 变异率

### 内部构成

```text
Genetic_Operators
├── select_parents()
├── crossover()
├── mutation()
└── repair()
```

### 处理过程

选择父代，进行交叉、变异和约束修复。

### 输出

- 子代种群

### 是否需要用户自己实现

通用算子由算法库提供；特殊编码通常需要自己实现。

## 09_Main_Solver

### 作用

控制NSGA-III完整运行。

### 输入

- Problem
- NSGA-III配置

### 内部构成

```text
Main_Solver
├── initialize()
├── evaluate()
├── sort()
├── associate()
├── select()
├── reproduce()
└── stop()
```

### 处理过程

反复执行评价、排序、参考方向关联、选择和繁殖。

### 输出

- 折中方案集
- 每个方案的目标值
- 参考方向对应关系

### 是否需要用户自己实现

主框架通常由算法库提供。

# 12. 它真正帮我解决什么

| 问题 | NSGA-III的作用 |
|---|---|
| 帮助理解问题？ | 不能，现实问题仍由人分析。 |
| 帮助建立模型？ | 不能自动建模，人必须定义变量、目标和约束。 |
| 帮助搜索答案？ | 是，主要负责搜索多种折中方案。 |
| 帮助预测结果？ | 不能，但可以调用预测模型评价方案。 |
| 帮助连续决策？ | 通常解决一次性优化，环境变化后需要重新运行。 |
| 帮助验证可行性？ | 可以执行人定义的规则，但不会自动发现规则。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 三个以上目标 | 参考方向能帮助维持方案分布 |
| 调度、路径、工程设计 | 经常存在多个冲突目标 |
| 希望获得多类折中方案 | 能覆盖不同取舍方向 |
| 各目标量纲不同 | 会先对目标值进行标准化 |

| 不太适合 | 原因 |
|---|---|
| 只有一个目标 | 普通GA更简单 |
| 只有两个目标 | NSGA-II通常已经够用 |
| 必须证明最优 | NSGA-III通常不能证明 |
| 评价一次特别昂贵 | 需要评价大量方案 |

# 14. 与相近算法比较

| 对比项 | NSGA-III | NSGA-II | SPEA2 |
|---|---|---|---|
| 主要用途 | 多目标、尤其多目标数量较多 | 两三个目标 | 两三个目标 |
| 分布控制 | 参考方向 | 拥挤距离 | 密度距离 |
| 优秀解保存 | 父代和子代合并筛选 | 父代和子代合并筛选 | 独立外部档案 |
| 是否需要模型 | 需要人定义目标和约束 | 同样需要 | 同样需要 |
| 是否保证可行 | 取决于约束处理 | 取决于约束处理 | 取决于约束处理 |
| 是否保证最优 | 不保证 | 不保证 | 不保证 |

# 15. 可以与其他算法融合的位置

```text
贪心算法
  ↓ 生成较好的初始方案
NSGA-III
  ↓ 输出不同方向的折中方案
局部搜索
  ↓ 精细改进
最终方案集
```

| 融合方式 | 融合位置 | 数据传递 | 解决的问题 |
|---|---|---|---|
| NSGA-III + 贪心 | 初始化 | 贪心输出初始方案 | 提高起点质量 |
| NSGA-III + 局部搜索 | 子代优化 | 子代输入局部搜索 | 提高局部精度 |
| NSGA-III + CP/MILP | 修复或补全 | 部分决策输入求解器 | 处理复杂约束 |
| NSGA-III + RL | 算子和参数控制 | RL输出操作策略 | 动态调整搜索 |
| NSGA-III + 预测模型 | 目标评价 | 模型输出预测目标值 | 降低评价成本 |

# 16. 最小示例

## 原始问题

选择运输方案，同时希望时间短、成本低、能耗少。

## 输入数据

| 方案 | 时间 | 成本 | 能耗 |
|---|---:|---:|---:|
| A | 2 | 100 | 90 |
| B | 3 | 70 | 65 |
| C | 4 | 60 | 40 |
| D | 5 | 55 | 30 |

## 变量

```text
选择哪个运输方案
```

## 规则

```text
只能选择一个方案
```

## 目标

```text
时间最短
成本最低
能耗最少
```

## 算法执行过程

```text
生成参考方向
├── 更重视时间
├── 更重视成本
├── 更重视能耗
└── 三个目标较均衡

候选方案
  ↓
非支配排序
  ↓
关联到不同参考方向
  ↓
从各方向保留代表方案
```

## 输出结果

```text
折中方案集
├── A：速度优先
├── B：较均衡
├── C：成本和能耗较低
└── D：成本与能耗优先
```

NSGA-III负责提供不同取舍方向的方案，但不会替用户决定最终选择哪一个。

# 17. 一句话总结

> 人负责定义方案、多个目标、约束和参考方向；NSGA-III负责搜索并保留不同方向上的代表方案；最终输出一组分布较均匀的折中方案。
