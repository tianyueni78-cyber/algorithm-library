# MILP：混合整数线性规划

本文中的 MILP 指 Mixed-Integer Linear Programming（混合整数线性规划）。

MILP 更准确地说是一类优化模型，而不是单一算法。它通常由分支定界、割平面和 LP 松弛等算法共同求解。

MILP 的“混合”指同一个模型中同时存在：

```text
整数或0-1变量
+
连续变量
```

例如：

```text
是否启动机器 → 只能是0或1
机器生产多少 → 可以是2.5吨
```

# 1. 一句话说明它是什么

> MILP 是一种同时处理“选不选择”和“选择后投入多少”的优化方法，主要用于在满足资源和业务规则的前提下寻找成本最低或收益最高的方案。

MILP 常用于：

- 决定是否启动某台机器，以及启动后生产多少；
- 决定建设哪些仓库，以及各仓库运输多少货物；
- 决定使用多少辆车，以及每辆车运输多少；
- 决定哪些订单被接受，以及为订单分配多少资源；
- 决定任务分配给哪台机器，以及任务何时执行；
- 决定是否投资某个项目，以及投资多少资金。

MILP 的核心作用不是帮助人自动发现变量和约束，而是：

> 当人已经把现实问题写成整数变量、连续变量、线性约束和线性目标以后，由求解器搜索可行方案并尽量找到最优方案。

# 3. 人和 MILP 分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 整理已知数据
  ├── 找出需要决定的事情
  ├── 区分离散决定和连续数量
  ├── 创建整数、0-1和连续变量
  ├── 把现实规则写成线性约束
  ├── 定义成本、利润或时间目标
  └── 检查模型是否符合现实
  ↓
MILP求解器需要完成的工作
  ├── 检查并简化模型
  ├── 暂时放松整数限制
  ├── 求解多个LP子问题
  ├── 对整数变量进行分支
  ├── 排除不可能更优的分支
  ├── 寻找更好的整数可行解
  └── 尝试证明当前解最优
  ↓
最终结果
  ├── 哪些方案被选择
  ├── 每个连续数量是多少
  ├── 最优成本或利润
  ├── 求解状态
  └── 当前解与理论最优值的差距
```

## 3.1 人向 MILP 提供什么

人需要提供：

- 原始业务数据；
- 0-1变量；
- 一般整数变量；
- 连续变量；
- 变量上下界；
- 线性约束；
- 线性目标函数；
- 求解时间等参数。

例如：

```text
已知：
机器启动成本
机器生产成本
机器最大产能
市场需求

需要决定：
是否启动机器
每台机器生产多少

必须满足：
没有启动的机器不能生产
总产量必须满足需求
生产量不能超过机器产能

希望：
总成本最低
```

## 3.2 MILP 求解器做什么

求解器接收到模型后，会：

1. 检查模型结构；
2. 简化变量和约束；
3. 暂时允许整数变量取小数；
4. 求解这个放松后的 LP；
5. 检查整数变量是否得到合法整数；
6. 如果不是整数，就把问题拆成多个分支；
7. 在每个分支中继续求解；
8. 保存当前最好的整数可行解；
9. 排除不可能超过当前答案的分支；
10. 在可能时证明当前解最优。

## 3.3 MILP 最后返回什么

求解器通常返回：

- 求解状态；
- 整数变量的取值；
- 连续变量的取值；
- 目标函数值；
- 理论最优界；
- 最优差距；
- 求解时间；
- 搜索节点数量。

常见求解状态：

```text
OPTIMAL      找到并证明了最优解
FEASIBLE     找到可行解，但没有证明最优
INFEASIBLE   模型没有可行解
UNBOUNDED    目标可以无限改善
UNKNOWN      暂时无法确定
```

# 5. 从抽象现实问题中提取 MILP 模型的方法

## 5.1 什么事情需要决定

```text
什么事情需要选择、开启、关闭、分配或确定？
→ 决策变量
```

MILP 最重要的是把决策分成两类。

### 离散决策

只能取完整值：

```text
是否选择
选择哪一个
使用多少辆车
安排多少名员工
```

对应：

- 0-1变量；
- 整数变量。

### 连续决策

允许取小数：

```text
生产多少吨
运输多少货物
投入多少资金
分配多少能源
```

对应：

- 连续变量。

常见自然语言与变量类型：

| 现实表达 | 变量类型 |
|---|---|
| 是否启动机器 | 0-1变量 |
| 是否建设仓库 | 0-1变量 |
| 使用多少辆车 | 整数变量 |
| 安排多少名员工 | 整数变量 |
| 生产多少吨 | 连续变量 |
| 运输多少货物 | 连续变量 |
| 投入多少资金 | 连续变量 |

## 5.2 什么情况绝对不允许

```text
什么必须满足？
什么不能发生？
什么至少需要多少？
什么最多允许多少？
→ 约束
```

常见关键词：

| 现实语言 | 可能的约束 |
|---|---|
| 不能超过 | 上限约束 |
| 至少需要 | 下限约束 |
| 必须等于 | 等式约束 |
| 只能选择一个 | 唯一选择约束 |
| 只有启动后才能生产 | 联动约束 |
| 如果选择A，就必须选择B | 逻辑约束 |
| 不能同时选择A和B | 互斥约束 |
| 总量必须满足需求 | 需求约束 |
| 总使用量不能超过容量 | 容量约束 |

MILP 中很重要的一类约束是联动约束：

```text
离散决定
  ↓ 控制
连续数量
```

例如：

```text
y = 1：机器启动
y = 0：机器关闭
x：机器生产量
M：机器最大产能
```

联动约束：

```text
x ≤ M × y
```

它表示：

- 如果 `y=0`，那么 `x≤0`，机器不能生产；
- 如果 `y=1`，那么 `x≤M`，机器可以在产能范围内生产。

## 5.3 什么结果算更好

```text
成本更低、利润更高、时间更短、使用资源更少
→ 目标函数
```

常见目标：

- 最小化固定启动成本；
- 最小化生产成本；
- 最小化运输成本；
- 最小化总延误；
- 最大化利润；
- 最大化完成订单数量；
- 最小化使用的机器或车辆数量。

MILP 可以把固定成本和连续成本放在同一个目标中：

```text
总成本
=
是否启动 × 固定成本
+
生产数量 × 单位成本
```

## 5.4 哪些信息在决策前已经知道

```text
决策前已经确定的数字
→ 输入数据或参数
```

例如：

- 机器启动成本；
- 机器最大产能；
- 单位生产成本；
- 客户需求；
- 运输距离；
- 车辆容量；
- 员工数量；
- 加工时间。

区分方法：

```text
机器最大产能为5吨
→ 已知参数

机器实际生产多少吨
→ 连续变量

机器是否启动
→ 0-1变量
```

## 5.5 哪些信息会随着过程变化

可能变化的信息包括：

- 新订单到达；
- 机器发生故障；
- 市场需求改变；
- 能源价格变化；
- 运输时间变化；
- 资源临时不可用。

标准 MILP 通常是静态求解：

```text
输入当前数据
→ 求解一次
→ 输出一套方案
```

如果环境变化，可以使用滚动优化：

```text
获取当前状态
  ↓
更新MILP数据和约束
  ↓
固定已经执行的决定
  ↓
重新求解
  ↓
执行下一阶段决策
```

## 5.6 固定建模框架

面对现实问题时，可以依次问：

```text
已经知道哪些数据？
→ 参数

需要决定哪些“是或否”？
→ 0-1变量

需要决定哪些完整数量？
→ 整数变量

需要决定哪些可取小数的数量？
→ 连续变量

哪些连续变量受离散决定控制？
→ 联动约束

哪些资源不能超限？
→ 容量约束

哪些需求必须满足？
→ 需求约束

哪些逻辑不能违反？
→ 选择、互斥或条件约束

什么结果算最好？
→ 目标函数

这些关系能否写成线性形式？
→ 判断是否适合标准MILP
```

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 现实中的已知数据 | 启动成本、产能、需求 |
| 建模后的输入 | 整数变量、连续变量、约束、目标 | `y[i]`、`x[i]`、容量约束 |
| 求解器参数 | 控制求解过程的设置 | 时间限制、线程数、最优差距 |
| 算法内部数据 | LP松弛解、搜索节点、上下界 | 当前最好解和理论下界 |
| 模型输出 | 每个变量的取值 | `y1=1`、`x1=4` |
| 最终业务输出 | 可以执行的现实方案 | 启动生产线1并生产4吨 |

## 6.1 原始业务输入

原始输入通常包括：

```text
对象集合
成本数据
利润数据
容量数据
需求数据
允许关系
时间数据
业务规则
```

## 6.2 建模后的算法输入

MILP 求解器需要：

```text
0-1变量
+ 整数变量
+ 连续变量
+ 线性约束
+ 线性目标函数
```

## 6.3 算法内部数据

求解器内部通常维护：

- LP 松弛解；
- 当前最好整数解；
- 当前理论界；
- 搜索树；
- 待处理节点；
- 割平面；
- 最优差距；
- 启发式候选解。

这些内容通常由求解器管理。

## 6.4 最终业务输出

求解器可能返回：

```text
y1 = 1
y2 = 0
x1 = 4
x2 = 0
```

业务解释是：

```text
启动生产线1
关闭生产线2
生产线1生产4吨
生产线2不生产
```

# 7. 完整运行流程

```text
现实问题
  ↓
整理成本、容量和需求数据
  ↓
识别离散选择与连续数量
  ↓
创建0-1、整数和连续变量
  ↓
添加容量、需求和逻辑约束
  ↓
添加离散变量与连续变量的联动约束
  ↓
设置最低成本或最高利润目标
  ↓
生成MILP模型
  ↓
求解LP松弛问题
  ↓
对非整数结果进行分支
  ↓
使用界和割平面剪枝
  ↓
得到整数可行候选解
  ↓
比较并改进候选解
  ↓
返回当前最好或已证明最优的方案
  ↓
转换和验证现实结果
```

# 8. 模块结构

一个不过度拆分的 MILP 项目可以采用：

```text
MILP_Project
├── 01_Problem_Data
├── 02_Model_Builder
├── 03_Solver
├── 04_Solution
└── 05_Main
```

模型构建模块内部包括：

```text
Model_Builder
├── Variables
├── Constraints
├── Linking_Constraints
└── Objective
```

求解器内部通常包括：

```text
Solver_Internal
├── Presolve
├── LP_Relaxation
├── Branch_And_Bound
├── Cutting_Planes
├── Primal_Heuristics
└── Bound_Manager
```

求解器内部模块一般不需要用户自己实现。

# 9. 每个模块的输入、输出和构成

## 9.1 问题数据模块 Problem Data

### 作用

读取、检查并整理现实问题中的已知数据。

### 输入

- 业务对象；
- 固定成本；
- 单位成本；
- 资源容量；
- 市场需求；
- 允许关系；
- 其他业务参数。

### 内部构成

```text
ProblemData
├── DataLoader
├── DataValidator
└── DataContainer
```

### 处理过程

1. 读取原始数据；
2. 检查缺失和重复信息；
3. 统一单位；
4. 给业务对象统一编号；
5. 转换成数组、表格或字典；
6. 检查模型需要的数据是否完整。

### 输出

- 对象集合；
- 固定成本向量；
- 连续成本向量；
- 容量参数；
- 需求参数；
- 允许关系。

### 是否需要用户自己实现

通常需要自己实现。

求解器不知道业务数据的格式和含义。

## 9.2 模型构建模块 Model Builder

### 作用

把业务数据转换成完整的 MILP 模型。

### 输入

- 结构化问题数据；
- 变量定义；
- 业务规则；
- 优化目标。

### 内部构成

```text
ModelBuilder
├── VariableBuilder
├── ConstraintBuilder
├── LinkingConstraintBuilder
└── ObjectiveBuilder
```

### 处理过程

1. 创建模型；
2. 创建离散变量；
3. 创建连续变量；
4. 设置变量上下界；
5. 添加业务约束；
6. 添加离散与连续变量的联动约束；
7. 设置目标函数；
8. 返回完整模型。

### 输出

- 完整 MILP 模型；
- 变量集合；
- 业务对象与变量的映射。

### 是否需要用户自己实现

模型的业务含义和构建逻辑需要自己实现。

模型接口由求解库提供。

## 9.3 决策变量组件 Variables

### 作用

表示现实中的离散选择和连续数量。

### 输入

- 业务对象；
- 变量名称；
- 变量类型；
- 变量上下界。

### 内部构成

```text
Variables
├── BinaryVariables
├── IntegerVariables
├── ContinuousVariables
└── VariableIndex
```

### 处理过程

1. 找出所有“是否选择”决策；
2. 创建0-1变量；
3. 找出所有完整数量决策；
4. 创建整数变量；
5. 找出允许小数的数量；
6. 创建连续变量；
7. 保存变量和业务对象的对应关系。

### 输出

- 二进制变量；
- 一般整数变量；
- 连续变量；
- 变量索引。

### 是否需要用户自己实现

变量含义和变量类型需要用户决定。

变量对象由求解库创建。

## 9.4 约束组件 Constraints

### 作用

把现实中的容量、需求、分配和逻辑规则写入模型。

### 输入

- 决策变量；
- 资源容量；
- 需求数据；
- 业务规则。

### 内部构成

```text
Constraints
├── CapacityConstraints
├── DemandConstraints
├── AssignmentConstraints
├── LogicalConstraints
└── LinkingConstraints
```

### 处理过程

1. 找出必须满足的规则；
2. 确定规则涉及哪些变量；
3. 把规则写成线性等式或不等式；
4. 为关键约束设置清晰名称；
5. 将约束加入模型。

### 输出

- 容量约束；
- 需求约束；
- 分配约束；
- 逻辑约束；
- 联动约束。

### 是否需要用户自己实现

约束的现实含义需要自己定义。

约束对象和存储由求解器提供。

## 9.5 联动约束组件 Linking Constraints

### 作用

连接离散选择和连续数量。

### 输入

- 0-1变量；
- 连续变量；
- 最大容量；
- 业务联动规则。

### 内部构成

```text
LinkingConstraints
├── ActivationConstraints
├── UpperBoundLinks
├── LowerBoundLinks
└── ConditionalConstraints
```

### 处理过程

1. 找到“只有选择后才能执行”的关系；
2. 确定控制变量；
3. 确定被控制的连续变量；
4. 根据真实容量设置上下界；
5. 建立联动约束。

### 输出

例如：

```text
x[i] ≤ capacity[i] × y[i]
```

表示：

```text
y[i]=0 → x[i]=0
y[i]=1 → x[i]可以在容量内取值
```

### 是否需要用户自己实现

联动关系和合理界限需要自己设计。

求解器负责执行约束。

## 9.6 目标组件 Objective

### 作用

告诉求解器怎样评价不同可行方案。

### 输入

- 离散变量；
- 连续变量；
- 固定成本；
- 单位成本或利润；
- 优化方向。

### 内部构成

```text
Objective
├── FixedCostTerms
├── VariableCostTerms
├── ObjectiveExpression
└── OptimizationDirection
```

### 处理过程

1. 计算选择方案产生的固定成本；
2. 计算连续数量产生的可变成本；
3. 将它们合并为总目标；
4. 设置最小化或最大化。

### 输出

例如：

```text
总成本
=
固定启动成本
+
连续生产成本
+
运输成本
```

### 是否需要用户自己实现

目标含义和计算方式需要自己设计。

求解器提供目标函数接口。

## 9.7 求解器模块 Solver

### 作用

在满足全部约束的混合变量方案中寻找最优解。

### 输入

- 完整 MILP 模型；
- 时间限制；
- 线程数量；
- 最优差距；
- 可选初始解；
- 求解参数。

### 内部构成

```text
Solver
├── Presolve
├── LPRelaxation
├── BranchAndBound
├── CuttingPlanes
├── PrimalHeuristics
└── BoundManager
```

### 处理过程

1. 预处理并简化模型；
2. 暂时取消整数限制；
3. 求解 LP 松弛问题；
4. 检查离散变量是否满足整数要求；
5. 对不满足整数要求的变量进行分支；
6. 计算各分支的理论界；
7. 排除不可能更优的分支；
8. 使用割平面缩小搜索区域；
9. 使用内部启发式寻找整数可行解；
10. 达到停止条件后返回结果。

### 输出

- 求解状态；
- 整数变量值；
- 连续变量值；
- 目标函数值；
- 最优界；
- 最优差距；
- 求解统计信息。

### 是否需要用户自己实现

通常由 Gurobi、CPLEX、SCIP、HiGHS、OR-Tools 等求解器提供。

一般不需要自己实现分支定界和割平面。

## 9.8 解提取与验证模块 Solution

### 作用

把求解器变量转换成现实方案并验证结果。

### 输入

- 求解状态；
- 变量值；
- 目标值；
- 原始业务数据。

### 内部构成

```text
Solution
├── SolutionExtractor
├── BusinessConverter
├── ConstraintValidator
└── ResultExporter
```

### 处理过程

1. 检查是否找到可行解；
2. 读取整数和连续变量；
3. 转换成业务决策；
4. 重新计算成本或利润；
5. 检查关键业务约束；
6. 输出结果表格。

### 输出

- 选择了哪些方案；
- 每个方案执行多少；
- 总成本或利润；
- 约束验证结果；
- 业务报表。

### 是否需要用户自己实现

通常需要自己实现。

求解器不知道用户希望如何展示业务结果。

## 9.9 主流程模块 Main

### 作用

按照固定顺序组织完整程序。

### 输入

- 数据文件；
- 模型配置；
- 求解参数。

### 内部构成

```text
Main
├── LoadData
├── BuildModel
├── SolveModel
└── ExportSolution
```

### 处理过程

```text
读取数据
→ 构建模型
→ 调用求解器
→ 提取结果
→ 验证结果
→ 输出方案
```

### 输出

- 最终业务方案；
- 求解日志；
- 运行状态；
- 结果文件。

### 是否需要用户自己实现

通常需要自己实现，但应该保持简短。

# 12. MILP 真正帮我解决什么

## 12.1 它是在帮助我理解问题吗？

不是直接帮助。

MILP 提供了一个整理问题的框架：

```text
离散选择
+ 连续数量
+ 线性约束
+ 线性目标
```

但现实问题的含义仍然需要由人理解。

## 12.2 它是在帮助我建立模型吗？

部分是。

MILP 告诉你可以把问题拆成：

- 0-1变量；
- 整数变量；
- 连续变量；
- 线性约束；
- 线性目标。

但具体变量和约束仍然需要人定义。

## 12.3 它是在帮助我搜索答案吗？

是。

MILP 求解器会在大量离散选择和连续分配组合中寻找可行方案，并尽量证明哪个方案最优。

## 12.4 它是在帮助我预测结果吗？

不是。

MILP 负责优化决策，不负责根据历史数据预测需求、价格或故障。

可以使用：

```text
机器学习负责预测
MILP负责优化
```

## 12.5 它是在帮助我做连续决策吗？

MILP 中的“连续变量”是指变量允许取小数，不等于持续与环境互动。

标准 MILP 通常一次输入、一次求解。

动态环境可以通过滚动优化反复求解。

## 12.6 它是在帮助我验证解是否可行吗？

可以。

如果候选方案的变量值被固定，求解器可以检查这些值是否满足模型约束。

但只能验证已经写进模型的规则。

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 设施选址与运输分配 | 同时包含是否建设和运输多少 |
| 机器启动与生产计划 | 同时包含开关决定和连续产量 |
| 车辆使用与货物流量 | 同时包含车辆数量和运输量 |
| 订单选择与资源分配 | 同时包含是否接单和资源投入 |
| 能源系统优化 | 同时包含设备启停和连续功率 |
| 投资组合 | 同时包含是否投资和投资金额 |
| 生产批次和连续配比 | 同时包含批次决策和连续用量 |
| 需要最优性界的问题 | 求解器可以提供理论界和最优差距 |

| 不太适合 | 原因 |
|---|---|
| 关系高度非线性 | 标准 MILP 只接受线性关系 |
| 复杂任务顺序非常多 | CP 或专门调度算法可能更自然 |
| 超大规模且要求瞬时响应 | 精确搜索可能耗时较长 |
| 图像、语音或文本理解 | MILP 不负责提取语义 |
| 主要任务是预测未来 | 应使用统计或机器学习方法 |
| 环境持续交互且模型难更新 | 强化学习可能更自然 |
| 现实规则无法明确表达 | 无法构建可靠模型 |

# 14. 与相近算法比较

| 对比项 | MILP | LP | IP | CP |
|---|---|---|---|---|
| 中文名称 | 混合整数线性规划 | 线性规划 | 整数规划 | 约束规划 |
| 变量类型 | 整数与连续变量混合 | 连续变量 | 整数变量 | 整数、布尔、区间和序列变量 |
| 是否允许小数 | 部分变量允许 | 全部变量通常允许 | 通常不允许 | 由变量域决定 |
| 是否需要人建模 | 需要 | 需要 | 需要 | 需要 |
| 核心求解方式 | LP松弛、分支定界、割平面 | 单纯形法、内点法 | 分支定界、割平面 | 约束传播和搜索 |
| 是否保证可行 | 返回解满足已写约束 | 同左 | 同左 | 同左 |
| 是否追求最优 | 通常是 | 通常是 | 通常是 | 可以只求可行或继续优化 |
| 适用问题 | 离散选择与连续分配混合 | 连续资源分配 | 纯离散数量或选择 | 排序、调度、复杂逻辑 |

## 14.1 MILP 与 LP

LP 只处理连续数量：

```text
生产多少吨
运输多少货物
```

MILP 还可以处理：

```text
是否启动机器
是否建设仓库
```

## 14.2 MILP 与 IP

IP 中所有核心变量通常要求为整数。

MILP 同时包含：

```text
整数变量 + 连续变量
```

实际工程问题经常同时包含这两类变量，因此 MILP 使用得非常广泛。

## 14.3 MILP 与 CP

MILP 更擅长：

- 成本；
- 容量；
- 流量；
- 资源平衡；
- 离散与连续联合优化。

CP 更擅长：

- 时间区间；
- 任务顺序；
- 资源互斥；
- 复杂逻辑。

# 15. 可以与其他算法融合的位置

## 15.1 启发式算法提供初始解

```text
GA、NSGA-II、贪心或局部搜索
  ↓ 提供一个候选方案
MILP
  ↓ 继续优化并计算理论界
更好的方案或已证明最优的方案
```

融合位置：

- 初始解；
- 热启动；
- 候选整数解。

融合目的：

- 更快找到高质量可行解；
- 帮助求解器剪枝；
- 缩短得到实用方案的时间。

## 15.2 MILP 修复候选解

```text
GA或RL
  ↓ 产生可能违反约束的方案
MILP
  ↓ 修复冲突并优化连续数量
可行业务方案
```

前一个算法输出：

- 机器选择；
- 任务分配；
- 车辆选择；
- 初始排序。

MILP 接收这些部分决定后：

- 固定部分变量；
- 修复剩余冲突；
- 优化资源分配。

## 15.3 机器学习预测参数

```text
机器学习
  ↓ 预测需求、价格、时间或故障概率
MILP
  ↓ 优化选择和资源分配
最终决策方案
```

机器学习负责：

- 预测未知数据。

MILP 负责：

- 在预测数据基础上做优化决策。

## 15.4 强化学习控制求解策略

```text
MILP当前求解状态
  ↓
RL选择分支变量、割或启发式策略
  ↓
MILP继续搜索
```

融合位置：

- 分支变量选择；
- 节点选择；
- 求解参数控制；
- 启发式策略选择。

## 15.5 分解方法处理大规模模型

```text
大型MILP
  ↓ 拆分
主问题 + 子问题
  ↓ 交换约束或价格信息
完整方案
```

常见方法：

- Benders 分解；
- 列生成；
- Dantzig-Wolfe 分解；
- 拉格朗日松弛。

# 16. 最小示例

## 16.1 原始问题

工厂有两条生产线，需要满足4吨产品需求。

| 生产线 | 固定启动成本 | 单位生产成本 | 最大产能 |
|---|---:|---:|---:|
| 生产线1 | 5 | 1 | 4 |
| 生产线2 | 2 | 2 | 5 |

需要决定：

- 启动哪条生产线；
- 每条生产线生产多少；
- 使总成本最低。

## 16.2 输入数据

```text
需求：4吨

生产线1：
启动成本5
单位生产成本1
最大产能4

生产线2：
启动成本2
单位生产成本2
最大产能5
```

## 16.3 变量

0-1变量：

```text
y1 = 1：启动生产线1
y1 = 0：关闭生产线1

y2 = 1：启动生产线2
y2 = 0：关闭生产线2
```

连续变量：

```text
x1 = 生产线1的产量
x2 = 生产线2的产量
```

## 16.4 约束

满足需求：

```text
x1 + x2 ≥ 4
```

生产线1只有启动后才能生产：

```text
x1 ≤ 4 × y1
```

生产线2只有启动后才能生产：

```text
x2 ≤ 5 × y2
```

变量范围：

```text
y1,y2 ∈ {0,1}
x1,x2 ≥ 0
```

## 16.5 目标

最小化总成本：

```text
5y1 + 2y2 + 1x1 + 2x2
```

其中：

```text
5y1 + 2y2
→ 固定启动成本

1x1 + 2x2
→ 连续生产成本
```

## 16.6 手工检查方案

### 方案一：只启动生产线1

```text
y1=1
y2=0
x1=4
x2=0

总成本：
5 + 4 = 9
```

### 方案二：只启动生产线2

```text
y1=0
y2=1
x1=0
x2=4

总成本：
2 + 8 = 10
```

### 方案三：两条生产线都启动

即使把4吨全部放在生产线1：

```text
固定成本 = 5 + 2
生产成本 = 4

总成本 = 11
```

因此没有必要同时启动两条生产线。

## 16.7 输出结果

```text
y1 = 1
y2 = 0
x1 = 4
x2 = 0

最低总成本 = 9
```

现实含义：

```text
启动生产线1
关闭生产线2
生产线1生产4吨
总成本为9
```

这个示例展示了 MILP 的核心：

```text
y决定是否启动
x决定启动后生产多少
联动约束保证未启动时不能生产
```

# 17. 一句话总结

> 人负责把现实问题转换成整数选择、连续数量、线性约束和目标；MILP 求解器负责联合搜索“选什么”和“选后投入多少”的最优组合；最终输出满足约束的离散决定、连续数量和目标值。
