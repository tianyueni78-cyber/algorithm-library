# QP：二次规划

本文中的 QP 指 Quadratic Programming（二次规划）。

标准 QP 通常具有以下特点：

```text
连续决策变量
+
二次目标函数
+
线性约束
```

“二次目标”是指评价方案时允许出现：

```text
变量的平方
两个变量的乘积
偏差的平方
```

例如：

```text
(x - 目标值)²
```

它表示：实际值偏离目标越远，受到的惩罚增长得越快。

QP 是一类优化模型，不是单一算法。实际求解可能使用：

- 活跃集法；
- 内点法；
- 投影梯度法；
- 算子分裂法；
- 专门的凸 QP 求解算法。

# 1. 一句话说明它是什么

> QP 是一种在满足资源和业务限制的前提下，寻找成本、偏差、波动或风险最小方案的方法，特别适合处理“偏离目标越远，惩罚越大”的问题。

QP 常用于：

- 让生产量尽量接近计划值；
- 让资源分配尽量平衡；
- 减少控制动作的大幅波动；
- 降低投资组合风险；
- 让机器人运动轨迹更加平滑；
- 让实际输出尽量跟踪目标输出；
- 在满足安全约束的前提下修正控制动作；
- 作为模型预测控制 MPC 的内部优化问题。

QP 的核心作用不是自动理解现实问题，而是：

> 当人已经定义了连续变量、线性约束和二次评价标准后，由 QP 求解器寻找最优连续方案。

# 3. 人和 QP 分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 整理已知数据
  ├── 找出需要决定的连续数量
  ├── 找出必须满足的限制
  ├── 确定希望接近的目标值
  ├── 定义偏差、风险或波动的惩罚
  ├── 构造二次目标函数
  ├── 检查模型是否为凸QP
  └── 验证结果是否符合现实
  ↓
QP求解器需要完成的工作
  ├── 读取二次目标和线性约束
  ├── 检查并简化模型
  ├── 确定当前可行范围
  ├── 计算目标函数的变化方向
  ├── 识别当前起作用的约束
  ├── 迭代寻找更优连续方案
  └── 返回最优解或当前最好解
  ↓
最终结果
  ├── 每个连续变量的取值
  ├── 二次目标函数值
  ├── 哪些约束处于边界
  ├── 求解状态
  └── 可转换为现实行动的方案
```

## 3.1 人向 QP 提供什么

人需要提供：

- 原始业务数据；
- 连续决策变量；
- 变量上下界；
- 线性等式约束；
- 线性不等式约束；
- 二次目标函数；
- 各类偏差的权重；
- 求解参数。

例如：

```text
已知：
总需求为10吨
两条生产线的目标产量
每条生产线的最大产能

需要决定：
两条生产线实际生产多少

必须满足：
总产量达到10吨
每条生产线不能超过产能

希望：
实际产量尽量接近原计划
```

## 3.2 QP 求解器做什么

QP 求解器会：

1. 读取变量、约束和二次目标；
2. 判断模型的数值结构；
3. 在满足约束的区域中寻找候选解；
4. 计算候选解的偏差、风险或波动；
5. 调整变量以降低目标值；
6. 处理已经达到边界的约束；
7. 判断是否满足停止条件；
8. 返回最优或当前最好方案。

## 3.3 QP 最后返回什么

求解器通常返回：

- 求解状态；
- 每个连续变量的值；
- 二次目标函数值；
- 约束是否满足；
- 哪些约束处于边界；
- 迭代次数；
- 求解时间；
- 可选的对偶变量。

常见状态：

```text
OPTIMAL      找到最优解
INFEASIBLE   没有同时满足全部约束的方案
UNBOUNDED    目标可以无限改善
MAX_ITER     达到最大迭代次数
NUMERICAL    出现数值问题
UNKNOWN      暂时无法确定结果
```

## 3.4 凸 QP 与非凸 QP

这是理解 QP 时必须区分的内容。

### 凸 QP

可以把目标函数想成一个碗：

```text
      \        /
       \      /
        \____/
```

碗底只有一个最低区域。

对于凸 QP：

- 局部最优解也是全局最优解；
- 求解通常比较稳定；
- 求解器更容易证明结果最优。

### 非凸 QP

目标函数可能像多个山谷：

```text
\__/  \____/  \__/
```

对于非凸 QP：

- 可能有多个局部最优解；
- 找到一个低点不代表是全局最低点；
- 求解难度可能明显增加；
- 不同求解器的保证可能不同。

因此不能只看到“QP”就认为求解器一定能轻松找到全局最优解。

# 5. 从抽象现实问题中提取 QP 模型的方法

## 5.1 什么事情需要决定

```text
什么连续数量需要确定？
→ 决策变量
```

常见自然语言：

| 现实表达 | 可能的 QP 变量 |
|---|---|
| 每台机器生产多少 | 连续产量变量 |
| 每个资源分配多少 | 连续分配变量 |
| 每个资产投资多少 | 连续投资比例 |
| 每个时刻施加多少控制量 | 连续控制变量 |
| 轨迹上每个位置是多少 | 连续位置变量 |
| 每个区域供应多少能量 | 连续功率变量 |

QP 的变量通常允许取小数：

```text
2.5吨
3.7千瓦
25.8万元
0.42投资比例
```

如果核心决定必须是0或1或完整整数，通常需要 MIQP，而不是纯 QP。

MIQP 指混合整数二次规划：

```text
整数变量
+
连续变量
+
二次目标或二次关系
```

## 5.2 什么情况绝对不允许

```text
什么必须满足？
什么不能超过？
什么至少需要多少？
什么必须保持平衡？
→ 约束
```

常见关键词：

| 现实语言 | 可能的约束 |
|---|---|
| 不能超过 | 上限约束 |
| 至少达到 | 下限约束 |
| 必须等于 | 等式约束 |
| 总量保持不变 | 平衡约束 |
| 总投入不能超过预算 | 预算约束 |
| 输出必须满足需求 | 需求约束 |
| 变量不能为负 | 非负约束 |
| 控制量不能变化过快 | 变化率约束 |

标准 QP 经常使用线性约束：

```text
变量的加权总和 ≤ 上限
变量的加权总和 = 需求
变量的加权总和 ≥ 下限
```

## 5.3 什么结果算更好

QP 特别适合以下表达：

```text
尽量接近目标
尽量保持平稳
尽量降低风险
尽量避免过大变化
尽量平衡多个对象
```

这些要求经常用平方惩罚表示。

### 偏离目标的平方

```text
(实际值 - 目标值)²
```

偏差越大，惩罚增长越快。

例如：

| 偏差 | 普通绝对偏差 | 平方偏差 |
|---:|---:|---:|
| 1 | 1 | 1 |
| 2 | 2 | 4 |
| 3 | 3 | 9 |
| 4 | 4 | 16 |

因此平方目标会更强烈地避免大偏差。

### 变化量的平方

```text
(本次控制量 - 上次控制量)²
```

用于减少突然变化，让动作更平滑。

### 风险的二次表达

投资组合中，不同资产之间会互相影响。

风险可能写成：

```text
各资产投资比例
×
资产之间的协方差
×
投资比例
```

这里的二次项表示多个资产共同变化带来的组合风险。

## 5.4 哪些信息在决策前已经知道

```text
决策前已经确定的数据
→ 参数
```

例如：

- 目标产量；
- 资源总量；
- 最大产能；
- 允许范围；
- 当前状态；
- 上一次控制动作；
- 资产收益；
- 风险矩阵；
- 各类偏差的权重。

区分方法：

```text
目标产量为6吨
→ 已知参数

实际安排生产多少
→ 决策变量
```

## 5.5 哪些信息会随着过程变化

可能变化的信息包括：

- 目标值；
- 当前设备状态；
- 市场风险；
- 产品需求；
- 当前车辆位置；
- 控制系统状态；
- 上一次执行结果。

标准 QP 通常求解一次当前问题。

动态问题可以反复求解：

```text
读取当前状态
  ↓
更新QP参数
  ↓
求解当前最优动作
  ↓
执行第一个动作
  ↓
获取新状态
  ↓
再次求解
```

模型预测控制 MPC 就经常采用这种方式。

## 5.6 固定提取框架

面对现实问题，可以依次问：

```text
已经知道哪些数据？
→ 参数

需要决定哪些连续数量？
→ 决策变量

哪些数量必须保持平衡？
→ 等式约束

哪些资源不能超限？
→ 不等式约束

希望变量接近什么目标？
→ 跟踪误差

希望避免哪些大偏差？
→ 平方偏差项

希望哪些动作更加平滑？
→ 变化量平方项

不同变量之间是否会互相影响？
→ 交叉二次项

各类偏差谁更重要？
→ 目标权重

目标函数是不是凸的？
→ 判断能否稳定求得全局最优解
```

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 现实中的已知数据 | 目标产量、产能、资源量 |
| 建模后的输入 | 连续变量、线性约束、二次目标 | `x1`、`x2`、偏差平方 |
| 求解器参数 | 控制求解过程的设置 | 精度、最大迭代次数 |
| 算法内部数据 | 梯度、活跃约束、搜索方向 | 当前迭代点和改进方向 |
| 模型输出 | 变量值和目标值 | `x1=5`、`x2=5` |
| 最终业务输出 | 可以执行的现实方案 | 两条生产线各生产5吨 |

## 6.1 原始业务输入

原始数据可能包括：

```text
目标值
当前值
容量
需求
成本
风险
权重
允许范围
```

## 6.2 建模后的算法输入

标准 QP 通常需要：

```text
决策变量 x
二次目标矩阵 Q
线性目标系数 c
线性约束矩阵 A
约束上下界
变量上下界
```

常见目标形式：

```text
最小化：

1/2 × xᵀQx + cᵀx
```

初学阶段可以这样理解：

```text
xᵀQx
→ 平方项和变量之间的共同影响

cᵀx
→ 普通线性成本或收益
```

不需要先手工推导矩阵，但需要知道 Q 决定目标函数的弯曲形状。

## 6.3 算法内部数据

求解器内部可能维护：

- 当前候选解；
- 目标函数值；
- 目标梯度；
- 活跃约束；
- 搜索方向；
- 步长；
- 对偶变量；
- 收敛误差。

## 6.4 最终业务输出

例如：

```text
求解器输出：
x1 = 5
x2 = 5

业务输出：
生产线1生产5吨
生产线2生产5吨
总产量为10吨
```

# 7. 完整运行流程

```text
现实问题
  ↓
整理目标值、资源和限制数据
  ↓
识别需要决定的连续数量
  ↓
创建连续决策变量
  ↓
添加变量范围和线性约束
  ↓
定义线性成本
  ↓
定义偏差、波动或风险的平方项
  ↓
检查二次目标是否为凸
  ↓
生成QP模型
  ↓
调用QP求解器
  ↓
计算当前梯度和可行搜索方向
  ↓
处理当前起作用的约束
  ↓
迭代改进候选解
  ↓
得到最优或当前最好方案
  ↓
验证约束和目标值
  ↓
转换成现实输出
```

# 8. 模块结构

一个不过度拆分的 QP 项目可以采用：

```text
QP_Project
├── 01_Problem_Data
├── 02_Model_Builder
├── 03_Solver
├── 04_Solution
└── 05_Main
```

模型构建模块内部包括：

```text
Model_Builder
├── Variables
├── Linear_Constraints
└── Quadratic_Objective
```

求解器内部可能包括：

```text
Solver_Internal
├── Presolve
├── Gradient_And_Hessian
├── Active_Set_Or_Interior_Point
├── Linear_System_Solver
└── Convergence_Checker
```

用户通常不需要自己实现求解器内部组件。

# 9. 每个模块的输入、输出和构成

## 9.1 问题数据模块 Problem Data

### 作用

读取并整理 QP 模型需要的现实数据。

### 输入

- 目标值；
- 当前状态；
- 容量；
- 资源限制；
- 成本；
- 风险数据；
- 惩罚权重。

### 内部构成

```text
ProblemData
├── DataLoader
├── DataValidator
└── DataContainer
```

### 处理过程

1. 读取原始数据；
2. 检查数据缺失；
3. 统一单位；
4. 检查矩阵维度；
5. 检查上下界是否合理；
6. 保存模型参数。

### 输出

- 目标向量；
- 当前状态；
- 约束参数；
- 权重；
- 风险或二次系数数据。

### 是否需要用户自己实现

通常需要自己实现。

求解器不知道业务数据的来源和含义。

## 9.2 模型构建模块 Model Builder

### 作用

把现实问题转换成完整 QP 模型。

### 输入

- 结构化问题数据；
- 变量定义；
- 业务约束；
- 二次评价标准。

### 内部构成

```text
ModelBuilder
├── VariableBuilder
├── ConstraintBuilder
└── QuadraticObjectiveBuilder
```

### 处理过程

1. 创建模型；
2. 创建连续变量；
3. 设置变量上下界；
4. 添加线性约束；
5. 构造平方偏差和交叉项；
6. 设置二次目标；
7. 返回模型和变量映射。

### 输出

- 完整 QP 模型；
- 变量集合；
- Q 矩阵；
- 线性系数；
- 约束矩阵。

### 是否需要用户自己实现

模型结构和业务含义需要自己实现。

模型接口由求解库提供。

## 9.3 决策变量组件 Variables

### 作用

表示现实中需要确定的连续数量。

### 输入

- 业务对象；
- 变量名称；
- 最小值；
- 最大值。

### 内部构成

```text
Variables
├── ContinuousVariables
├── LowerBounds
├── UpperBounds
└── VariableIndex
```

### 处理过程

1. 找出需要决定的数量；
2. 检查是否允许取小数；
3. 设置合理范围；
4. 创建连续变量；
5. 保存变量与业务对象的对应关系。

### 输出

- 连续决策变量；
- 变量上下界；
- 变量索引。

### 是否需要用户自己实现

变量含义和范围需要自己定义。

变量对象由求解库创建。

## 9.4 线性约束组件 Linear Constraints

### 作用

把现实中的容量、需求和平衡要求加入模型。

### 输入

- 决策变量；
- 资源数据；
- 需求数据；
- 业务规则。

### 内部构成

```text
LinearConstraints
├── EqualityConstraints
├── InequalityConstraints
├── BoundConstraints
└── BusinessConstraints
```

### 处理过程

1. 找出必须遵守的规则；
2. 确定涉及的变量；
3. 计算每个变量的线性系数；
4. 写成等式或不等式；
5. 将约束加入模型。

### 输出

- 等式约束；
- 不等式约束；
- 变量上下界。

### 是否需要用户自己实现

约束含义和表达方式需要自己设计。

约束接口由求解器提供。

## 9.5 二次目标组件 Quadratic Objective

### 作用

表示偏差、风险、波动和平滑性的评价标准。

### 输入

- 决策变量；
- 目标值；
- 二次权重；
- 线性成本；
- 变量之间的关联数据。

### 内部构成

```text
QuadraticObjective
├── QuadraticTerms
├── CrossTerms
├── LinearTerms
├── Weights
└── ObjectiveExpression
```

### 处理过程

1. 找出需要惩罚的偏差；
2. 为偏差建立平方项；
3. 找出变量之间的共同影响；
4. 添加交叉项；
5. 添加普通线性成本；
6. 设置不同目标的权重；
7. 检查 Q 矩阵是否满足凸性要求。

### 输出

- Q 矩阵；
- 线性系数；
- 完整二次目标函数。

### 是否需要用户自己实现

目标含义、权重和矩阵构造通常需要自己设计。

求解器负责计算和优化目标。

## 9.6 求解器模块 Solver

### 作用

在满足约束的连续方案中寻找二次目标最优解。

### 输入

- 完整 QP 模型；
- 初始解；
- 求解精度；
- 最大迭代次数；
- 求解方法。

### 内部构成

```text
Solver
├── Presolve
├── ActiveSetOrInteriorPoint
├── LinearSystemSolver
├── StepCalculator
└── ConvergenceChecker
```

### 处理过程

1. 检查并简化模型；
2. 读取初始点；
3. 计算目标函数变化方向；
4. 确定哪些约束限制当前移动；
5. 计算新的候选解；
6. 更新活跃约束或内部状态；
7. 检查目标和约束误差；
8. 达到停止条件后返回结果。

### 输出

- 求解状态；
- 最优或当前最好变量值；
- 目标函数值；
- 迭代次数；
- 对偶变量；
- 求解时间。

### 是否需要用户自己实现

通常由 OSQP、CVXOPT、Gurobi、CPLEX、MOSEK 等求解器提供。

一般不需要自己实现底层 QP 算法。

## 9.7 解提取与验证模块 Solution

### 作用

把变量值转换成现实方案并检查结果。

Solution

- 目标函数值；

# 12. QP 真正帮我解决什么

## 12.1 它是在帮助我理解问题吗？

不是直接帮助。

QP 提供了一个思考框架：

```text
连续变量
+ 线性限制
+ 二次评价
```

但现实问题中的变量和规则仍然需要人理解。

## 12.2 它是在帮助我建立模型吗？

部分是。

QP 告诉你可以用平方项表达：

- 偏离目标；
- 风险；
- 波动；
- 不平衡；
- 动作变化。

但具体惩罚什么、权重多大，需要人决定。

## 12.3 它是在帮助我搜索答案吗？

是。

QP 求解器负责在可行连续区域中寻找二次目标最优的变量组合。

## 12.4 它是在帮助我预测结果吗？

不是。

QP 不会根据历史数据预测未来状态。

可以使用：

```text
机器学习负责预测
QP负责根据预测结果优化
```

## 12.5 它是在帮助我做连续决策吗？

QP 的变量通常是连续变量，但标准 QP 本身是一次性求解。

如果需要持续决策，可以将 QP 放在循环中重复求解，例如 MPC。

## 12.6 它是在帮助我验证解是否可行吗？

可以检查候选解是否满足模型中的线性约束和变量范围。

但它无法检查没有写入模型的现实规则。

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 目标跟踪 | 平方项可以惩罚偏离目标 |
| 平滑控制 | 可以惩罚动作的大幅变化 |
| 投资组合优化 | 风险可以表示成二次形式 |
| 平衡资源分配 | 可以惩罚分配不均 |
| 模型预测控制 | 每次可以快速计算连续控制量 |
| 轨迹优化 | 可以减少位置或速度变化 |
| 最小二乘问题 | 误差平方天然是二次目标 |
| 安全动作投影 | 可以寻找离原动作最近的可行动作 |

| 不太适合 | 原因 |
|---|---|
| 是否选择某个方案 | 需要整数变量，应考虑 MIQP |
| 任务排序 | 顺序关系难用纯 QP 表达 |
| 高度非线性关系 | 超出标准二次目标和线性约束 |
| 图像或文本理解 | QP 不负责提取语义 |
| 大量复杂逻辑约束 | MILP 或 CP 可能更自然 |
| 非凸且需要全局最优 | 求解难度可能非常高 |
| 主要目标是预测 | 应使用统计或机器学习方法 |

# 14. 与相近算法比较

| 对比项 | QP | LP | NLP | MIQP |
|---|---|---|---|---|
| 中文名称 | 二次规划 | 线性规划 | 非线性规划 | 混合整数二次规划 |
| 变量类型 | 通常连续 | 连续 | 通常连续 | 整数与连续混合 |
| 目标函数 | 二次 | 线性 | 一般非线性 | 二次 |
| 约束 | 标准QP通常为线性 | 线性 | 可以非线性 | 通常线性，也可能扩展 |
| 是否需要人建模 | 需要 | 需要 | 需要 | 需要 |
| 求解方式 | 活跃集、内点、算子分裂 | 单纯形、内点 | 梯度、SQP等 | 分支定界加QP求解 |
| 全局最优保证 | 凸QP通常可以 | 通常可以 | 取决于凸性 | 取决于模型和求解器 |
| 适用问题 | 风险、偏差、平滑 | 线性资源分配 | 复杂非线性关系 | 离散选择加二次评价 |

## 14.1 QP 与 LP

LP 的目标是线性的：

```text
3x + 5y
```

QP 的目标允许平方和乘积：

```text
x² + 2xy + y²
```

如果问题只需要固定单位成本，LP 往往足够。

如果需要惩罚偏差、波动或风险，QP 更自然。

## 14.2 QP 与 NLP

QP 是非线性规划的一种特殊形式。

它只允许目标具有二次结构，标准约束通常保持线性，因此比一般 NLP 更容易求解。

## 14.3 QP 与 MIQP

QP 通常只有连续变量。

如果还需要：

```text
是否启动
选择哪台机器
使用多少辆车
```

就需要加入整数变量，形成 MIQP。

# 15. 可以与其他算法融合的位置

## 15.1 机器学习预测参数

```text
机器学习
  ↓ 预测目标、需求或风险
QP
  ↓ 优化连续决策
最终分配或控制方案
```

机器学习输出：

- 需求预测；
- 价格预测；
- 风险矩阵；
- 未来状态。

QP 接收这些预测并计算最优决策。

## 15.2 模型预测控制 MPC

```text
当前系统状态
  ↓
预测未来状态
  ↓
构建QP
  ↓
求解一段控制序列
  ↓
只执行第一个控制动作
  ↓
获取新状态并重新求解
```

QP 在这里负责：

- 跟踪目标；
- 限制控制范围；
- 减少动作波动；
- 满足系统约束。

## 15.3 强化学习安全修正

```text
RL
  ↓ 产生建议动作
QP安全层
  ↓ 寻找距离建议动作最近的可行动作
环境
```

融合目的：

- RL 负责学习策略；
- QP 负责满足安全和资源约束。

QP 的目标可以是：

```text
最小化：

修正动作与RL原动作之间的平方距离
```

## 15.4 非线性优化中的局部子问题

```text
复杂非线性问题
  ↓ 在当前点附近近似
QP子问题
  ↓ 得到改进方向
更新原问题变量
```

序列二次规划 SQP 就使用这种思想：

- 原问题可能非线性；
- 每次构造一个局部 QP；
- 通过反复求解 QP 改善原问题。

## 15.5 启发式算法后的局部优化

```text
GA、PSO或其他启发式算法
  ↓ 提供候选连续方案
QP
  ↓ 在局部可行区域精确改进
更好的连续方案
```

QP 可以负责：

- 候选解修复；
- 局部连续变量优化；
- 平滑处理；
- 风险调整。

# 16. 最小示例

## 16.1 原始问题

工厂原计划：

```text
生产线1生产6吨
生产线2生产4吨
```

现在仍然需要生产10吨产品。

但是生产线1临时受限，最多只能生产5吨。

需要重新分配产量，同时让新方案尽量接近原计划。

## 16.2 输入数据

```text
总需求：10吨

生产线1目标：6吨
生产线2目标：4吨

生产线1最大产能：5吨
生产线2最大产能：8吨
```

## 16.3 变量

```text
x1 = 生产线1的实际产量
x2 = 生产线2的实际产量
```

这两个变量允许取小数。

## 16.4 约束

总产量必须达到10吨：

```text
x1 + x2 = 10
```

生产线1不能超过5吨：

```text
0 ≤ x1 ≤ 5
```

生产线2不能超过8吨：

```text
0 ≤ x2 ≤ 8
```

## 16.5 目标

让新方案尽量接近原计划：

```text
最小化：

(x1 - 6)² + (x2 - 4)²
```

这里：

```text
(x1 - 6)²
→ 生产线1偏离原计划的惩罚

(x2 - 4)²
→ 生产线2偏离原计划的惩罚
```

## 16.6 算法执行过程

如果没有新产能限制，最理想方案是：

```text
x1 = 6
x2 = 4
```

但这违反：

```text
x1 ≤ 5
```

因此生产线1最多只能生产5吨。

为了满足总需求：

```text
x1 + x2 = 10
```

当：

```text
x1 = 5
```

就必须：

```text
x2 = 5
```

目标值为：

```text
(5 - 6)² + (5 - 4)²
= 1 + 1
= 2
```

## 16.7 输出结果

```text
x1 = 5
x2 = 5
最小偏差目标值 = 2
```

现实含义：

```text
生产线1生产5吨
生产线2生产5吨
总产量达到10吨
在新产能限制下尽量接近原计划
```

# 17. 一句话总结

> 人负责把现实问题转换成连续变量、线性约束和二次评价目标；QP 求解器负责在可行范围中寻找偏差、风险或波动最小的连续方案；最终输出各连续变量的最优取值和对应的目标值。
