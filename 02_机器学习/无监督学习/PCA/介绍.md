# PCA
# 1. 一句话说明它是什么

> `PCA（主成分分析）` 是一种把很多相互重复的信息压缩成少量综合信息的方法，主要用于减少数据特征数量。

本文讨论最常用的**线性PCA**：用原始特征的组合生成新的综合特征。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 选择需要压缩的原始特征
  ├── 清理并统一数据尺度
  ├── 决定保留多少信息
  └── 解释压缩后的综合特征
  ↓
算法需要完成的工作
  ├── 找出数据变化最明显的方向
  ├── 按保留信息量排列这些方向
  ├── 选择前几个方向
  └── 把原始数据转换成较少的新特征
  ↓
最终结果
  ├── 压缩后的特征表
  ├── 每个新特征保留的信息比例
  └── 原始特征对新特征的贡献
```

- **人提供**：数值特征表、保留数量或信息比例。
- **算法完成**：寻找主要变化方向并转换数据。
- **算法返回**：较少的新特征及其信息保留比例。

PCA不会自动完成分类、聚类或数值预测。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 保留几个综合特征，或者保留多少信息

什么情况绝对不允许？
→ 错误数据、不同单位直接比较、使用不合适的类别编号

什么结果算更好？
→ 使用更少特征，同时尽量保留原始数据变化

哪些信息在决策前已经知道？
→ 每个对象的原始数值特征

哪些信息会随着过程变化？
→ 新样本或原始数据的整体分布
```

| 自然语言关键词 | 对应内容 |
|---|---|
| “压缩、减少特征” | 降维 |
| “信息重复、关系相近” | 相关特征 |
| “保留多少信息” | 信息保留比例 |
| “综合指标” | 主成分 |
| “贡献大小” | 原始特征权重 |
| “温度、压力、能耗” | 原始输入特征 |

“主成分”就是PCA生成的新综合特征。

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 多个原始指标 | 温度、压力、振动、能耗 |
| 建模后的算法输入 | 清理并统一尺度的数值表 | 每行一个设备 |
| 算法内部数据 | 主要变化方向、贡献权重 | 温度和能耗共同形成新特征 |
| 最终业务输出 | 较少的新特征 | 4个特征压缩成2个主成分 |

PCA不需要历史正确答案，通常属于无监督学习方法。

# 7. 完整运行流程

```text
现实数据
  ↓
选择数值特征
  ↓
清理并统一数据尺度
  ↓
PCA寻找主要变化方向
  ↓
计算各方向保留的信息量
  ↓
选择保留数量
  ↓
转换成较少的新特征
  ↓
检查信息保留比例
  ↓
交给后续算法使用
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

确定需要压缩的数据和保留目标。

### 输入

- 原始业务数据
- 后续任务要求

### 内部构成

```text
Problem_Data
├── Input_Features
├── Component_Count
└── Retained_Information_Target
```

### 处理过程

1. 选择需要压缩的数值特征。
2. 决定保留固定数量，或者保留指定比例的信息。
3. 明确压缩结果将用于什么任务。

### 输出

- 特征列表
- 保留数量或比例

### 是否需要用户自己实现

**通常需要自己完成。**

---

## 02_Data_Preparation

### 作用

把不同特征转换成可以公平比较的数据。

### 输入

- 原始特征表
- 特征列表

### 内部构成

```text
Data_Preparation
├── Missing_Value_Handling
├── Feature_Centering
└── Feature_Scaling
```

### 处理过程

1. 处理缺失和异常数据。
2. 调整各特征的中心位置。
3. 必要时统一不同特征的尺度。

### 输出

- 处理后的特征表
- 数据转换规则

### 是否需要用户自己实现

**两者都可以。**库提供工具，人负责选择处理方式。

---

## 03_Component_Extraction

### 作用

寻找主要变化方向并生成新特征。

### 输入

- 处理后的特征表
- 保留数量或比例

### 内部构成

```text
Component_Extraction
├── Variation_Analysis
├── Direction_Ranking
└── Data_Transformation
```

### 处理过程

1. 分析原始特征如何共同变化。
2. 找出保留信息最多的方向。
3. 按信息量从高到低排序。
4. 选择前几个方向。
5. 将原始数据转换成新特征。

### 输出

- 主成分
- 压缩后的特征表
- 信息保留比例
- 原始特征贡献权重

### 是否需要用户自己实现

**通常由PCA算法库提供。**

---

## 04_Result_Validation

### 作用

判断压缩是否保留了足够信息。

### 输入

- 信息保留比例
- 压缩前后的数据
- 后续任务结果

### 内部构成

```text
Result_Validation
├── Information_Check
├── Component_Inspection
└── Downstream_Comparison
```

### 处理过程

1. 检查累计保留的信息比例。
2. 查看原始特征对主成分的贡献。
3. 比较压缩前后的后续任务表现。

### 输出

- 推荐保留数量
- 信息损失情况
- 压缩后的最终数据

### 是否需要用户自己实现

**计算可由库提供；保留数量和业务解释由人决定。**

# 11. 用户需要实现什么

## 通常需要自己实现

- 选择原始特征；
- 清理数据；
- 判断是否需要统一尺度；
- 决定保留数量或信息比例；
- 解释主成分；
- 检查后续任务是否受到影响。

## 通常由算法库或求解器提供

- 分析特征之间的共同变化；
- 寻找主要方向；
- 计算信息保留比例；
- 转换训练数据；
- 使用同一规则转换新数据。

# 12. 它真正帮我解决什么

| 问题 | PCA的边界 |
|---|---|
| 帮助理解问题吗？ | 能显示数据的主要变化方向，但新特征可能不容易解释。 |
| 帮助建立模型吗？ | 能建立数据转换模型，但不是最终预测模型。 |
| 帮助搜索答案吗？ | 会寻找保留信息较多的线性方向，不搜索业务方案。 |
| 帮助预测结果吗？ | 不能直接预测类别或数值，可为预测算法准备输入。 |
| 帮助做连续决策吗？ | 不能。 |
| 帮助验证解是否可行吗？ | 不能，只能检查压缩后保留了多少信息。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 特征数量较多 | 可以减少输入维度 |
| 多个特征高度相关 | 可以压缩重复信息 |
| 数据可视化 | 可压缩到二维或三维 |
| 后续算法训练较慢 | 减少特征可降低计算量 |
| 数据噪声集中在次要方向 | 可以舍弃部分次要变化 |

| 不太适合 | 原因 |
|---|---|
| 原始特征很少 | 没有明显压缩必要 |
| 必须保留原始特征含义 | 主成分是多个特征的组合 |
| 数据关系明显非线性 | 线性PCA可能无法有效表达 |
| 类别字段很多 | 普通PCA主要处理数值数据 |
| 少量变化恰好是关键信息 | PCA可能把它当成次要信息删除 |

# 14. 与相近算法比较

| 对比项 | PCA | 特征选择 | t-SNE |
|---|---|---|---|
| 输入形式 | 数值特征表 | 特征表及可选答案 | 数值特征表 |
| 输出形式 | 新的综合特征 | 保留下来的原始特征 | 低维可视化坐标 |
| 是否生成新特征 | 是 | 否 | 是 |
| 是否需要正确答案 | 不需要 | 视方法而定 | 不需要 |
| 如何处理维度 | 组合原始特征 | 删除部分原始特征 | 保留局部邻近关系 |
| 能否稳定转换新数据 | 可以 | 可以 | 通常不是主要用途 |
| 是否保证业务可解释 | 不保证 | 相对较好 | 不保证 |
| 主要用途 | 压缩、去除重复信息 | 保留重要原始字段 | 二维或三维可视化 |

# 15. 可以与其他算法融合的位置

## 数据缩放与PCA

```text
StandardScaler
  ↓ 输出统一尺度的数据
PCA
  ↓ 输出少量主成分
```

- **融合位置**：数据准备。
- **为什么融合**：不同单位可能导致某些特征控制结果。
- **解决问题**：让各特征得到公平比较。

## PCA与聚类算法

```text
PCA
  ↓ 输出压缩后的特征
K-means或DBSCAN
  ↓ 输出群组编号
```

- **融合位置**：聚类前的数据处理。
- **为什么融合**：特征过多会影响距离判断。
- **解决问题**：减少噪声和聚类计算量。

## PCA与预测算法

```text
PCA
  ↓ 输出压缩后的特征
SVM、KNN或回归算法
  ↓ 输出类别或数值
```

- **融合位置**：预测模型的输入处理。
- **为什么融合**：原始特征多且重复。
- **解决问题**：减少训练成本和特征重复。

# 16. 最小示例

## 原始问题

两个指标几乎表达相同信息，希望压缩成一个综合指标。

## 输入数据

| 对象 | 特征A | 特征B |
|---|---:|---:|
| 1 | 1 | 1 |
| 2 | 2 | 2 |
| 3 | 3 | 3 |

## 变量或状态

- 输入：特征A、特征B；
- 输出：一个主成分；
- 保留数量：1。

## 规则或约束

- 两个特征使用相同尺度；
- 不提供类别或正确答案；
- 接受压缩后失去原始字段名称。

## 目标

把两个重复特征压缩成一个综合特征。

## 算法执行过程

```text
特征A和特征B总是一起增加
  ↓
PCA发现主要变化方向
  ↓
把两个特征组合成一个主成分
```

## 输出结果

```text
原始输入：2个特征
压缩输出：1个主成分
```

新主成分可理解为对象的“整体大小”，但具体含义仍需人解释。

# 17. 一句话总结

> 人负责选择原始特征并决定保留多少信息；`PCA`负责寻找主要变化方向并压缩数据；最终输出较少的综合特征及信息保留比例。
