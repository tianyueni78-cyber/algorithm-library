# Hierarchical Clustering
# 1. 一句话说明它是什么

> `Hierarchical Clustering（层次聚类）` 是一种把相似对象逐步合并成群组的方法，主要用于发现数据从小群组到大群组的层级关系。

本文采用最常见的**凝聚型层次聚类**：开始时每个对象各自一组，然后逐步合并。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 选择用于比较对象的信息
  ├── 统一不同信息的数值尺度
  ├── 选择群组之间的比较方式
  └── 决定最后保留几组或在哪里停止合并
  ↓
算法需要完成的工作
  ├── 计算对象之间的距离
  ├── 找到最接近的两个群组
  ├── 逐步合并群组
  └── 记录完整的合并过程
  ↓
最终结果
  ├── 群组编号
  └── 群组层级树
```

- **人提供**：对象特征、距离方式、群组比较方式。
- **算法完成**：反复寻找并合并最接近的群组。
- **算法返回**：层级树，以及按指定位置切分后的群组。

它不能自动解释群组的业务含义。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 每个对象属于哪个群组，以及群组之间有什么层级关系

什么情况绝对不允许？
→ 错误数据、禁止使用的信息、不同单位直接比较

什么结果算更好？
→ 同组对象相似，不同组差异明显，层级关系符合业务理解

哪些信息在决策前已经知道？
→ 每个对象可以用于比较的特征

哪些信息会随着过程变化？
→ 新增对象或发生变化的对象特征
```

| 自然语言关键词 | 对应内容 |
|---|---|
| “自动分组、归类” | 聚类结果 |
| “相似、接近” | 距离 |
| “逐步合并、上下级” | 层级结构 |
| “最后分成几组” | 切分位置 |
| “位置、金额、频率” | 输入特征 |

层次聚类通常不是动态算法。数据明显变化后，一般需要重新运行。

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 对象的业务记录 | 客户年龄、消费金额、频率 |
| 建模后的算法输入 | 统一尺度的数值特征 | 每行代表一个客户 |
| 算法内部数据 | 距离表、群组合并记录 | 群组A与B最接近 |
| 最终业务输出 | 群组编号和层级树 | 客户分为3组 |

层次聚类不需要历史正确答案，属于无监督学习。

# 7. 完整运行流程

```text
现实对象
  ↓
选择比较特征
  ↓
清理并统一数据尺度
  ↓
计算对象之间的距离
  ↓
每个对象先单独成为一组
  ↓
反复合并最接近的两个群组
  ↓
生成层级树
  ↓
选择切分位置
  ↓
输出最终群组
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

确定比较对象、输入特征和群组比较规则。

### 输入

- 原始业务数据
- 业务中的相似标准

### 内部构成

```text
Problem_Data
├── Input_Features
├── Distance_Metric
└── Linkage_Method
```

`Linkage Method`表示如何计算两个群组之间的距离，例如参考最近成员、最远成员或整体情况。

### 处理过程

1. 确定需要分组的对象。
2. 选择能够代表相似性的特征。
3. 选择距离和群组比较方式。

### 输出

- 特征列表
- 距离方式
- 群组比较方式

### 是否需要用户自己实现

**通常需要自己完成。**

---

## 02_Data_Preparation

### 作用

把业务记录转换成可以公平比较的数值。

### 输入

- 原始数据
- 特征列表

### 内部构成

```text
Data_Preparation
├── Missing_Value_Handling
├── Category_Encoding
└── Feature_Scaling
```

### 处理过程

1. 处理缺失和错误数据。
2. 将必要的文字信息转换成数字。
3. 统一不同特征的数值尺度。

### 输出

- 处理后的特征表
- 数据转换规则

### 是否需要用户自己实现

**两者都可以。**库提供工具，人负责判断处理是否合理。

---

## 03_Hierarchy_Building

### 作用

逐步合并群组并记录层级关系。

### 输入

- 处理后的特征表
- 距离方式
- 群组比较方式

### 内部构成

```text
Hierarchy_Building
├── Distance_Calculation
├── Closest_Group_Search
├── Group_Merge
└── Tree_Record
```

### 处理过程

1. 每个对象单独成为一组。
2. 计算群组之间的距离。
3. 合并最接近的两个群组。
4. 更新距离。
5. 重复合并，直到形成完整层级树。

### 输出

- 合并记录
- 层级树
- 指定切分位置下的群组编号

### 是否需要用户自己实现

**通常由算法库提供。**

---

## 04_Result_Validation

### 作用

选择合理的切分位置并检查群组。

### 输入

- 层级树
- 群组编号
- 原始业务数据

### 内部构成

```text
Result_Validation
├── Tree_Inspection
├── Cluster_Statistics
└── Business_Interpretation
```

### 处理过程

1. 查看层级树中的明显分界。
2. 比较不同群组数量。
3. 统计每组的特征。
4. 根据业务含义选择最终结果。

### 输出

- 最终群组编号
- 群组统计
- 业务群组名称

### 是否需要用户自己实现

**统计可由库提供；最终选择和解释由人完成。**

# 11. 用户需要实现什么

## 通常需要自己实现

- 确定分组对象；
- 选择输入特征；
- 清理并统一数据；
- 选择距离方式；
- 选择群组比较方式；
- 决定最终切成几组；
- 解释并命名群组。

## 通常由算法库或求解器提供

- 计算距离；
- 搜索最近群组；
- 合并群组；
- 记录合并顺序；
- 生成层级树数据；
- 输出群组编号。

# 12. 它真正帮我解决什么

| 问题 | 层次聚类的边界 |
|---|---|
| 帮助理解问题吗？ | 能显示对象和群组的层级关系，但业务含义需要人解释。 |
| 帮助建立模型吗？ | 能建立聚类结构，输入特征和切分位置仍由人决定。 |
| 帮助搜索答案吗？ | 能逐步搜索并合并相近群组，不是优化求解器。 |
| 帮助预测结果吗？ | 通常不用于预测新对象。 |
| 帮助做连续决策吗？ | 不能。 |
| 帮助验证解是否可行吗？ | 不能保证业务正确，只提供分组结构。 |

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 需要查看群组层级 | 保留完整合并过程 |
| 不确定分成几组 | 可以先建树，再选择切分位置 |
| 样本量较小或中等 | 距离和层级较容易计算 |
| 客户、产品或物种分类 | 可以观察对象之间的层级关系 |

| 不太适合 | 原因 |
|---|---|
| 数据量很大 | 距离计算和存储成本较高 |
| 数据频繁增加 | 新数据通常需要重新聚类 |
| 需要直接识别异常点 | DBSCAN通常更直接 |
| 特征很多 | 距离可能失去区分能力 |
| 数据未统一尺度 | 大数值特征会控制结果 |

# 14. 与相近算法比较

| 对比项 | 层次聚类 | K-Means | DBSCAN |
|---|---|---|---|
| 输入形式 | 无答案的特征数据 | 无答案的特征数据 | 无答案的特征数据 |
| 输出形式 | 层级树、群组编号 | 群组编号、群组中心 | 群组编号、异常点 |
| 是否提前指定群组数 | 建树时不需要 | 需要 | 不需要 |
| 分组方式 | 逐步合并相近群组 | 反复调整群组中心 | 从密集区域扩展 |
| 是否保留层级 | 是 | 否 | 否 |
| 是否直接识别异常点 | 否 | 否 | 是 |
| 是否保证业务正确 | 不保证 | 不保证 | 不保证 |
| 是否追求全局最优 | 否 | 通常不能保证 | 否 |
| 适用问题 | 层级关系分析 | 近似圆形的明确分组 | 不规则群组和异常检测 |

# 15. 可以与其他算法融合的位置

## 降维与层次聚类

```text
PCA等降维算法
  ↓ 输出较少的关键特征
层次聚类
  ↓ 输出层级树和群组
业务分析
```

- **融合位置**：数据准备。
- **为什么融合**：特征过多会影响距离。
- **解决问题**：减少噪声和计算量。

## 层次聚类与分类算法

```text
层次聚类
  ↓ 输出群组编号
分类算法
  ↓ 学习如何判断新对象属于哪个群组
```

- **融合位置**：新对象预测。
- **为什么融合**：层次聚类通常没有直接预测新对象的标准接口。
- **解决问题**：让后续新对象可以获得群组预测。

## 层次聚类与群组分析

```text
层次聚类
  ↓ 输出不同切分位置
群组评价方法
  ↓ 选择最终群组数量
```

- **融合位置**：结果验证。
- **为什么融合**：算法生成层级，但最终切在哪里需要判断。
- **解决问题**：减少完全依靠人工选择。

# 16. 最小示例

## 原始问题

根据一维位置，把4个对象逐步分组。

## 输入数据

```text
A = 1
B = 2
C = 8
D = 9
```

## 变量或状态

- 输入：每个对象的位置；
- 输出：层级关系和最终群组。

## 规则或约束

- 使用相同位置单位；
- 距离近的群组优先合并；
- 不提供正确分组答案。

## 目标

找出对象之间从近到远的分组层级。

## 算法执行过程

```text
开始：
{A} {B} {C} {D}

第一次合并：
{A,B} {C} {D}

第二次合并：
{A,B} {C,D}

第三次合并：
{A,B,C,D}
```

在第二次合并后切分：

```text
群组0：A、B
群组1：C、D
```

## 输出结果

- 完整合并顺序；
- 两个最终群组；
- 每个对象的群组编号。

# 17. 一句话总结

> 人负责选择比较特征、距离方式和切分位置；`Hierarchical Clustering`负责逐步合并相近对象并记录层级；最终输出层级树和群组编号。
