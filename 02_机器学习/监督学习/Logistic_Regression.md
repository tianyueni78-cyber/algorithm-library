# Logistic Regression
# 1. 一句话说明它是什么

> `Logistic Regression（逻辑回归）` 是一种把多项信息合成一个概率的方法，主要用于判断对象属于哪个类别。

虽然名字中有“回归”，它通常用于**分类**，例如：

- 是否违约；
- 是否故障；
- 是否购买。

---

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 明确要判断什么
  ├── 提供带正确答案的历史案例
  ├── 选择预测时可获得的信息
  └── 确定多大概率算“是”
  ↓
算法需要完成的工作
  ├── 学习每项信息的影响大小
  ├── 计算新案例属于某类的概率
  └── 根据概率门槛给出类别
  ↓
最终结果
  ├── 预测概率
  └── 预测类别
```

- **人提供**：历史案例、正确类别、输入特征、分类门槛。
- **算法执行**：学习输入信息与类别之间的关系。
- **算法返回**：属于某个类别的概率及最终类别。

它不能自动判断数据是否合法，也不能证明因果关系。

---

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 输出类别，例如“故障/正常”

什么情况绝对不允许？
→ 禁用数据、业务规则、结果使用限制

什么结果算更好？
→ 分类更准确，或漏判、误判更少

哪些信息在决策前已经知道？
→ 可用于判断的输入特征

哪些信息会随着过程变化？
→ 客户、设备或环境的最新状态
```

## 关键词对应关系

| 自然语言关键词 | 对应内容 |
|---|---|
| “是否、会不会、有无” | 二分类输出 |
| “属于哪一类” | 多分类输出 |
| “可能性、风险多大” | 概率输出 |
| “根据、考虑、已知” | 输入特征 |
| “实际是否发生” | 历史正确答案 |
| “超过70%就报警” | 分类门槛 |
| “少漏报、少误报” | 评价指标 |

“特征”就是判断依据，例如温度、振动和运行时间。

---

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 历史业务记录 | 温度、振动、是否故障 |
| 建模后的算法输入 | 数值特征和类别答案 | `X=设备信息，y=故障/正常` |
| 算法内部数据 | 各项特征的影响系数 | 温度升高会提高多少故障倾向 |
| 最终业务输出 | 概率和类别 | 故障概率80%，判为故障 |

通常把两个类别记为：

```text
0 → 正常
1 → 故障
```

这只是算法编码，不代表类别本身有大小关系。

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

明确要判断什么、使用什么信息。

### 输入

- 现实问题
- 历史记录
- 业务要求

### 内部构成

```text
Problem_Data
├── Target_Class
├── Input_Features
└── Decision_Threshold
```

### 处理过程

1. 定义类别。
2. 选择预测前可获得的信息。
3. 排除泄露答案的数据。
4. 确定漏判和误判的代价。

### 输出

- 类别定义
- 特征列表
- 评价标准

### 是否需要用户自己实现

**通常需要自己实现。**

---

## 02_Data_Preparation

### 作用

把业务记录转换成算法可读取的数字表格。

### 输入

- 原始数据
- 类别答案
- 特征列表

### 内部构成

```text
Data_Preparation
├── Data_Cleaning
├── Category_Encoding
└── Feature_Scaling
```

### 处理过程

1. 处理缺失值和异常值。
2. 将文字类别转换成数字。
3. 必要时统一特征尺度。
4. 划分训练集和测试集。

### 输出

- 训练数据
- 测试数据

### 是否需要用户自己实现

**两者都可以。**库提供工具，人负责判断处理方式。

---

## 03_Model_Training

### 作用

学习每项输入对分类结果的影响。

### 输入

- 训练特征
- 历史正确类别
- 模型设置

### 内部构成

```text
Model_Training
├── Score_Calculation
├── Probability_Conversion
└── Coefficient_Adjustment
```

### 处理过程

1. 给每项输入分配一个影响系数。
2. 合成一个分类分数。
3. 把分数转换成0到1之间的概率。
4. 调整系数，使历史预测尽量接近真实类别。

### 输出

- 训练好的模型
- 各特征的影响系数

### 是否需要用户自己实现

**通常由算法库提供。**

---

## 04_Prediction

### 作用

把新案例转换成概率和类别。

### 输入

- 训练好的模型
- 新案例
- 分类门槛

### 内部构成

```text
Prediction
├── Probability_Prediction
├── Threshold_Check
└── Class_Output
```

### 处理过程

1. 计算新案例属于目标类别的概率。
2. 将概率与门槛比较。
3. 输出最终类别。

例如：

```text
故障概率 = 80%
门槛 = 60%
80% > 60% → 判为故障
```

### 输出

- 预测概率
- 预测类别

### 是否需要用户自己实现

**概率计算由库提供；门槛和业务动作由用户决定。**

---

## 05_Evaluation

### 作用

检查模型的漏判和误判情况。

### 输入

- 测试数据
- 真实类别
- 预测结果

### 内部构成

```text
Evaluation
├── Accuracy_Check
├── Error_Analysis
└── Threshold_Selection
```

### 处理过程

1. 比较预测类别和真实类别。
2. 分别统计漏判与误判。
3. 尝试不同概率门槛。
4. 选择符合业务要求的门槛。

### 输出

- 准确率等指标
- 漏判和误判数量
- 推荐门槛

### 是否需要用户自己实现

**指标计算由库提供；门槛选择需要人完成。**

# 12. 它真正帮我解决什么

| 问题 | 逻辑回归的边界 |
|---|---|
| 帮助理解问题吗？ | 可以显示各项信息如何影响分类倾向，但不能证明因果。 |
| 帮助建立模型吗？ | 可以建立分类模型；类别和输入仍由人定义。 |
| 帮助搜索答案吗？ | 会寻找合适的系数，但不是排产或路径优化算法。 |
| 帮助预测结果吗？ | 可以，主要输出类别概率。 |
| 帮助做连续决策吗？ | 通常不能，只完成一次输入对应的一次判断。 |
| 帮助验证解是否可行吗？ | 不能保证业务可行，只能评价分类效果。 |

它不会自动：

- 收集正确数据；
- 选择合法特征；
- 决定概率门槛；
- 处理复杂业务约束；
- 证明某个因素导致结果发生。

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 是否违约、是否故障 | 适合二分类 |
| 需要风险概率 | 可以直接输出概率 |
| 需要较容易解释的模型 | 可以查看特征影响方向 |
| 需要快速建立基准模型 | 训练和预测通常较快 |
| 输入与分类倾向关系较简单 | 符合模型特点 |

| 不太适合 | 原因 |
|---|---|
| 预测房价等连续数值 | 应使用线性回归等方法 |
| 类别边界非常复杂 | 简单模型可能表达不足 |
| 图片、语音直接分类 | 通常需要先提取特征 |
| 数据中异常值很多 | 可能影响模型系数 |
| 必须证明因果关系 | 预测关系不等于因果关系 |
| 必须满足复杂硬约束 | 需要额外规则或优化算法 |

# 14. 与相近算法比较

| 对比项 | 逻辑回归 | 线性回归 | 决策树分类 |
|---|---|---|---|
| 输入形式 | 表格特征 | 表格特征 | 表格特征 |
| 输出形式 | 类别概率 | 连续数值 | 类别或概率 |
| 是否需要历史答案 | 需要 | 需要 | 需要 |
| 如何学习 | 学习分类概率公式 | 学习数值预测公式 | 学习分段判断规则 |
| 是否保证业务可行 | 不保证 | 不保证 | 不保证 |
| 是否追求业务最优方案 | 否 | 否 | 否 |
| 关系特点 | 较平滑的分类边界 | 线性数值关系 | 分段、非线性关系 |
| 适用问题 | 是否发生 | 具体是多少 | 复杂规则分类 |

最关键区别：

```text
线性回归 → 预测“多少”
逻辑回归 → 预测“属于某类的概率”
```

# 15. 可以与其他算法融合的位置

## 特征提取与逻辑回归

```text
文本或图片处理算法
  ↓ 输出数值特征
逻辑回归
  ↓ 输出类别概率
业务系统
```

- **融合位置**：数据准备模块。
- **为什么融合**：逻辑回归不能直接理解原始文本或图片。
- **前者输出**：数值特征。
- **逻辑回归接收**：特征表。
- **解决问题**：完成文本或图片分类。

## 特征选择与逻辑回归

```text
Lasso等特征选择方法
  ↓ 保留重要特征
逻辑回归
  ↓ 输出概率
```

- **融合位置**：训练模块。
- **为什么融合**：输入过多时，模型可能不稳定。
- **前者输出**：较少的重要特征。
- **逻辑回归接收**：筛选后的数据。
- **解决问题**：简化模型并减少无关信息。

## 逻辑回归与优化算法

```text
逻辑回归
  ↓ 输出故障或违约概率
优化算法
  ↓ 在约束下安排资源
最终决策
```

- **融合位置**：优化算法的输入或风险评价。
- **为什么融合**：逻辑回归负责预测风险，不负责安排资源。
- **逻辑回归输出**：风险概率。
- **优化算法接收**：风险概率、成本和约束。
- **解决问题**：把“风险预测”转化为“行动方案”。

# 16. 最小示例

## 原始问题

根据设备温度判断是否需要故障检查。

## 输入数据

| 温度 | 实际状态 |
|---:|---|
| 40℃ | 正常 |
| 50℃ | 正常 |
| 70℃ | 故障 |
| 80℃ | 故障 |

## 变量或状态

- 输入：温度；
- 输出：故障概率和类别。

## 规则或约束

- 只使用检查前测得的温度；
- 故障概率达到60%时报警；
- 报警结果不能代替强制安全规则。

## 目标

尽量正确识别故障，同时减少漏报。

## 算法执行过程

算法从历史数据中学习到：

```text
温度越高 → 故障概率通常越高
```

对于新设备：

```text
温度 = 75℃
算法计算故障概率 = 85%
报警门槛 = 60%
```

因为：

```text
85% > 60%
```

## 输出结果

```text
故障概率：85%
预测类别：故障
业务动作：触发检查
```

真实概率必须由实际数据训练得到，不能仅凭这四条记录确定。

# 17. 一句话总结

> 人负责定义类别、准备历史数据并设定判断门槛；`Logistic Regression`负责学习各项输入与类别之间的关系；最终输出类别概率和预测类别。
