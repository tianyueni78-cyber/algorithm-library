# LightGBM
# 1. 一句话说明它是什么

> `LightGBM` 是一种让许多小决策树不断纠正前面错误的算法，主要用于根据表格数据预测类别、概率或数值。

本文讨论微软开源的机器学习算法 LightGBM，而不是某个软件界面。

---

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 明确要预测什么
  ├── 提供带答案的历史数据
  ├── 选择预测时可获得的信息
  └── 确定评价标准和业务规则
  ↓
算法需要完成的工作
  ├── 训练第一棵小树
  ├── 找出预测错误
  ├── 用后续树不断纠错
  └── 汇总所有树的结果
  ↓
最终结果
  ├── 类别或概率
  └── 数值预测
```

- **人提供**：历史案例、正确答案、输入特征和训练参数。
- **算法完成**：连续训练多棵树，让后面的树修正前面的错误。
- **算法返回**：训练模型、预测结果和特征重要性等辅助信息。

它不能替人决定预测目标是否合法、数据是否可靠。

---

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 要预测的类别、概率或数值

什么情况绝对不允许？
→ 禁用数据、业务规则、结果使用限制

什么结果算更好？
→ 准确率更高、漏判更少、数值误差更小

哪些信息在决策前已经知道？
→ 可以提供给模型的输入特征

哪些信息会随着过程变化？
→ 客户、设备、市场等随时间变化的数据
```

## 自然语言关键词对应关系

| 关键词 | 对应内容 |
|---|---|
| “是否、哪一类” | 分类输出 |
| “概率多大” | 概率输出 |
| “多少、价格、时间” | 数值输出 |
| “根据、已知、考虑” | 输入特征 |
| “实际结果、历史答案” | 正确答案，也叫标签 |
| “必须、禁止、不能使用” | 业务规则 |
| “准确、少漏判、误差低” | 评价指标 |

LightGBM不是排产求解器。这里的“目标”通常是**预测得更准**，不是直接寻找最优调度方案。

---

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 现实中的历史记录 | 客户收入、欠款、是否违约 |
| 建模后的算法输入 | 整理后的特征表和正确答案 | `X=客户特征，y=是否违约` |
| 算法内部数据 | 多棵树、分裂条件、纠错信息 | “负债率大于60%” |
| 最终业务输出 | 类别、概率或数值 | 违约概率82% |

LightGBM主要处理一行一个案例、一列一个特征的表格数据。

# 7. 完整运行流程

```text
现实问题
  ↓
明确预测目标
  ↓
整理历史数据
  ↓
划分训练集和测试集
  ↓
训练第一棵小树
  ↓
后续小树不断纠正错误
  ↓
组合所有树的预测
  ↓
用测试数据验证
  ↓
输出类别、概率或数值
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

确定预测对象、可用信息和评价标准。

### 输入

- 业务问题
- 历史记录
- 业务要求

### 内部构成

```text
Problem_Data
├── Prediction_Target
├── Input_Features
└── Evaluation_Rule
```

### 处理过程

1. 明确预测类别还是数值。
2. 选择预测前真正可获得的信息。
3. 排除泄露答案的数据。
4. 确定什么错误最严重。

### 输出

- 预测目标
- 特征列表
- 评价指标

### 是否需要用户自己实现

**通常需要自己实现。**

---

## 02_Data_Preparation

### 作用

把业务记录整理成模型可以读取的表格。

### 输入

- 原始数据
- 特征列表
- 正确答案

### 内部构成

```text
Data_Preparation
├── Data_Cleaning
├── Category_Handling
└── Dataset_Split
```

### 处理过程

1. 处理错误和缺失数据。
2. 标记文字类别列。
3. 划分训练集、验证集和测试集。

LightGBM通常不要求把所有数值缩放到相同范围。

### 输出

- 训练数据
- 验证数据
- 测试数据

### 是否需要用户自己实现

**两者都需要。**库负责格式转换，人负责判断数据是否合理。

---

## 03_Model_Training

### 作用

训练多棵树，让后面的树持续修正已有错误。

### 输入

- 训练数据
- 正确答案
- 训练参数

### 内部构成

```text
Model_Training
├── Tree_Building
├── Error_Correction
└── Stop_Control
```

### 处理过程

1. 建立一棵小树。
2. 检查哪些案例预测得不好。
3. 下一棵树重点修正这些错误。
4. 重复训练并累加结果。
5. 验证效果不再改善时停止。

### 输出

- LightGBM模型
- 训练记录

### 是否需要用户自己实现

**核心训练由LightGBM库提供；参数和停止规则由用户设置。**

---

## 04_Prediction

### 作用

使用全部树共同预测新案例。

### 输入

- 训练好的模型
- 新案例

### 内部构成

```text
Prediction
├── Tree_Predictions
├── Result_Combination
└── Business_Output
```

### 处理过程

1. 新案例经过每棵树。
2. 每棵树给出一小部分结果。
3. 汇总所有树的结果。
4. 转换成类别、概率或数值。

### 输出

- 预测结果
- 可选的预测概率

### 是否需要用户自己实现

**预测计算由库提供；业务结果转换通常由用户实现。**

---

## 05_Evaluation

### 作用

确认模型面对没见过的数据是否可靠。

### 输入

- 测试数据
- 真实答案
- 模型预测

### 内部构成

```text
Evaluation
├── Metric_Calculation
├── Error_Analysis
└── Explanation
```

### 处理过程

1. 比较预测和真实结果。
2. 计算准确率、漏判率或数值误差。
3. 查看错误案例。
4. 分析模型主要参考了哪些特征。

### 输出

- 评价指标
- 错误案例
- 特征重要性

### 是否需要用户自己实现

**计算可由库提供；业务解释必须由人完成。**

# 10. 推荐代码结构

## 最小版本

```text
LightGBM_Project
├── data.csv
└── main.py
```

- `data.csv`：历史数据。
- `main.py`：数据划分、训练、预测和评价。

## 完整版本

```text
LightGBM_Project
├── data
│   ├── raw.csv
│   └── processed.csv
├── prepare_data.py
├── train.py
├── predict.py
├── evaluate.py
└── model.txt
```

- `prepare_data.py`：清理和转换数据。
- `train.py`：训练并保存模型。
- `predict.py`：预测新案例。
- `evaluate.py`：计算指标并分析错误。
- `model.txt`：保存训练好的树模型。

小项目使用一个文件即可，不必强行拆分。

# 11. 用户需要实现什么

## 通常需要自己实现

- 定义预测目标；
- 收集并检查数据；
- 选择可用特征；
- 防止答案泄露；
- 选择评价指标；
- 设置基本训练参数；
- 确定预测结果如何进入业务流程。

## 通常由算法库或求解器提供

- 建立多棵树；
- 计算每轮需要纠正的错误；
- 快速寻找分裂条件；
- 组合所有树的预测；
- 提前停止训练；
- 输出特征重要性。

LightGBM库提供训练能力，但不会自动完成正确的业务建模。

# 12. 它真正帮我解决什么

| 问题 | LightGBM的边界 |
|---|---|
| 帮助理解问题吗？ | 可以展示特征重要性，但不能证明真实原因。 |
| 帮助建立模型吗？ | 能建立预测模型，但目标和输入仍由人定义。 |
| 帮助搜索答案吗？ | 会搜索较好的树结构，但不是通用优化求解器。 |
| 帮助预测结果吗？ | 可以，这是它的主要用途。 |
| 帮助做连续决策吗？ | 通常不能；它一般对一次输入完成一次预测。 |
| 帮助验证解是否可行吗？ | 不能保证业务可行，只能评估预测表现。 |

它不能自动保证：

- 数据正确；
- 预测公平；
- 结论具有因果关系；
- 未来环境与历史环境相同；
- 输出满足排产、容量等硬性规则。

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 客户风险预测 | 擅长复杂的表格数据关系 |
| 设备故障预测 | 能结合多种设备指标 |
| 销量、价格预测 | 可以预测数值 |
| 大量表格数据 | 训练速度通常较快 |
| 特征关系复杂 | 多棵树可以表达非线性关系 |

| 不太适合 | 原因 |
|---|---|
| 数据量极少 | 容易学到偶然规律 |
| 直接处理原始图片或语音 | 神经网络通常更合适 |
| 必须获得简单规则 | 多棵树不容易人工阅读 |
| 必须证明因果关系 | 它学习的是预测规律 |
| 必须满足复杂硬约束 | 需要额外优化算法或规则检查 |
| 环境频繁突变 | 历史规律可能迅速失效 |

# 14. 与相近算法比较

| 对比项 | LightGBM | XGBoost | 随机森林 |
|---|---|---|---|
| 输入形式 | 表格特征和答案 | 表格特征和答案 | 表格特征和答案 |
| 输出形式 | 类别、概率或数值 | 类别、概率或数值 | 类别、概率或数值 |
| 是否需要人写预测公式 | 不需要 | 不需要 | 不需要 |
| 如何学习 | 后一棵树纠正前面的错误 | 后一棵树纠正前面的错误 | 多棵树独立训练后投票 |
| 训练特点 | 通常速度快、内存占用较低 | 通常稳定、工具成熟 | 参数相对容易理解 |
| 是否保证业务可行 | 不保证 | 不保证 | 不保证 |
| 是否保证绝对最优 | 不保证 | 不保证 | 不保证 |
| 适用问题 | 较大规模表格数据 | 通用表格预测 | 基线模型和稳定预测 |

LightGBM和XGBoost最接近；随机森林的树之间主要是并行投票，不是连续纠错。

# 15. 可以与其他算法融合的位置

## 特征提取与LightGBM

```text
文本、图片或时间序列处理算法
  ↓ 输出表格特征
LightGBM
  ↓ 输出预测概率或数值
业务系统
```

- **融合位置**：数据准备模块。
- **为什么融合**：LightGBM擅长表格，不直接理解原始图片或文本。
- **前者输出**：数值特征。
- **LightGBM接收**：特征表。
- **解决问题**：让复杂原始数据可以参与预测。

## 参数优化与LightGBM

```text
贝叶斯优化
  ↓ 提供候选参数
LightGBM
  ↓ 返回验证成绩
贝叶斯优化
```

- **融合位置**：训练模块。
- **为什么融合**：树数量、深度等参数会影响效果。
- **优化算法输出**：候选参数。
- **LightGBM输出**：对应的验证成绩。
- **解决问题**：减少人工试参数。

## LightGBM与优化算法

```text
LightGBM
  ↓ 预测订单时间、故障概率或需求量
调度优化算法
  ↓ 生成满足约束的方案
最终决策
```

- **融合位置**：目标评价或输入预测模块。
- **为什么融合**：LightGBM会预测，但不会自动安排资源。
- **LightGBM输出**：未来数值或风险概率。
- **优化算法接收**：预测结果、容量和业务约束。
- **解决问题**：把“预测未来”转换成“安排下一步”。

# 16. 最小示例

## 原始问题

根据设备温度和振动判断是否会故障。

## 输入数据

| 温度 | 振动 | 是否故障 |
|---:|---:|---|
| 40 | 2 | 否 |
| 45 | 3 | 否 |
| 80 | 7 | 是 |
| 85 | 8 | 是 |

新设备状态：

```text
温度：78
振动：7
```

## 变量或状态

- 输入：温度、振动；
- 输出：故障或正常。

## 规则或约束

- 只能使用预测前已经测得的数据；
- 不能把维修结果作为输入；
- 输出不能直接代替停机安全规则。

## 目标

尽量正确识别故障设备。

## 算法执行过程

为了便于手工理解，假设只训练两棵小树：

```text
第1棵树：
温度 > 60？
├── 是 → 增加故障分数
└── 否 → 降低故障分数

第2棵树：
振动 > 5？
├── 是 → 继续增加故障分数
└── 否 → 降低故障分数
```

新设备满足：

```text
温度 > 60
振动 > 5
```

两棵树都提高故障判断分数。

## 输出结果

```text
预测：可能故障
例如：故障概率90%
```

真实LightGBM通常包含很多棵树，具体概率必须由实际训练得到。
