# KNN
# 1. 一句话说明它是什么

> `KNN（K-近邻）` 是一种参考“最相似的几个历史案例”来判断新案例的方法，主要用于分类或预测数值。

本文采用机器学习中的 KNN：

- **分类 KNN**：预测类别，例如水果种类。
- **回归 KNN**：预测数值，例如房屋价格。

其中 `K` 表示参考几个邻居。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 明确要预测什么
  ├── 提供带正确答案的历史案例
  ├── 选择可以比较的特征
  └── 决定参考几个邻居，即 K
  ↓
算法需要完成的工作
  ├── 比较新案例与历史案例的距离
  ├── 找出最近的 K 个案例
  └── 根据邻居的答案生成预测
  ↓
最终结果
  ├── 类别或数值
  └── 可选：最近邻居及其距离
```

- **人提供**：历史案例、正确答案、新案例、K值及比较方法。
- **算法执行**：寻找最相似的 K 个历史案例。
- **算法返回**：预测类别、数值或类别概率。

KNN不能替人判断“哪些特征真正代表相似”。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 要预测的类别或数值

什么情况绝对不允许？
→ 禁用的数据、输入格式和业务规则

什么结果算更好？
→ 分类正确率、漏判率或数值误差

哪些信息在决策前已经知道？
→ 新对象的特征和带答案的历史案例

哪些信息会随着过程变化？
→ 历史案例、新案例及数据分布
```

## 关键词对应关系

| 自然语言关键词 | 建模含义 |
|---|---|
| “判断、识别、属于哪类” | 分类输出 |
| “预测多少、估计价格” | 数值输出 |
| “根据、参考、比较” | 输入特征 |
| “相似、接近” | 距离计算方式 |
| “附近几个、参考几个” | K值 |
| “必须、不能、禁止” | 业务规则 |
| “准确、少漏判、误差小” | 评价指标 |
| “历史上实际是什么” | 正确答案，也叫标签 |

这里的“距离”不是只能指米数，而是两个案例在特征上有多大差别。

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 现实中的历史记录 | 水果重量、颜色和种类 |
| 建模后的算法输入 | 数值化并统一尺度的数据 | 重量=150，颜色深度=7 |
| 算法内部数据 | 新案例到历史案例的距离 | 与案例A距离1.2 |
| 最终业务输出 | 类别、数值或概率 | 苹果；苹果概率67% |

KNN通常需要两类输入：

- 历史案例及其正确答案；
- 一个需要预测的新案例。

# 7. 完整运行流程

```text
现实问题
  ↓
确定预测目标和比较特征
  ↓
清理数据并统一数值尺度
  ↓
保存历史案例
  ↓
输入新案例
  ↓
计算它与历史案例的距离
  ↓
选出最近的 K 个邻居
  ↓
投票或取平均值
  ↓
验证预测效果
  ↓
输出业务结果
```

KNN几乎没有传统的“训练过程”：它主要是保存历史数据，预测时再进行比较。

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

确定预测目标以及判断“相似”的依据。

### 输入

- 现实问题
- 历史记录
- 业务要求

### 内部构成

```text
Problem_Data
├── Prediction_Target
├── Input_Features
└── Business_Rules
```

### 处理过程

1. 明确预测类别还是数值。
2. 选择预测前可以获得的特征。
3. 排除泄露正确答案的信息。

### 输出

- 特征列表
- 正确答案
- 业务规则

### 是否需要用户自己实现

**通常需要自己实现。**算法库不知道业务中什么叫“相似”。

---

## 02_Data_Preparation

### 作用

把不同单位的数据转换成可以公平比较的形式。

### 输入

- 原始特征
- 缺失或异常记录

### 内部构成

```text
Data_Preparation
├── Data_Cleaning
├── Category_Encoding
└── Feature_Scaling
```

### 处理过程

1. 处理缺失值和错误数据。
2. 把文字类别转成数值。
3. 统一不同特征的尺度。

例如，年龄只有几十，而收入可能有几万。不处理时，收入可能完全控制距离。

### 输出

- 处理后的历史数据
- 同样方式处理的新数据

### 是否需要用户自己实现

**两者都可以。**库提供处理工具，但人必须决定处理方式。

---

## 03_Neighbor_Search

### 作用

找出与新案例最接近的 K 个历史案例。

### 输入

- 历史案例
- 新案例
- K值
- 距离计算方式

### 内部构成

```text
Neighbor_Search
├── Distance_Calculation
├── Distance_Sorting
└── Top_K_Selection
```

### 处理过程

1. 计算新案例与每个历史案例的差别。
2. 按距离从小到大排列。
3. 选择最近的 K 个案例。

### 输出

- K个邻居
- 对应距离
- 邻居的正确答案

### 是否需要用户自己实现

**通常由算法库提供。**

---

## 04_Prediction

### 作用

根据邻居的答案形成最终预测。

### 输入

- K个邻居的答案
- 邻居距离

### 内部构成

```text
Prediction
├── Neighbor_Voting
├── Distance_Weighting
└── Result_Output
```

### 处理过程

分类时：

1. 统计每个类别出现多少次。
2. 通常选择票数最多的类别。

回归时：

1. 读取邻居的数值。
2. 通常计算平均值。

也可以让距离更近的邻居拥有更大权重。

### 输出

- 预测类别或数值
- 可选的类别比例

### 是否需要用户自己实现

**通常由算法库提供。**

---

## 05_Evaluation

### 作用

检查K值、特征和预测方法是否合适。

### 输入

- 测试案例
- 真实答案
- 预测答案

### 内部构成

```text
Evaluation
├── Metric_Calculation
├── K_Comparison
└── Error_Analysis
```

### 处理过程

1. 用测试案例进行预测。
2. 比较预测与真实答案。
3. 尝试不同K值。
4. 检查错误案例及邻居是否合理。

### 输出

- 准确率或数值误差
- 推荐的K值
- 错误案例

### 是否需要用户自己实现

**指标计算可由库完成；指标选择和结果判断由人完成。**

# 10. 推荐代码结构

## 最小版本

```text
KNN_Project
├── data.csv
└── main.py
```

- `data.csv`：历史案例及正确答案。
- `main.py`：数据处理、KNN预测和评价。

## 完整版本

```text
KNN_Project
├── data
│   ├── raw.csv
│   └── processed.csv
├── prepare_data.py
├── train.py
├── predict.py
├── evaluate.py
└── model.joblib
```

- `prepare_data.py`：清理、转换并统一数据尺度。
- `train.py`：确定参数并保存历史数据和处理规则。
- `predict.py`：寻找邻居并输出预测。
- `evaluate.py`：比较K值和预测效果。
- `model.joblib`：保存KNN及数据处理设置。

小项目使用一个 `main.py` 通常就够了。

# 11. 用户需要实现什么

## 通常需要自己实现

- 定义预测目标；
- 收集带答案的历史案例；
- 选择代表相似性的特征；
- 清理数据；
- 选择评价指标；
- 判断错误预测的业务影响；
- 决定预测结果如何使用。

## 通常由算法库或求解器提供

- 距离计算；
- 最近邻搜索；
- 分类投票；
- 回归平均；
- 距离加权；
- 常见评价指标。

例如，`scikit-learn` 可以执行KNN，但不会自动判断哪些业务特征应该参与距离计算。

# 12. 它真正帮我解决什么

| 问题 | KNN的实际边界 |
|---|---|
| 帮助理解问题吗？ | 可以查看它参考了哪些邻居，但不能自动解释真实原因。 |
| 帮助建立模型吗？ | 只完成相似案例比较；目标、特征和相似标准仍由人确定。 |
| 帮助搜索答案吗？ | 会从历史数据中搜索最近邻居，但不是求解排产等优化问题。 |
| 帮助预测结果吗？ | 可以，这是主要用途。 |
| 帮助做连续决策吗？ | 通常不能；它一般处理一次输入并给出一次预测。 |
| 帮助验证解是否可行吗？ | 不能保证业务可行，只能评估预测是否准确。 |

KNN尤其不能：

- 证明因果关系；
- 自动发现合理的业务特征；
- 在没有相似历史案例时可靠预测；
- 自动适应突然变化的新环境。

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 数据量较小的分类 | 方法直接，容易使用 |
| 相似案例通常结果相似 | 符合KNN的基本思路 |
| 推荐相似商品或案例 | 可以直接搜索邻居 |
| 需要查看参考案例 | 预测依据比较直观 |
| 类别边界不规则 | 不要求用一条直线分开 |

| 不太适合 | 原因 |
|---|---|
| 数据量非常大 | 每次预测都可能要搜索大量记录 |
| 特征非常多 | 案例之间的距离会变得不可靠 |
| 各特征单位没有统一 | 大数值特征会控制结果 |
| 类别数量严重不平衡 | 多数类别容易占据邻居 |
| 实时预测要求极高 | 查询邻居可能较慢 |
| 没有相似历史案例 | 缺少可靠参考对象 |

# 14. 与相近算法比较

| 对比项 | KNN | K-Means | 决策树 |
|---|---|---|---|
| 输入形式 | 特征及正确答案 | 只有特征 | 特征及正确答案 |
| 输出形式 | 类别或数值 | 数据分组 | 类别或数值 |
| 是否需要正确答案 | 需要 | 不需要 | 需要 |
| 如何学习 | 保存案例，预测时找邻居 | 自动寻找若干组的中心 | 学习连续判断规则 |
| 是否产生明确模型 | 没有紧凑规则模型 | 产生若干组中心 | 产生判断树 |
| 是否保证业务可行 | 不保证 | 不保证 | 不保证 |
| 是否追求绝对最优 | 不保证 | 不保证 | 不保证 |
| 适用问题 | 根据相似案例预测 | 探索数据自然分组 | 学习可查看的判断规则 |

最容易混淆的是：

- **KNN**：已知历史答案，预测新案例。
- **K-Means**：没有历史答案，只是把相似对象分组。

# 15. 可以与其他算法融合的位置

## 特征提取与KNN

```text
图片或文本处理算法
  ↓ 输出数值特征
KNN
  ↓ 输出类别或相似案例
业务系统
```

- **为什么融合**：KNN不能直接理解原始图片或文本。
- **融合模块**：数据准备。
- **前一个算法输出**：表示内容特点的数字。
- **KNN接收**：这些数字。
- **解决问题**：实现图片识别或文本分类。

## 降维与KNN

“降维”就是把大量重复信息压缩成较少的关键特征。

```text
PCA等降维算法
  ↓ 输出少量关键特征
KNN
  ↓ 搜索最近邻居
预测结果
```

- **为什么融合**：特征太多时，距离容易失去意义。
- **融合模块**：特征处理。
- **降维算法输出**：压缩后的特征。
- **KNN接收**：更少、更集中的特征。
- **解决问题**：减少噪声并提高搜索速度。

## 参数搜索与KNN

```text
参数搜索
  ↓ 提供K值和距离设置
KNN
  ↓ 返回验证成绩
参数搜索
```

- **为什么融合**：K太小容易受噪声影响，K太大容易忽略局部差异。
- **融合模块**：参数选择。
- **参数搜索输出**：候选K值。
- **KNN输出**：每个设置的验证成绩。
- **解决问题**：选择更合适的K值。

# 16. 最小示例

## 原始问题

根据重量判断一个新水果是苹果还是橙子。

## 输入数据

| 水果 | 重量 | 正确种类 |
|---|---:|---|
| A | 100克 | 苹果 |
| B | 120克 | 苹果 |
| C | 180克 | 橙子 |
| D | 200克 | 橙子 |

新水果重量：`130克`。

## 变量或状态

- 输入特征：重量；
- 输出：苹果或橙子；
- K值：3。

## 规则或约束

- 只能使用重量进行比较；
- 参考最近的3个水果；
- 选择邻居中数量最多的种类。

## 目标

正确判断新水果的种类。

## 算法执行过程

计算重量差：

| 历史水果 | 重量差 | 种类 |
|---|---:|---|
| B | 10克 | 苹果 |
| A | 30克 | 苹果 |
| C | 50克 | 橙子 |
| D | 70克 | 橙子 |

最近3个邻居：

```text
B → 苹果
A → 苹果
C → 橙子
```

投票结果：

```text
苹果：2票
橙子：1票
```

## 输出结果

```text
预测：苹果
```

这个结果可以手工检查，但只根据重量判断水果，在真实应用中可能不够可靠。

# 17. 一句话总结

> 人负责定义什么叫相似、提供历史案例并选择K值；`KNN`负责找到最接近的K个案例并汇总它们的答案；最终输出预测类别、数值或相似案例。
