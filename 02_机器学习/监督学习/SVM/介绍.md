# SVM
# 1. 一句话说明它是什么

> `SVM（支持向量机）` 是一种在不同类别之间寻找尽可能宽的分界线的方法，主要用于分类，也可以预测连续数值。

本文重点讲分类型 SVM；用于数值预测的版本叫 `SVR`。

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 明确要判断的类别
  ├── 提供带正确答案的历史案例
  ├── 选择用于判断的信息
  └── 决定如何处理误判和复杂边界
  ↓
算法需要完成的工作
  ├── 寻找最关键的边界案例
  ├── 建立尽量宽的分类边界
  └── 判断新案例位于边界哪一侧
  ↓
最终结果
  ├── 预测类别
  └── 到分类边界的相对位置
```

- **人提供**：历史案例、正确类别、输入特征和参数。
- **算法执行**：寻找能够分开不同类别的边界。
- **算法返回**：预测类别和分类分数。

SVM原生输出的通常是分类分数，不一定是概率；概率往往需要算法库额外转换。

# 5. 从抽象现实问题中提取模型的方法

```text
什么事情需要决定？
→ 新对象属于哪个类别，或预测一个数值

什么情况绝对不允许？
→ 禁用数据、业务规则、结果使用限制

什么结果算更好？
→ 分类错误少，而且边界尽量稳定

哪些信息在决策前已经知道？
→ 新对象的输入特征

哪些信息会随着过程变化？
→ 新样本、设备状态或市场数据
```

## 关键词对应关系

| 自然语言关键词 | 对应内容 |
|---|---|
| “是否、属于哪类” | 分类输出 |
| “预测多少” | SVR数值输出 |
| “根据、已知、参考” | 输入特征 |
| “历史实际类别” | 正确答案 |
| “分开、区分” | 分类边界 |
| “允许少量误判” | 错误容忍程度 |
| “准确、少漏判” | 评价指标 |

“分类边界”可以理解为两类对象之间的一道分隔线。

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 历史业务记录 | 温度、振动、是否故障 |
| 建模后的算法输入 | 统一尺度的数字特征及类别 | `X=设备特征，y=故障/正常` |
| 算法内部数据 | 分界线及关键边界案例 | 最接近分界线的几台设备 |
| 最终业务输出 | 类别或数值 | 预测为故障 |

最接近分类边界的关键案例叫**支持向量**。它们主要决定边界的位置。

# 7. 完整运行流程

```text
现实问题
  ↓
确定类别和输入特征
  ↓
清理数据并统一数值尺度
  ↓
划分训练集和测试集
  ↓
选择简单或弯曲的分类边界
  ↓
寻找关键边界案例
  ↓
建立间隔尽量宽的边界
  ↓
预测新案例
  ↓
验证误判和漏判
  ↓
输出业务类别
```

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

明确要区分哪些类别、使用哪些信息。

### 输入

- 现实问题
- 历史记录
- 业务规则

### 内部构成

```text
Problem_Data
├── Target_Classes
├── Input_Features
└── Error_Cost
```

### 处理过程

1. 定义类别。
2. 选择预测前可获得的信息。
3. 排除泄露答案的数据。
4. 明确漏判与误判的影响。

### 输出

- 类别定义
- 输入特征
- 评价标准

### 是否需要用户自己实现

**通常需要自己实现。**

---

## 02_Data_Preparation

### 作用

把不同单位的数据转换成可公平比较的数字。

### 输入

- 原始数据
- 特征列表
- 正确类别

### 内部构成

```text
Data_Preparation
├── Data_Cleaning
├── Category_Encoding
└── Feature_Scaling
```

### 处理过程

1. 处理缺失和异常数据。
2. 将文字类别转换成数字。
3. 统一不同特征的尺度。
4. 划分训练集和测试集。

SVM通常很需要尺度统一，否则大数值特征可能控制边界。

### 输出

- 训练数据
- 测试数据
- 数据转换规则

### 是否需要用户自己实现

**两者都可以。**库提供工具，人负责选择处理方式。

---

## 03_Model_Training

### 作用

寻找能够稳定区分类别的边界。

### 输入

- 训练数据
- 正确类别
- 边界类型和参数

### 内部构成

```text
Model_Training
├── Boundary_Search
├── Margin_Control
└── Support_Vector_Selection
```

“间隔”就是分类边界到两侧最近案例之间的空间。

### 处理过程

1. 尝试分类边界。
2. 找出距离边界最近的案例。
3. 在边界宽度与分类错误之间取得平衡。
4. 保存最终边界和支持向量。

### 输出

- 训练好的SVM
- 支持向量
- 分类边界参数

### 是否需要用户自己实现

**通常由算法库提供；用户选择边界类型和参数。**

---

## 04_Prediction

### 作用

判断新案例位于分类边界哪一侧。

### 输入

- 训练好的模型
- 处理后的新案例

### 内部构成

```text
Prediction
├── Boundary_Score
├── Class_Assignment
└── Optional_Probability
```

### 处理过程

1. 使用训练时相同的方式处理新数据。
2. 计算新案例相对边界的位置。
3. 根据所在一侧输出类别。
4. 必要时额外转换成概率。

### 输出

- 预测类别
- 分类分数
- 可选概率

### 是否需要用户自己实现

**类别和分数由库提供；业务门槛及动作由用户决定。**

---

## 05_Evaluation

### 作用

检查模型对新数据是否可靠。

### 输入

- 测试数据
- 真实类别
- 预测类别

### 内部构成

```text
Evaluation
├── Metric_Calculation
├── Error_Analysis
└── Parameter_Comparison
```

### 处理过程

1. 比较预测与真实类别。
2. 统计漏判和误判。
3. 比较不同边界类型和参数。
4. 检查错误案例。

### 输出

- 准确率等指标
- 错误案例
- 推荐参数

### 是否需要用户自己实现

**计算由库提供；业务解释由人完成。**

# 11. 用户需要实现什么

## 通常需要自己实现

- 定义类别；
- 收集历史数据；
- 选择输入特征；
- 清理和检查数据；
- 防止答案泄露；
- 选择评价指标；
- 选择是否需要概率；
- 判断结果如何进入业务流程。

## 通常由算法库或求解器提供

- 搜索分类边界；
- 识别支持向量；
- 处理复杂边界；
- 执行分类或数值预测；
- 计算常见评价指标。

算法库不会自动判断哪种边界最符合业务，需要通过验证数据比较。

# 12. 它真正帮我解决什么

| 问题 | SVM的边界 |
|---|---|
| 帮助理解问题吗？ | 能展示边界和关键案例，但复杂边界不容易解释。 |
| 帮助建立模型吗？ | 可以建立分类模型；类别与输入仍由人定义。 |
| 帮助搜索答案吗？ | 会搜索分类边界，但不是调度或路径优化算法。 |
| 帮助预测结果吗？ | 可以，主要用于分类，也可通过SVR预测数值。 |
| 帮助做连续决策吗？ | 通常不能，只完成一次输入对应的一次预测。 |
| 帮助验证解是否可行吗？ | 不能保证业务可行，只能评价预测表现。 |

它不能自动：

- 证明因果关系；
- 选择合法业务特征；
- 处理复杂硬约束；
- 保证概率准确；
- 在环境变化后继续保持可靠。

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 中小规模分类数据 | 往往能找到稳定边界 |
| 特征较多、案例不算特别多 | SVM常能保持较好效果 |
| 文本分类 | 数字化后的文本特征很多 |
| 类别边界清晰 | 宽间隔思想比较有效 |
| 需要复杂弯曲边界 | 可以使用核方法 |

“核方法”就是让SVM间接建立弯曲边界，而不要求人手工画出来。

| 不太适合 | 原因 |
|---|---|
| 数据量非常大 | 训练可能很慢 |
| 需要高度可解释的规则 | 复杂边界难以说明 |
| 数据未统一尺度 | 分类边界容易失真 |
| 类别严重重叠 | 很难找到稳定分界 |
| 原生概率非常重要 | SVM通常需要额外概率校准 |
| 需要超出历史范围预测 | 可靠性较差 |

# 14. 与相近算法比较

| 对比项 | SVM | 逻辑回归 | KNN |
|---|---|---|---|
| 输入形式 | 数值特征和类别 | 数值特征和类别 | 特征和历史答案 |
| 输出形式 | 类别、分数，可选概率 | 类别概率 | 类别、数值或邻居 |
| 是否需要历史答案 | 需要 | 需要 | 需要 |
| 如何学习 | 寻找宽而稳定的边界 | 学习分类概率公式 | 预测时寻找最近案例 |
| 复杂边界 | 可以 | 通常较弱 | 可以自然形成 |
| 预测速度 | 通常较快 | 快 | 数据多时可能较慢 |
| 是否保证业务可行 | 不保证 | 不保证 | 不保证 |
| 是否追求业务最优方案 | 否 | 否 | 否 |
| 适用问题 | 边界清晰的分类 | 需要概率和解释 | 相似案例决定结果 |

# 15. 可以与其他算法融合的位置

## 特征提取与SVM

```text
文本或图片处理算法
  ↓ 输出数值特征
SVM
  ↓ 输出类别
业务系统
```

- **融合位置**：数据准备模块。
- **为什么融合**：SVM不能直接理解原始文本或图片。
- **前者输出**：数值特征。
- **SVM接收**：特征表。
- **解决问题**：实现文本或图像分类。

## 降维与SVM

“降维”就是把大量重复特征压缩成少量关键信息。

```text
PCA等降维方法
  ↓ 输出压缩后的特征
SVM
  ↓ 建立分类边界
预测结果
```

- **融合位置**：特征处理模块。
- **为什么融合**：无关特征会增加训练成本。
- **降维方法输出**：较少的关键特征。
- **SVM接收**：压缩后的数据。
- **解决问题**：减少噪声和计算量。

## 参数优化与SVM

```text
参数搜索算法
  ↓ 提供边界类型和参数
SVM
  ↓ 返回验证成绩
参数搜索算法
```

- **融合位置**：训练模块。
- **为什么融合**：不同参数可能产生完全不同的边界。
- **参数搜索输出**：候选设置。
- **SVM输出**：验证成绩。
- **解决问题**：减少人工反复试参数。

# 16. 最小示例

## 原始问题

根据零件长度判断零件属于A类还是B类。

## 输入数据

| 零件 | 长度 | 类别 |
|---|---:|---|
| A1 | 1 | A |
| A2 | 2 | A |
| A3 | 3 | A |
| B1 | 5 | B |
| B2 | 6 | B |
| B3 | 7 | B |

## 变量或状态

- 输入：零件长度；
- 输出：A类或B类。

## 规则或约束

- 只使用长度；
- 允许算法在两类之间寻找边界；
- 新零件长度必须按相同单位输入。

## 目标

正确区分A类和B类，并让边界距离两类都尽量远。

## 算法执行过程

离边界最近的案例是：

```text
A3：长度3
B1：长度5
```

它们是这个例子中的支持向量。

二者中间的位置是：

```text
分类边界：长度4附近
```

新零件长度为 `5.5`：

```text
5.5位于边界右侧
→ 判断为B类
```

## 输出结果

```text
预测类别：B
```

真实问题通常包含多个特征，边界会从一条线变成平面或更复杂的形状。

# 17. 一句话总结

> 人负责定义类别、准备历史数据并选择输入特征；`SVM`负责寻找间隔尽量宽的分类边界；最终输出新案例的类别、分类分数或预测数值。
