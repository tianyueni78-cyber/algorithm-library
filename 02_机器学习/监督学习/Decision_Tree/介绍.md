# Decision Tree
# 1. 一句话说明它是什么

> `Decision Tree（决策树）` 是一种模仿“连续提问并作出判断”的算法，主要用于根据已有案例对新对象进行分类或数值预测。

本文讨论机器学习中的决策树，包括：

- **分类树**：预测类别，例如“是否会违约”。
- **回归树**：预测数值，例如“房价是多少”。

---

# 3. 人和算法分别负责什么

```text
现实问题
  ↓
人需要完成的工作
  ├── 明确要预测什么
  ├── 收集并整理历史案例
  ├── 选择可用于判断的信息
  └── 检查数据和结果是否符合业务常识
  ↓
算法需要完成的工作
  ├── 寻找最有区分能力的问题
  ├── 按答案不断拆分历史案例
  ├── 形成一棵判断树
  └── 用判断树预测新案例
  ↓
最终结果
  ├── 预测类别或数值
  └── 一条可以查看的判断路径
```

具体来说：

- **人提供**：历史案例、每个案例的特征、正确答案。
- **算法执行**：自动寻找“先问什么、再问什么、在哪里停止”。
- **算法返回**：训练好的树、预测结果，有时还包括预测概率和特征重要性。

例如，人提供客户的收入、负债、工作年限以及历史违约结果；算法学习判断规则；最后预测新客户是否可能违约。

# 5. 从抽象现实问题中提取模型的方法

## 可重复使用的提问框架

```text
什么事情需要决定？
→ 输出：类别或数值

什么情况绝对不允许？
→ 数据规则、业务限制或结果使用条件

什么结果算更好？
→ 准确率、误判成本、平均预测误差等评价指标

哪些信息在决策前已经知道？
→ 可以作为判断依据的输入特征

哪些信息会随着过程变化？
→ 决策树通常不直接处理持续变化过程，
   需要把某一时刻的信息整理成一次输入
```

## 自然语言关键词对应关系

| 自然语言中的表达 | 通常对应 |
|---|---|
| “判断、识别、是否、属于哪类” | 分类输出 |
| “预测多少、预计价格、预计时间” | 数值输出 |
| “根据、考虑、已知、参考” | 输入特征 |
| “必须、禁止、不能使用” | 业务规则或数据限制 |
| “尽量准确、减少漏判、降低损失” | 评价指标 |
| “历史上实际发生了什么” | 正确答案，也叫标签 |
| “年龄、温度、收入、设备类型” | 特征，即判断依据 |

决策树里的“变量”可以简单理解为一张表中的列，例如年龄、收入和负债。

# 6. 总体输入与输出

| 类型 | 内容 | 示例 |
|---|---|---|
| 原始业务输入 | 现实中收集的记录 | 客户资料、历史贷款记录 |
| 建模后的算法输入 | 整理成表格的特征和正确答案 | 收入、负债率、是否违约 |
| 算法内部数据 | 分裂条件、节点、叶子、样本分组 | “负债率 > 60%？” |
| 最终业务输出 | 给新对象的预测及解释 | “高风险，概率为78%” |

可以把输入表理解为：

| 收入 | 负债率 | 工作年限 | 是否违约 |
|---:|---:|---:|---|
| 8000 | 20% | 6 | 否 |
| 4000 | 75% | 1 | 是 |

前三列是判断依据，最后一列是算法学习时参考的正确答案。

# 7. 完整运行流程

```text
现实问题：判断客户是否会违约
  ↓
确定预测目标和可用信息
  ↓
整理历史案例并清理数据
  ↓
划分训练数据与测试数据
  ↓
算法寻找第一个判断条件
  ↓
继续拆分各组，形成决策树
  ↓
输入新客户资料
  ↓
沿树中的条件向下判断
  ↓
输出预测类别或数值
  ↓
用测试数据和业务规则验证结果
```

核心直觉只有一句：

> 每次选择一个问题，尽量把不同结果的案例分开。

# 9. 每个模块的输入、输出和构成

## 01_Problem_Data

### 作用

明确要预测什么，以及允许使用哪些信息。

### 输入

- 现实业务问题
- 历史记录
- 业务要求

### 内部构成

```text
Problem_Data
├── Prediction_Target
├── Input_Features
└── Business_Rules
```

### 处理过程

1. 确定预测类别还是数值。
2. 指定正确答案所在的数据列。
3. 排除预测时不可能提前知道的信息。
4. 明确误判会造成什么后果。

### 输出

- 原始数据表
- 目标列
- 可用特征列表

### 是否需要用户自己实现

**通常需要自己完成。**算法库不知道你的业务目标，也不知道哪些数据可以合法、合理地使用。

---

## 02_Data_Preparation

### 作用

把原始记录转换成算法可以读取的整齐表格。

### 输入

- 原始数据表
- 特征列表
- 目标列

### 内部构成

```text
Data_Preparation
├── Missing_Value_Handling
├── Category_Encoding
└── Train_Test_Split
```

### 处理过程

1. 处理缺失、错误和重复记录。
2. 把文字类别转换成库能识别的形式。
3. 将数据分成训练集和测试集。
4. 检查是否出现“提前泄露答案”的列。

### 输出

- 训练输入
- 训练答案
- 测试输入
- 测试答案

### 是否需要用户自己实现

**两者都需要。**库可以提供转换和划分工具，但数据是否合理必须由人判断。

---

## 03_Tree_Training

### 作用

从历史案例中学习判断顺序和判断条件。

### 输入

- 训练输入
- 训练答案
- 树的大小限制

### 内部构成

```text
Tree_Training
├── Split_Search
├── Node_Creation
├── Stop_Rules
└── Tree_Pruning
```

### 处理过程

1. 尝试不同特征和切分位置。
2. 找出最能区分结果的问题。
3. 将案例分到不同分支。
4. 对每个分支重复这个过程。
5. 达到停止条件后生成最终结果节点。
6. 必要时剪掉作用不大的分支，避免死记训练数据。

### 输出

- 训练好的决策树
- 每个节点的判断条件

### 是否需要用户自己实现

**通常由算法库提供。**用户主要负责选择最大深度、最小样本数等限制。

---

## 04_Prediction

### 作用

让新案例沿着已经学好的树得到结果。

### 输入

- 训练好的决策树
- 新案例的特征

### 内部构成

```text
Prediction
├── Condition_Check
├── Branch_Selection
└── Result_Output
```

### 处理过程

1. 从树的顶部开始。
2. 检查当前条件。
3. 根据条件结果选择左分支或右分支。
4. 重复判断，直到到达末端。
5. 返回该末端保存的类别、数值或概率。

### 输出

- 预测类别或数值
- 可选的预测概率
- 判断路径

### 是否需要用户自己实现

**通常由算法库提供。**业务系统可能需要自己实现输入转换和结果展示。

---

## 05_Evaluation

### 作用

检查决策树对没见过的数据是否仍然可靠。

### 输入

- 测试输入
- 测试答案
- 模型预测结果

### 内部构成

```text
Evaluation
├── Metric_Calculation
├── Error_Analysis
└── Business_Validation
```

### 处理过程

1. 使用测试数据进行预测。
2. 将预测与真实结果比较。
3. 统计正确、漏判和误判情况。
4. 检查关键分支是否符合业务常识。
5. 判断模型是否可以投入使用。

### 输出

- 准确率或预测误差
- 错误案例
- 是否可用的业务结论

### 是否需要用户自己实现

**评价计算通常由库提供；评价指标的选择和业务解释需要人完成。**

# 10. 推荐代码结构

## 最小版本

```text
DecisionTree_Project
├── data.csv
└── main.py
```

- `data.csv`：历史案例。
- `main.py`：读取数据、训练、预测和评价。

适合学习和小实验。

## 完整版本

```text
DecisionTree_Project
├── data
│   ├── raw.csv
│   └── processed.csv
├── prepare_data.py
├── train.py
├── predict.py
├── evaluate.py
└── model
    └── decision_tree.joblib
```

- `raw.csv`：未经处理的业务数据。
- `processed.csv`：算法实际读取的数据。
- `prepare_data.py`：清理和转换数据。
- `train.py`：训练并保存决策树。
- `predict.py`：加载决策树并预测新案例。
- `evaluate.py`：计算指标并查看错误案例。
- `decision_tree.joblib`：保存好的模型。

不必一开始就使用完整结构。能在一个文件中讲清楚时，不要过早拆分。

# 11. 用户需要实现什么

## 通常需要自己实现

- 明确预测目标。
- 收集和检查历史数据。
- 选择预测时真正可用的特征。
- 防止把答案或未来信息放入输入。
- 选择合适的评价指标。
- 判断结果是否符合业务要求。
- 决定如何使用预测结果。

## 通常由算法库或求解器提供

- 搜索最佳切分条件。
- 创建树节点和分支。
- 控制树的深度。
- 剪枝。
- 执行预测。
- 计算常见评价指标。
- 显示决策树。

例如，`scikit-learn` 会完成训练和预测，但不会替你判断“客户姓名是否应该用于贷款审批”。

# 12. 它真正帮我解决什么

| 问题 | 决策树的实际边界 |
|---|---|
| 帮助理解问题吗？ | **部分可以。**树的判断路径容易查看，但它只能反映数据中的规律，不一定是真实因果关系。 |
| 帮助建立模型吗？ | **部分可以。**算法能生成判断树，但预测目标、输入信息和业务边界仍由人定义。 |
| 帮助搜索答案吗？ | **可以。**它会从许多切分方式中寻找较好的判断规则。 |
| 帮助预测结果吗？ | **可以。**这是它的主要用途，可以预测类别或数值。 |
| 帮助做连续决策吗？ | **通常不直接可以。**普通决策树处理一次输入、给出一次结果，不负责长期连续行动。 |
| 帮助验证解是否可行吗？ | **不能自动保证。**它能评估预测表现，但业务是否合法、安全、可执行仍需额外检查。 |

它不能替代：

- 数据收集；
- 业务判断；
- 因果分析；
- 道德与法律审查；
- 对未来突发变化的判断。

# 13. 适用与不适用场景

| 比较适合 | 原因 |
|---|---|
| 客户风险分类 | 可以输出清晰的判断路径 |
| 故障类型识别 | 能同时处理多种设备特征 |
| 房价或需求量预测 | 回归树可以预测数值 |
| 需要向业务人员解释结果 | 可以把模型画成判断树 |
| 输入关系存在明显分段 | 很适合表达“超过某值就不同” |

| 不太适合 | 原因 |
|---|---|
| 数据非常少且噪声很大 | 容易学到偶然规律 |
| 图片、语音和长文本直接预测 | 单棵树不擅长处理原始高维数据 |
| 需要非常平滑的数值预测 | 树的输出通常是分段跳变的 |
| 数据规律经常突然改变 | 旧树不会自动理解新环境 |
| 必须证明因果关系 | 决策树主要发现相关规律，不证明原因 |
| 必须保证业务规则绝不违反 | 需要额外规则检查，不能只依赖预测 |

# 14. 与相近算法比较

| 对比项 | 决策树 | 逻辑回归 | 随机森林 |
|---|---|---|---|
| 输入形式 | 表格特征 | 表格特征 | 表格特征 |
| 输出形式 | 类别、概率或数值 | 主要是类别概率 | 类别、概率或数值 |
| 是否需要人建立公式 | 不需要 | 通常不需要手写，但模型结构较固定 | 不需要 |
| 如何学习 | 连续寻找判断条件 | 学习各特征的整体影响权重 | 训练许多不同决策树并综合结果 |
| 是否保证业务可行 | 不保证 | 不保证 | 不保证 |
| 是否保证找到绝对最优模型 | 不保证 | 通常优化固定形式的模型 | 不保证 |
| 可解释性 | 单棵树较强 | 中等 | 比单棵树弱 |
| 预测稳定性 | 容易受数据变化影响 | 通常较稳定 | 通常比单棵树稳定 |
| 适用问题 | 分段、规则式判断 | 关系较平滑的分类问题 | 更重视预测准确性的问题 |

简单区分：

- 想看清楚判断规则：优先考虑**决策树**。
- 想得到较简单、稳定的概率关系：考虑**逻辑回归**。
- 更重视预测表现，可以接受解释变复杂：考虑**随机森林**。

# 15. 可以与其他算法融合的位置

## 融合示例一：特征提取与决策树

```text
文本或图片处理算法
  ↓ 提取数值特征
决策树
  ↓ 输出类别
业务系统
```

- **为什么融合**：决策树不能直接理解原始图片或长文本。
- **融合位置**：数据准备模块。
- **前一个算法输出**：图片或文本的数值特征。
- **决策树接收**：这些数值特征。
- **解决的问题**：把复杂原始数据转换成树能处理的表格。

## 融合示例二：决策树与集成学习

```text
多组抽样数据
  ↓ 分别训练多棵决策树
随机森林
  ↓ 汇总投票或平均
最终预测
```

- **为什么融合**：单棵树容易因数据稍微变化而产生不同结果。
- **融合位置**：训练与结果汇总模块。
- **每棵树输出**：自己的预测。
- **随机森林接收**：所有树的预测。
- **解决的问题**：提高稳定性，通常也能提高准确率。

## 融合示例三：优化算法调整参数

```text
网格搜索或贝叶斯优化
  ↓ 提供树深度、最小样本数等参数
决策树
  ↓ 返回测试表现
参数优化算法
```

- **为什么融合**：树太深容易死记数据，太浅又可能学不到规律。
- **融合位置**：参数选择模块。
- **优化算法输出**：一组训练参数。
- **决策树返回**：这组参数对应的验证成绩。
- **解决的问题**：自动寻找比较合适的树大小。

# 16. 最小示例

## 原始问题

根据天气判断是否去公园。

## 输入数据

| 天气 | 风大吗 | 实际是否去 |
|---|---|---|
| 晴 | 否 | 去 |
| 晴 | 是 | 不去 |
| 雨 | 否 | 不去 |
| 阴 | 否 | 去 |

## 变量或状态

算法可以看到：

- 天气；
- 是否有大风。

算法需要预测：

- 去；
- 不去。

## 规则或约束

- 预测时只能使用天气和风力。
- 不能把“实际是否去”当作预测输入。
- 每个案例必须有一个已知结果。

## 目标

尽量正确预测“去”或“不去”。

## 算法执行过程

算法可能从数据中建立下面的小树：

```text
天气是雨吗？
├── 是 → 不去
└── 否
    ↓
    风大吗？
    ├── 是 → 不去
    └── 否 → 去
```

现在输入一个新案例：

```text
天气：晴
风大：否
```

判断过程：

```text
天气是雨吗？→ 否
风大吗？→ 否
结果 → 去
```

## 输出结果

```text
预测：去公园
判断路径：不是雨天，并且风不大
```

这个例子可以手工检查，但数据太少，不能说明它在真实环境中一定可靠。

# 17. 一句话总结

> 人负责定义预测目标、提供历史数据并检查业务合理性；`Decision Tree` 负责从数据中学习判断顺序并预测新案例；最终输出类别、数值以及相应的判断路径。

# 18. 理解检查

如果要用决策树判断一台机器是否会故障，你认为人应该提供什么输入，而决策树最后应该输出什么？
